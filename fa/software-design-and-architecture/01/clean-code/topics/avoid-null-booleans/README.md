# null و Boolean مبهم — Avoid passing nulls and booleans


> **زبان:** [نسخهٔ انگلیسی](../../../../../../en/software-design-and-architecture/01/clean-code/topics/avoid-null-booleans/README.md)

[فصل کد تمیز](../../README.md) · [فهرست دوره](../../../../00-index.md)

## هدف درس

بتوانی مسئلهٔ این اصل را تشخیص بدهی، آن را در کد به‌کار ببری، trade-off را توضیح بدهی و در آزمون از نتیجه دفاع کنی.

## آموزش دقیق

null می‌تواند «ناموجود»، «همه»، «نامشخص»، «هنوز نخوانده» یا «پاکش کن» معنا بدهد. Boolean موقعیتی هم call site را مبهم می‌کند: true دقیقاً چه حالت یا رفتاری را درخواست می‌کند؟ قرارداد نوع‌دار حالت مجاز را روشن و برخی خطاها را غیرقابل‌بیان می‌سازد.

۱. برای اختیاری واقعی از Optional یا Option استفاده کن.
۲. برای چند حالت معنی‌دار enum یا نوع tagged تعریف کن.
۳. برای دو رفتار متفاوت متد یا نام پارامتر جدا بده.
۴. در JSON فرق absent و null را مشخص کن؛ در PATCH ممکن است absent یعنی «دست‌نزن» و null یعنی «پاک‌کن».
۵. اعتبارسنجی مرز ورودی را انجام بده تا حالت نامعتبر وارد دامنه نشود.

## مثال

create_invoice(order, true, null) را نمی‌شود در محل فراخوانی فهمید. send_email=True از نظر خوانایی بهتر است؛ اگر حالت draft و issued قواعد مختلف دارند، InvoiceMode بهتر است. null در نام مشتری هم باید معلوم کند یعنی «بدون نام» مجاز است یا دادهٔ کاربر نرسیده.

## محدودیت

نوع‌های بیشتر mapping و serialization را حجیم می‌کنند. وقتی نبود مقدار واقعاً حالت دامنه است، آن را پنهان نکن؛ نام و اعتبارسنجی بده. enum نیز به‌تنهایی transition مجاز را کنترل نمی‌کند.

## تمرین

API دارای Boolean/null را بررسی کن. همهٔ حالت‌ها و اثرشان را بنویس و نوعی طراحی کن که حالت غیرممکن در ورودی بیان نشود.

## نمونهٔ کد/قرارداد

~~~python
class InvoiceMode(Enum):
    DRAFT = "draft"
    ISSUE_AND_SEND = "issue_and_send"

create_invoice(order, mode=InvoiceMode.ISSUE_AND_SEND)
~~~

## تمرین سنجش

نمونه‌ای از کد خودت یا یک پروژهٔ آموزشی انتخاب کن. مفهوم را در یک تغییر کوچک اعمال کن، آزمونی برای رفتار مرزی اضافه کن و با یک جمله ثبت کن که چه چیزی خواناتر یا امن‌تر شد.

## کوییز با پاسخ تشریحی

پیش از دیدن پاسخ، دلیل خودت را بنویس. پاسخ پیشنهادی باید با زمینه هماهنگ باشد؛ اگر گزینهٔ دیگری داری، trade-off آن را هم بیان کن.

1. **چرا Boolean موقعیتی نامناسب است؟**
   - پاسخ تشریحی: call site قصد را نشان نمی‌دهد؛ true معنای پنهان دارد.
2. **چه وقت null معتبر است؟**
   - پاسخ تشریحی: وقتی قرارداد دامنه نبود/پاک‌کردن/نامشخص را تعریف و از absent فنی جدا کرده باشد.
3. **چطور حالت‌های چندگانه را واضح می‌کنی؟**
   - پاسخ تشریحی: enum یا نوع tagged، یا عملیات نام‌داری که هر حالت را بیان کند.
