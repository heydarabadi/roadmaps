# تمرین DSA با JavaScript

> والد: [انتخاب زبان](../README.md) · [فصل ۱](../../README.md) · [English](../../../../../en/data-structures-and-algorithms/01-foundations/choose-language/javascript/README.md)

## پیش‌نیازها و نقشهٔ ذهنی

متغیر، function، array، object و Map. ابتدا مفهوم را به‌عنوان یک قرارداد ببین، سپس نمایش حافظه و عملیات را دنبال کن. هدف حفظ‌کردن نام نیست؛ باید بتوانی برای یک ورودی کوچک، state را بعد از هر گام بنویسی.

## ایده از پایه

JavaScript برای تمرین الگوریتم دسترس‌پذیر است و در مرورگر و Node.js اجرا می‌شود؛ اما coercion، نوع Number و عملیات آرایه/Map می‌توانند نتیجه یا کارایی را تغییر دهند.

## مدل، قرارداد و ناوردا

Array آرایهٔ قابل‌رشد است؛ index معمولاً O(1)، `push/pop` انتهایی amortized O(1)، `shift/unshift` O(n). `Map` و `Set` برای کلیدهای متنوع و membership مناسب‌اند. `Array.sort()` به‌صورت پیش‌فرض رشته‌ای مرتب می‌کند، پس برای عددها comparator عددی بده.

ناوردا (invariant) جمله‌ای است که در تمام مراحل الگوریتم باید درست بماند. نوشتن آن پیش از کدنویسی، هم به اثبات درستی کمک می‌کند و هم خطاهای مرزی را آشکار می‌سازد.

## الگوریتم یا عملیات گام‌به‌گام

صف BFS را با index head پیاده کن: `q=[s]; let head=0; while(head<q.length){const u=q[head++]; ...}` تا `shift()` هر بار کل آرایه را جابه‌جا نکند؛ یا deque پیاده‌سازی/کتابخانه معتبر. min-heap را خودت با sift-up/down یا ساختار آماده پیاده کن.

در پیاده‌سازی واقعی، قرارداد ورودی/خروجی را دقیق تعریف کن: رفتار ورودی تهی، مقدار تکراری، عنصر پیدا‌نشده و ظرفیت تمام‌شده باید روشن باشد.

## اجرای حل‌شده با ردگیری

`[2,10,1].sort()` ممکن است ترتیب lexicographic بدهد؛ `(a,b)=>a-b` ترتیب عددی می‌دهد. برای جست‌وجوی map، `const old=map.get(key)` مبهم است اگر value undefined مجاز باشد؛ از `map.has(key)` برای وجود مستقل استفاده کن.

برای تمرین، جدولی با ستون‌های «گام»، «اندیس/اشاره‌گر»، «بخش فعال»، «تغییر state» و «دلیل» بساز. این روش به‌خصوص برای الگوریتم‌های درجا و تقسیم‌و‌غلبه جلوی پرش ذهنی را می‌گیرد.

## چرا درست است؟

Array length تعداد slotهای تا آخر است اما holeها و sparse arrays رفتار خاص دارند. comparator مرتب‌سازی باید ترتیب منسجم بسازد. Map بر اساس هویت/قواعد کلید خود عمل می‌کند؛ object ساده برای map دلخواه semantics متفاوت دارد.

اثبات معمولاً سه بخش دارد: (۱) آغاز—ناوردا پیش از نخستین گام درست است؛ (۲) نگهداری—هر گام آن را حفظ می‌کند؛ (۳) پایان—شرط توقف همراه invariant جواب موردنیاز را نتیجه می‌دهد. اگر یکی از این سه بخش نامشخص است، هنوز درک الگوریتم کامل نشده است.

## تحلیل زمان و حافظه

`push/pop` انتهایی معمولاً amortized O(1)، `shift` O(n)، `includes` O(n)، Map/Set میانگین نزدیک O(1). Number اعداد صحیح را فقط تا حد امن دقیق نگه می‌دارد؛ برای مقادیر بسیار بزرگ `BigInt` لازم است، اما با Number مخلوط نمی‌شود.

در Big-O ورودی را تعریف کن (مثلاً n تعداد عناصر)، نوع حالت را نام ببر (بهترین/میانگین/بدترین)، و فضای کمکی را از حافظهٔ خود ورودی جدا کن. مرتبهٔ رشد زمان واقعی بر حسب ثانیه نیست؛ cache، تخصیص حافظه و ثابت‌های پیاده‌سازی هم اثر دارند.

## کاربرد واقعی و انتخاب مناسب

الگوریتم سمت مرورگر، تحلیل داده، مصاحبه و ابزار Node.js. برای گراف، Map از کلیدهای غیررشته‌ای پشتیبانی می‌کند؛ typed arrays برای دادهٔ عددی فشرده مناسب‌اند.

پیش از انتخاب بپرس: چه عملیاتی پرتکرارند؟ آیا ترتیب مهم است؟ دادهٔ ورودی چه اندازه است؟ آیا محدودیت حافظه، latency بدترین‌حالت یا thread-safety داریم؟ ساختار خوب برای workload نامناسب می‌تواند انتخاب بدی باشد.

## خطاهای رایج و edge caseها

مقایسهٔ `==` coercion می‌کند؛ ترجیحاً semantics را روشن و `===` را انتخاب کن. sort پیش‌فرض رشته‌ای است. `Array(5)` hole دارد، نه پنج مقدار undefined عادی. recursion عمیق و Number precision را بسنج.

حالت‌های مرزی را جداگانه بررسی کن: ورودی خالی، یک عضو، همهٔ اعضا برابر، هدف غایب، حداقل/حداکثر مقدار و اندازهٔ بزرگ. سرریز عدد صحیح در محاسبهٔ اندیس/ظرفیت نیز بسته به زبان مهم است.

## تمرین‌های مرحله‌ای

۱) sort عددی را با default مقایسه کن. ۲) BFS را با head index بنویس. ۳) برای 10^16+1 از Number و BigInt رفتار را آزمایش ذهنی/اجرایی کن.

برای هر تمرین، اول پاسخ ساده و درست بنویس، بعد پیچیدگی را حساب کن، سپس edge case اضافه کن. تمرین را با دست‌کم یک ورودی کوچک ردگیری کن و خروجی را با انتظار مستقل مقایسه کن.

## آزمون جامع با پاسخ تشریحی

ابتدا پاسخ‌ها را نخوان؛ جواب را با استدلال بنویس، سپس توضیح را مقایسه کن.

1. **پرسش:** sort عددی چگونه؟
   **پاسخ تشریحی:** با comparator مانند `(a,b)=>a-b`.
2. **پرسش:** چرا shift برای صف بد است؟
   **پاسخ تشریحی:** هزینهٔ جابه‌جایی عناصر می‌تواند O(n) باشد.
3. **پرسش:** برای عضویت کلیدها؟
   **پاسخ تشریحی:** Map/Set با lookup میانگین نزدیک O(1).
4. **پرسش:** محدودیت Number؟
   **پاسخ تشریحی:** دقت صحیح تا Number.MAX_SAFE_INTEGER.
5. **پرسش:** چرا map.has گاهی لازم است؟
   **پاسخ تشریحی:** تا وجود کلید را از value برابر undefined جدا کنیم.

## راهنمای بازگویی از حافظه

بدون نگاه به متن، ایده، پیش‌شرط، invariant، یک ردگیری واقعی، پیچیدگی، edge case و یک کاربرد را در چند دقیقه روی کاغذ توضیح بده. اگر فقط pseudocode را حفظی می‌نویسی اما دلیل درستی یا محدودیت‌ها را نمی‌دانی، یک بار دیگر بخش‌های invariant و خطاها را مرور کن.
