# فصل ۳ — جست‌وجو و مرتب‌سازی

> نسخهٔ انگلیسی: [English version](readme.en.md)

پیش‌شرط الگوریتم‌ها را رعایت کن و هزینهٔ مقایسه، جابه‌جایی و حافظه را مقایسه کن.

## ترتیب پیشنهادی

1. پیش‌نیازها و تعریف‌ها را بخوان.
2. مثال هر تاپیک را دستی اجرا کن.
3. تمرین‌ها را انجام بده و بعد پاسخ آزمون را ببین.
4. هنگام پیاده‌سازی، complexity را با operation واقعی کتابخانهٔ زبانت تطبیق بده.

## جدول انتخاب الگوریتم

| روش | پیش‌شرط/کاربرد | زمان | فضا / ویژگی |
|---|---|---:|---|
| Linear search | هر دنباله، یک/چند جست‌وجو | O(n) | O(1)، ساده |
| Binary search | دادهٔ مرتب و دسترسی تصادفی | O(log n) | O(1)، مرز هم می‌یابد |
| Insertion sort | کوچک یا تقریباً مرتب | best O(n), worst O(n²) | in-place، پایدار |
| Merge sort | تضمین رشد/پایداری/دادهٔ بیرونی | Θ(n log n) | O(n)، پایدار معمولاً |
| Quick sort | سرعت درون‌حافظه‌ای | avg O(n log n), worst O(n²) | معمولاً in-place، ناپایدار |
| Heap sort | بدترین‌حالت تضمینی، فضای کم | Θ(n log n) | O(1)، ناپایدار |
| Bubble/Selection | آموزش یا قید خاص | Θ(n²) | ساده، محدودیت‌های پایداری/نوشتن |

## انتخاب در سناریو

اگر داده فقط یک بار و unsorted جست‌وجو می‌شود، sort کامل ممکن است هزینهٔ اضافه باشد. اگر query زیاد و داده نسبتاً ثابت است، sort یک‌باره و binary search می‌تواند به‌صرفه شود. برای مرتب‌سازی رکوردهای هم‌کلید، stability مهم است؛ برای محدودیت RAM، auxiliary space را در نظر بگیر؛ برای نیاز worst-case، به average سریع Quick sort تکیه نکن مگر implementation محافظ داشته باشد.

## آموزش گره‌های والد در نقشهٔ رسمی

این بخش عنوان‌های گروهی نقشه را نیز پوشش می‌دهد؛ برای درس مستقل هر برگ، README تاپیک را باز کن.

## تاپیک والد نقشه: Sorting Algorithms

### آموزش

مرتب‌سازی ترتیب عناصر را بر اساس comparator تغییر می‌دهد. نقشه Bubble, Insertion, Selection, Merge, Quick و Heap Sort را پوشش می‌دهد.

**روش انتخاب/اجرا:** معیار پایداری، حافظهٔ کمکی، هزینهٔ بدترین‌حالت و اندازه/ترتیب ورودی را مشخص کن؛ بعد الگوریتم مناسب را از کتابخانهٔ استاندارد انتخاب یا پیاده‌سازی کن.

**پیچیدگی و مبادله:** Merge Sort پایدار و Θ(n log n) با فضای کمکی؛ Heap Sort بدترین O(n log n) با فضای کم؛ Quick Sort میانگین سریع و بدترین O(n²) دارد.

**تجربهٔ عملی:** مرتب‌کردن خروجی گزارش، زمان‌بندی کارها، merge فایل‌های مرتب و آماده‌سازی داده برای binary search.

**دام رایج:** مرتب‌سازی درجا لزوماً پایدار نیست و انتخاب الگوریتم از روی یک benchmark کوتاه قابل اتکا نیست.

### آزمون کوتاه با پاسخ

1. **پرسش:** پایداری یعنی چه؟
   **پاسخ:** ترتیب نسبی کلیدهای برابر حفظ شود.
2. **پرسش:** برای تضمین O(n log n) در بدترین حالت با فضای کم چه گزینه‌ای هست؟
   **پاسخ:** Heap Sort.
3. **پرسش:** چه پیش‌شرطی جست‌وجوی دودویی را ممکن می‌کند؟
   **پاسخ:** داده باید بر اساس همان معیار مرتب باشد.

## تاپیک والد نقشه: Search Algorithms

### آموزش

جست‌وجو عضو یا موقعیت مورد نظر را در مجموعه پیدا می‌کند. نقشه جست‌وجوی خطی و دودویی را معرفی می‌کند.

**روش انتخاب/اجرا:** اگر داده کوچک/نامرتب است جست‌وجوی خطی ساده است؛ اگر مرتب است و query زیاد دارید binary search یا ایندکس را بسنج؛ هزینهٔ مرتب‌سازی اولیه را حساب کن.

**پیچیدگی و مبادله:** Linear Search O(n) است؛ Binary Search روی دادهٔ مرتب O(log n) است.

**تجربهٔ عملی:** lookup در فهرست کاربران، ایندکس پایگاه داده و یافتن آستانه/موقعیت در آرایهٔ مرتب.

**دام رایج:** Binary search روی آرایهٔ نامرتب جواب معتبر نمی‌دهد؛ sorting صرفاً برای یک query ممکن است هزینهٔ بیشتری از اسکن داشته باشد.

### آزمون کوتاه با پاسخ

1. **پرسش:** مزیت اصلی Binary Search چیست؟
   **پاسخ:** هر گام نصف دامنهٔ جست‌وجو را حذف می‌کند.
2. **پرسش:** آیا جست‌وجوی خطی به دادهٔ مرتب نیاز دارد؟
   **پاسخ:** نه.
3. **پرسش:** در تصمیم میان sort و scan چه چیزی را حساب می‌کنی؟
   **پاسخ:** تعداد queryها، هزینهٔ sort و هزینهٔ هر lookup.


## آزمون جمع‌بندی فصل

۱. کدام پیش‌شرط binary search دارد؟ ترتیب comparator. ۲. در آرایهٔ تکراری چگونه اولین رخداد را می‌یابی؟ lower_bound. ۳. کدام الگوریتم‌های ساده برای تقریباً مرتب بودن خوب‌اند؟ insertion sort. ۴. merge sort و heap sort از نظر stability/space چه فرق دارند؟ merge معمولاً stable ولی O(n) space؛ heap O(1) و ناپایدار. ۵. آیا Quick sort worst-case همیشه n log n است؟ خیر، pivotهای بد می‌توانند n² بسازند. ۶. برای input خالی در sorting چه اتفاقی باید بیفتد؟ خروجی خالی؛ حلقهٔ پایه باید امن باشد.

## معیار عبور

یک ورودی با duplicateها را با دو sort دستی اجرا کن؛ stability را با شناسهٔ اولیه اثبات کن؛ سپس برای هر الگوریتم best/average/worst و auxiliary space را بدون نگاه به جدول بگو.
