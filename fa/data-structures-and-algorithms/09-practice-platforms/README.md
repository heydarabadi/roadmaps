# فصل ۹ — تمرین و خودارزیابی

> نسخهٔ انگلیسی: [English version](../../../en/data-structures-and-algorithms/09-practice-platforms/README.md)

حل مسئله را به چرخهٔ یادگیری تبدیل کن؛ پلتفرم فقط ابزار است و کیفیت بازاندیشی تعیین‌کننده است.

## ترتیب پیشنهادی

1. پیش‌نیازها و تعریف‌ها را بخوان.
2. مثال هر تاپیک را دستی اجرا کن.
3. تمرین‌ها را انجام بده و بعد پاسخ آزمون را ببین.
4. هنگام پیاده‌سازی، complexity را با operation واقعی کتابخانهٔ زبانت تطبیق بده.

## چرخهٔ تمرین که به یادگیری منجر می‌شود

برای هر مسئله ابتدا ۵–۱۰ دقیقه صورت را بازنویسی کن؛ قیدها، نوع جواب، تکرارها و empty case را یادداشت کن. راه‌حل مرجع ساده را طراحی کن، حتی اگر کند باشد. سپس بفهم کدام تکرار یا bottleneck را می‌توان حذف کرد. پیش از submit یک trace دستی و چند تست edge اجرا کن. پس از AC یا دیدن editorial، صفحه را ببند و proof/کد را از حافظه بازسازی کن؛ پاسخ را فردا و یک هفته بعد دوباره حل کن.

برچسب مرور باید مفهوم باشد: «lower_bound با duplicate»، «یک heap برای top-k»، «invariant پنجره»؛ برچسب را تنها به شمارهٔ سؤال محدود نکن. برای هر شکست یادداشت کن: آیا مدل اشتباه بود، proof ناقص بود، edge case جا افتاد یا syntax؟ این تشخیص انتخاب تمرین بعدی را بهتر می‌کند.

## تاپیک والد نقشه: Platforms to Practice

### آموزش

LeetCode و Edabit بستر تمرین‌اند؛ هیچ پلتفرمی جای فهم مسئله، پیاده‌سازی، تحلیل و بازبینی پاسخ را نمی‌گیرد.

**روش انتخاب/اجرا:** مسئله را بازگو کن؛ مثال مرزی بساز؛ راه‌حل ساده و سپس بهتر را بنویس؛ complexity را تحلیل کن؛ بعد پاسخ مرجع را ببین و اشتباه را ثبت کن.

**پیچیدگی و مبادله:** امتیاز سایت معیار رشد نیست؛ تغییر کیفیت توضیح و توانایی حل مسئلهٔ جدید را دنبال کن.

**تجربهٔ عملی:** LeetCode تمرین مسئله‌های الگوریتمی؛ Edabit تمرین‌های کوچک و syntax-oriented.

**دام رایج:** از حفظ solution و مسابقهٔ streak پرهیز کن؛ اگر چند روز بعد نتوانی دوباره بسازی هنوز مسلط نیستی.

   **پاسخ:** ایده، invariant، پیچیدگی، edge case و دلیل رد راه‌حل‌های دیگر.
2. **پرسش:** چرا قبل از دیدن editorial باید تلاش کرد؟
   **پاسخ:** تا مدل ذهنی و نقطهٔ گیر واقعی مشخص شود.
3. **پرسش:** چطور تسلط را می‌سنجی؟
   **پاسخ:** مسئلهٔ مشابهِ ندیده را مستقل حل و راه‌حل را توضیح می‌دهم.


## آزمون جمع‌بندی فصل

۱. Accepted تضمین می‌کند الگوریتم برای همهٔ ورودی‌ها درست است؟ خیر؛ فقط مجموعهٔ تست ارزیاب را گذرانده. ۲. چرا brute force را قبل از optimize می‌نویسیم؟ baseline و oracle تست. ۳. پس از دیدن راه‌حل، بهترین مرور چیست؟ بازسازی مستقل با توضیح invariant و complexity. ۴. برای تمرین syntax کوتاه کدام پلتفرم این فصل پیشنهاد می‌کند؟ Edabit؛ برای مسائل الگوریتمی متنوع‌تر LeetCode. ۵. آیا کپی کد بدون فهم، تسلط می‌آورد؟ خیر. ۶. چه چیز پروژهٔ واقعی بیشتر از challenge دارد؟ contract، failure، concurrency، observability و maintainability.

## معیار تسلط

بتوانی صورت مسئله را توضیح دهی، راه brute force و بهینه را مقایسه کنی، proof و complexity را بنویسی، edge caseهای مستقل بسازی و روز بعد بدون راهنما دوباره حلش کنی.
