# نمایه‌سازی خطی

> نسخهٔ انگلیسی: [English version](../../../../en/data-structures-and-algorithms/07-complex-structures-and-indexing/linear-indexing/README.md)

> مسیر: [فصل ۷ — ساختارهای پیچیده و نمایه‌سازی](../README.md) · پیش‌نیاز پیشنهادی: فصل ۱ و مبانی برنامه‌نویسی

## پیش‌نیازها و نقشهٔ ذهنی

فایل/آرایه مرتب، کلید و رکورد. ابتدا مفهوم را به‌عنوان یک قرارداد ببین، سپس نمایش حافظه و عملیات را دنبال کن. هدف حفظ‌کردن نام نیست؛ باید بتوانی برای یک ورودی کوچک، state را بعد از هر گام بنویسی.

## ایده از پایه

ایندکس جدولی کمکی از کلید به آدرس رکورد است. در dense index برای هر رکورد ورودی index داریم؛ در sparse index برای هر block یا گروه، یک separator/کلید راهنما نگه می‌داریم. واژهٔ linear در نقشه را در این درس به‌عنوان مدل index مرتب/سطحی بخوان، نه complexity خطی همهٔ lookupها.

## مدل، قرارداد و ناوردا

index entry معمولاً (search-key, pointer) است؛ search-key ممکن است unique نباشد و به bucket/list رکوردها اشاره کند. index clustered ترتیب فیزیکی داده را با کلید نزدیک می‌کند؛ secondary index ترتیب فیزیکی دیگری می‌دهد و برای lookup به record pointer نیاز دارد.

ناوردا (invariant) جمله‌ای است که در تمام مراحل الگوریتم باید درست بماند. نوشتن آن پیش از کدنویسی، هم به اثبات درستی کمک می‌کند و هم خطاهای مرزی را آشکار می‌سازد.

## الگوریتم یا عملیات گام‌به‌گام

جست‌وجو در index مرتب: binary search روی keyها، پیدا کردن pointer block یا رکورد، سپس جست‌وجوی موضعی/صفحه. برای range query lower bound را پیدا و entryها/رکوردهای پیوسته را scan کن. درج index مرتب ممکن است شیفت، page split یا بازسازی بخواهد.

در پیاده‌سازی واقعی، قرارداد ورودی/خروجی را دقیق تعریف کن: رفتار ورودی تهی، مقدار تکراری، عنصر پیدا‌نشده و ظرفیت تمام‌شده باید روشن باشد.

## اجرای حل‌شده با ردگیری

فایل مرتب بر اساس customer_id در بلوک‌های 100 رکوردی. sparse index فقط نخستین کلید هر بلوک را نگه می‌دارد؛ lower bound آخرین separator≤id را پیدا می‌کند و سپس حداکثر یک بلوک را اسکن می‌کند. index متراکم هر شناسه را ثبت می‌کند اما بزرگ‌تر است.

برای تمرین، جدولی با ستون‌های «گام»، «اندیس/اشاره‌گر»، «بخش فعال»، «تغییر state» و «دلیل» بساز. این روش به‌خصوص برای الگوریتم‌های درجا و تقسیم‌و‌غلبه جلوی پرش ذهنی را می‌گیرد.

## چرا درست است؟

برای sparse index، separator باید بلوک حاوی هر کلید را قابل تشخیص کند؛ index مرتب با ترتیب comparator رکورد همخوان باشد؛ pointer پس از split/جابجایی داده به رکورد درست اشاره کند.

اثبات معمولاً سه بخش دارد: (۱) آغاز—ناوردا پیش از نخستین گام درست است؛ (۲) نگهداری—هر گام آن را حفظ می‌کند؛ (۳) پایان—شرط توقف همراه invariant جواب موردنیاز را نتیجه می‌دهد. اگر یکی از این سه بخش نامشخص است، هنوز درک الگوریتم کامل نشده است.

## تحلیل زمان و حافظه

binary search در index حافظه‌ای O(log I)، سپس I/O بلوک/scan محلی. dense index فضای O(n) entry و sparse index حدود O(n/B) entry می‌خواهد. هزینهٔ نگهداری index در هر write و cache miss باید سنجیده شود.

در Big-O ورودی را تعریف کن (مثلاً n تعداد عناصر)، نوع حالت را نام ببر (بهترین/میانگین/بدترین)، و فضای کمکی را از حافظهٔ خود ورودی جدا کن. مرتبهٔ رشد زمان واقعی بر حسب ثانیه نیست؛ cache، تخصیص حافظه و ثابت‌های پیاده‌سازی هم اثر دارند.

## کاربرد واقعی و انتخاب مناسب

ایندکس پایگاه داده برای lookup و range query؛ composite index برای ترتیب چندستونی؛ covering index برای پاسخ بدون مراجعه به جدول. طراحی index روی workload query و selectivity اثر دارد.

پیش از انتخاب بپرس: چه عملیاتی پرتکرارند؟ آیا ترتیب مهم است؟ دادهٔ ورودی چه اندازه است؟ آیا محدودیت حافظه، latency بدترین‌حالت یا thread-safety داریم؟ ساختار خوب برای workload نامناسب می‌تواند انتخاب بدی باشد.

## خطاهای رایج و edge caseها

ساخت index رایگان نیست: storage و write amplification دارد. ترتیب ستون‌های composite index مهم است. index غیرclustered ممکن است random I/O بسازد. index duplicate باید چند pointer/record را پوشش دهد.

حالت‌های مرزی را جداگانه بررسی کن: ورودی خالی، یک عضو، همهٔ اعضا برابر، هدف غایب، حداقل/حداکثر مقدار و اندازهٔ بزرگ. سرریز عدد صحیح در محاسبهٔ اندیس/ظرفیت نیز بسته به زبان مهم است.

## تمرین‌های مرحله‌ای

۱) dense و sparse index یک فایل کوچک را بساز. ۲) تعداد scanهای داخل block را برای lookup محاسبه کن. ۳) برای query `WHERE city=? ORDER BY age` چه ستون‌هایی در index می‌گذاری و چرا؟

برای هر تمرین، اول پاسخ ساده و درست بنویس، بعد پیچیدگی را حساب کن، سپس edge case اضافه کن. تمرین را با دست‌کم یک ورودی کوچک ردگیری کن و خروجی را با انتظار مستقل مقایسه کن.

## آزمون جامع با پاسخ تشریحی

ابتدا پاسخ‌ها را نخوان؛ جواب را با استدلال بنویس، سپس توضیح را مقایسه کن.

1. **پرسش:** dense index چیست؟
   **پاسخ تشریحی:** ورودی برای هر رکورد.
2. **پرسش:** sparse index چیست؟
   **پاسخ تشریحی:** ورودی برای هر block/گروه یا separator.
3. **پرسش:** مزیت range query در index مرتب؟
   **پاسخ تشریحی:** پس از یافتن مرز، داده‌ها به ترتیب پیمایش می‌شوند.
4. **پرسش:** هزینهٔ index چیست؟
   **پاسخ تشریحی:** فضا و هزینهٔ نگهداری/به‌روزرسانی در write.
5. **پرسش:** clustered چه می‌گوید؟
   **پاسخ تشریحی:** ترتیب فیزیکی داده با کلید index هم‌راستاست.

## راهنمای بازگویی از حافظه
