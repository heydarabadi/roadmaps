# فصل ۱ — هدف، جریان و مدل ذهنی

**زبان:** فارسی · [English](../en/01-foundations/README.md)

**هدف:** مفهوم بازبینی همتا، ارزش‌های آن، محدودیت‌ها و چرخهٔ استاندارد را بشناس.

## درس پیونددهندهٔ فصل

Code review مشاهدهٔ همتای تغییر پیش از ادغام است؛ هدف ساخت تیمی است که تغییر قابل‌فهم‌تر و کم‌ریسک‌تر تحویل دهد. این کار هم محصول را بهتر می‌کند و هم تصمیم‌ها را در تاریخچهٔ پروژه ثبت می‌کند. Review جای تست، lint، تحلیل امنیتی یا پایش را نمی‌گیرد، چون هر ابزار نوعی از خطا را پیدا می‌کند.

برای شروع هر review، سه جمله بنویس: مسئله چیست؟ رفتار مطلوب چیست؟ در صورت شکست چه کسی یا چه داده‌ای آسیب می‌بیند؟ سپس diff را از نمای کلی به جزئیات بخوان. قواعد ماشینی را به CI بسپار، اما رفتار و قراردادها را در زمینهٔ سیستم ارزیابی کن. تصمیم را با شواهد و محدودیت بیان کن.

**تمرین فصل:** روی PR بسته‌شدهٔ یک مخزن، پنج finding احتمالی را ثبت کن؛ کنار هرکدام بنویس آیا تست، ابزار، reviewer یا پایش باید آن را پوشش دهد. لازم نیست همه blocker شوند.

## مرور فصل

1. چرا review جای تست خودکار را نمی‌گیرد؟
2. در چرخهٔ review، چرا باید ابتدا هدف و رفتار مورد انتظار را بفهمیم؟
3. چه چیزی را به ابزار می‌سپاری و چه چیزی را برای قضاوت انسانی نگه می‌داری؟

**پاسخ راهنما:** تست می‌تواند مسیرهای تعریف‌شده را اجرا کند، اما الزام مبهم یا طراحی اشتباه را به‌تنهایی تشخیص نمی‌دهد؛ review نیز همهٔ حالت‌ها را اجرا نمی‌کند. ابتدا هدف را بفهم تا diff را نسبت به رفتار موردنیاز بسنجی. formatter، lint و تست‌های قطعی را خودکار کن؛ تناسب راه‌حل با نیاز، مرزهای معماری و trade-off را با انسان بررسی کن.
