# نحو زبان

> مسیر: [فصل ۱ — پایه‌ها و تحلیل الگوریتم](../readme.md) · پیش‌نیاز پیشنهادی: فصل ۱ و مبانی برنامه‌نویسی · [English](readme.en.md)

## پیش‌نیازها و نقشهٔ ذهنی

متغیر، مقدار و اجرای تابع. ابتدا مفهوم را به‌عنوان یک قرارداد ببین، سپس نمایش حافظه و عملیات را دنبال کن. هدف حفظ‌کردن نام نیست؛ باید بتوانی برای یک ورودی کوچک، state را بعد از هر گام بنویسی.

## ایده از پایه

Syntax دستور زبان نوشتن برنامه است؛ compiler/interpreter ابتدا می‌سنجد کد طبق این قواعد است. بعد از parse، برنامه ممکن است همچنان رفتار غلط داشته باشد. یادگیری DSA به تسلط اولیه بر متغیر، عبارت، شرط، حلقه، تابع و collection نیاز دارد، نه حفظ همهٔ نحو زبان.

## مدل، قرارداد و ناوردا

برنامه داده‌ها را با نوع و نام نگه می‌دارد؛ expression مقدار می‌سازد؛ statement کاری انجام می‌دهد؛ block محدودهٔ دستورها را مشخص می‌کند. `=` معمولاً assignment، `==` equality و `return` خروج از تابع با پاسخ است. جزئیات زبان فرق دارد—در بعضی زبان‌ها block با indentation و در برخی با آکولاد است.

ناوردا (invariant) جمله‌ای است که در تمام مراحل الگوریتم باید درست بماند. نوشتن آن پیش از کدنویسی، هم به اثبات درستی کمک می‌کند و هم خطاهای مرزی را آشکار می‌سازد.

## الگوریتم یا عملیات گام‌به‌گام

نمونه: `for x in values: if x == target: return true` ابتدا هر مقدار را می‌خواند؛ شرط برابری را می‌سنجد؛ در تطبیق تابع زود خارج می‌شود. ترجمهٔ همین منطق به زبان دیگر باید semantics را حفظ کند، نه شکل ظاهری را.

در پیاده‌سازی واقعی، قرارداد ورودی/خروجی را دقیق تعریف کن: رفتار ورودی تهی، مقدار تکراری، عنصر پیدا‌نشده و ظرفیت تمام‌شده باید روشن باشد.

## اجرای حل‌شده با ردگیری

در `[4,7,2]` و target=7: x=4 شرط false؛ x=7 true و return. عنصر 2 بررسی نمی‌شود. برای target=9 هر سه عضو بررسی و سپس نتیجهٔ false لازم است.

برای تمرین، جدولی با ستون‌های «گام»، «اندیس/اشاره‌گر»، «بخش فعال»، «تغییر state» و «دلیل» بساز. این روش به‌خصوص برای الگوریتم‌های درجا و تقسیم‌و‌غلبه جلوی پرش ذهنی را می‌گیرد.

## چرا درست است؟

تا پیش از هر iteration، همهٔ عناصر قبلی بررسی شده و هیچ‌کدام برابر هدف نبوده‌اند. اگر function `return` را نداشته باشد، مقدار خروجی/مسیر پایان زبان را مشخص کن.

اثبات معمولاً سه بخش دارد: (۱) آغاز—ناوردا پیش از نخستین گام درست است؛ (۲) نگهداری—هر گام آن را حفظ می‌کند؛ (۳) پایان—شرط توقف همراه invariant جواب موردنیاز را نتیجه می‌دهد. اگر یکی از این سه بخش نامشخص است، هنوز درک الگوریتم کامل نشده است.

## تحلیل زمان و حافظه

syntax خودش complexity نیست؛ معنای دستورهای اجراشده مهم است. copy، slice، concatenation و built-in calls ممکن است پنهانی Θ(n) باشند. برای هر construct، semantics و هزینهٔ کتابخانه را از مستندات زبان بررسی کن.

در Big-O ورودی را تعریف کن (مثلاً n تعداد عناصر)، نوع حالت را نام ببر (بهترین/میانگین/بدترین)، و فضای کمکی را از حافظهٔ خود ورودی جدا کن. مرتبهٔ رشد زمان واقعی بر حسب ثانیه نیست؛ cache، تخصیص حافظه و ثابت‌های پیاده‌سازی هم اثر دارند.

## کاربرد واقعی و انتخاب مناسب

خواندن کد هم‌تیمی، debug کردن و تبدیل pseudocode به implementation دقیق. سبک format استاندارد کمک می‌کند خطاهای کنترل جریان دیده شوند.

پیش از انتخاب بپرس: چه عملیاتی پرتکرارند؟ آیا ترتیب مهم است؟ دادهٔ ورودی چه اندازه است؟ آیا محدودیت حافظه، latency بدترین‌حالت یا thread-safety داریم؟ ساختار خوب برای workload نامناسب می‌تواند انتخاب بدی باشد.

## خطاهای رایج و edge caseها

syntax error را با logical error اشتباه نکن. `=` و `==`، mutable/immutable، null/nil، precedence و integer division در زبان‌ها متفاوت‌اند. کوتاه‌بودن کد معنی کم‌هزینه‌بودن نیست.

حالت‌های مرزی را جداگانه بررسی کن: ورودی خالی، یک عضو، همهٔ اعضا برابر، هدف غایب، حداقل/حداکثر مقدار و اندازهٔ بزرگ. سرریز عدد صحیح در محاسبهٔ اندیس/ظرفیت نیز بسته به زبان مهم است.

## تمرین‌های مرحله‌ای

۱) کد جست‌وجوی بالا را در زبان منتخب بنویس. ۲) تست هدف ابتدا/آخر/غایب اضافه کن. ۳) یک کپی collection پیدا و complexity آن را تعیین کن.

برای هر تمرین، اول پاسخ ساده و درست بنویس، بعد پیچیدگی را حساب کن، سپس edge case اضافه کن. تمرین را با دست‌کم یک ورودی کوچک ردگیری کن و خروجی را با انتظار مستقل مقایسه کن.

## آزمون جامع با پاسخ تشریحی

ابتدا پاسخ‌ها را نخوان؛ جواب را با استدلال بنویس، سپس توضیح را مقایسه کن.

1. **پرسش:** Syntax چه چیزی را می‌سنجد؟
   **پاسخ تشریحی:** درستی شکل و grammar کد.
2. **پرسش:** کد معتبر syntax حتماً درست است؟
   **پاسخ تشریحی:** خیر؛ ممکن است نتیجهٔ منطقی اشتباه باشد.
3. **پرسش:** چرا زبان فرق می‌کند؟
   **پاسخ تشریحی:** قواعد assignment، scope، collection و type semantics متفاوت‌اند.
4. **پرسش:** return چه می‌کند؟
   **پاسخ تشریحی:** تابع را با مقدار/نتیجه برمی‌گرداند.
5. **پرسش:** یک خط هزینهٔ پنهان؟
   **پاسخ تشریحی:** slice یا copy collection می‌تواند O(n) باشد.

## راهنمای بازگویی از حافظه

بدون نگاه به متن، ایده، پیش‌شرط، invariant، یک ردگیری واقعی، پیچیدگی، edge case و یک کاربرد را در چند دقیقه روی کاغذ توضیح بده. اگر فقط pseudocode را حفظی می‌نویسی اما دلیل درستی یا محدودیت‌ها را نمی‌دانی، یک بار دیگر بخش‌های invariant و خطاها را مرور کن.
