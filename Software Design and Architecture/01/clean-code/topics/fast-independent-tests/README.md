# آزمون سریع و مستقل — Tests should be fast and independent


> **زبان:** [نسخهٔ انگلیسی](../../../../en/01/clean-code/topics/fast-independent-tests/README.md)

[فصل کد تمیز](../../README.md) · [فهرست دوره](../../../../00-index.md)

## هدف درس

بتوانی مسئلهٔ این اصل را تشخیص بدهی، آن را در کد به‌کار ببری، trade-off را توضیح بدهی و در آزمون از نتیجه دفاع کنی.

## آموزش دقیق

آزمون مستقل با هر ترتیب اجرا نتیجهٔ یکسان می‌دهد؛ به دادهٔ باقی‌مانده، ساعت واقعی یا شبکهٔ ناپایدار وابسته نیست. آزمون unit رفتار کوچک و سریع را می‌سنجد؛ integration test قرارداد واقعی DB، queue یا API را؛ end-to-end یک مسیر محصول را از ابتدا تا انتها می‌سنجد و معمولاً کندتر است.

۱. آزمون را با دادهٔ خودش آغاز کن و cleanup قابل اعتماد داشته باش.
۲. زمان و randomness را ثابت/تزریق کن؛ برای تأخیر از sleep استفاده نکن.
۳. شبکهٔ خارجی و پرداخت واقعی را در unit test فراخوانی نکن.
۴. همه‌چیز را mock نکن؛ mock قرارداد واقعی دیتابیس یا transaction را اثبات نمی‌کند.
۵. شکست را تا حد ممکن نزدیک به رفتار معیوب نگه دار.

## مثال

برای بررسی deadline، now را پارامتر بده و زمان قبل، مساوی و بعد از مهلت را تست کن. برای ذخیرهٔ سفارش، integration test واقعی روی دیتابیس موقت بررسی می‌کند که query و transaction همان‌طور عمل می‌کنند که mock نمی‌تواند تضمین کند.

## هزینه و trade-off

تعداد زیاد end-to-end کند و شکننده است؛ تعداد زیاد unit test از جزئیات implementation تقلید می‌کند و هر refactor را می‌شکند. مجموعه‌ای لایه‌ای بساز و تعادل را بر اساس ریسک و بازخورد اندازه بگیر.

## تمرین

یک آزمون flaky را پیدا کن. shared state، ترتیب، زمان، concurrency و پاک‌سازی را بررسی کن؛ علت را حذف و آزمون را چند بار در اجرای مستقل بازتولید کن.

## نمونهٔ کد/قرارداد

~~~python
def is_expired(expires_at, now):
    return now >= expires_at

# Test fixed timestamps; do not sleep or read the system clock.
~~~

## تمرین سنجش

نمونه‌ای از کد خودت یا یک پروژهٔ آموزشی انتخاب کن. مفهوم را در یک تغییر کوچک اعمال کن، آزمونی برای رفتار مرزی اضافه کن و با یک جمله ثبت کن که چه چیزی خواناتر یا امن‌تر شد.

## کوییز با پاسخ تشریحی

پیش از دیدن پاسخ، دلیل خودت را بنویس. پاسخ پیشنهادی باید با زمینه هماهنگ باشد؛ اگر گزینهٔ دیگری داری، trade-off آن را هم بیان کن.

1. **چرا استقلال مهم است؟**
   - پاسخ تشریحی: ترتیب و state باقی‌مانده نتیجه را عوض نمی‌کند و شکست تکرارپذیر می‌شود.
2. **unit test چه چیزی را ثابت می‌کند؟**
   - پاسخ تشریحی: رفتار کوچک/سریع را؛ نه سازگاری واقعی تمام زیرساخت را.
3. **چرا integration test لازم است؟**
   - پاسخ تشریحی: قراردادهای واقعی query، schema، transaction و تنظیمات زیرساخت را بررسی کند.
