## روش استفاده

1. یک زبان اصلی انتخاب کن؛ برای مثال‌های این دوره زبان‌مستقل و شبه‌کد در اولویت است.
2. فصل‌ها را از ۱ به بعد بخوان؛ برای مرور مصاحبه، تاپیک را بر اساس مسئله انتخاب کن.
3. هر الگوریتم را قبل از دیدن جواب، با دادهٔ کوچک روی کاغذ اجرا کن.
4. برای هر درس تست مرزی بساز، complexity را بنویس و تفاوت حالت معمول و بدترین‌حالت را مشخص کن.
5. بعد از چند روز، کوییزهای پاسخ‌دار را بدون نگاه به پاسخ‌نامه تکرار کن.

هر درس تاپیک را با تعریف و پیش‌نیاز شروع می‌کند، بعد مدل داده/ناوردا، اجرای حل‌شده، اثبات درستی، زمان و فضا، کاربرد، خطاهای رایج و edge caseها را توضیح می‌دهد. تمرین‌ها برای پیاده‌سازی و تثبیت‌اند؛ آزمون انتهای همان درس پاسخ تشریحی دارد. لینک‌ها برای مرور یا مطالعهٔ عمیق‌ترند و برای فهم ایدهٔ اصلی لازم نیست از پوشه خارج شوی.

## روش حل هر مسئله

1. **قرارداد را بازنویسی کن:** ورودی، خروجی، پیش‌شرط، اندازهٔ ورودی، duplicateها و رفتار حالت تهی.
2. **نمونه و ضدنمونه بساز:** یک ورودی کوچک را دستی اجرا کن؛ سپس empty، تک‌عضوی، مقدار تکراری/منفی، نبودن جواب و بیشینهٔ قید را بررسی کن.
3. **راه‌حل ساده بنویس:** brute force پاسخ مرجع و معیار درستی می‌دهد.
4. **الگو و ساختار را انتخاب کن:** بپرس چه کاری پرتکرار است و چه فرضی مثل مرتب‌بودن، وزن نامنفی یا پیوستگی لازم است.
5. **ناوردا را پیش از کد مشخص کن:** جمله‌ای که در آغاز، حین اجرا و پایان باید درست بماند.
6. **هزینه را حساب کن:** پارامترهای مستقل را جدا نگه دار؛ زمان، حافظهٔ کمکی، case و هزینهٔ کتابخانه را بنویس.
7. **پیاده‌سازی را ردگیری کن:** هر تغییر اندیس، صف، heap یا state را روی مثال ثبت کن.
8. **پس از حل بازبینی کن:** یک راه‌حل جایگزین، edge case جاافتاده و دلیل انتخاب trade-off را توضیح بده.

## راهنمای سریع انتخاب

| شکل مسئله | الگوی شروع | شرط کلیدی |
|---|---|---|
| lookup بدون ترتیب | hash table/set | قید average/worst و hash معتبر |
| lookup/range در دادهٔ مرتب | binary search / درخت مرتب | comparator و ترتیب معتبر |
| FIFO یا LIFO | queue یا stack | ترتیب ورود/خروج در قرارداد |
| کمینه‌هزینه روی گراف | BFS، Dijkstra، Bellman–Ford یا A* | وزن یال و heuristic |
| اتصال ارزان همهٔ رأس‌ها | Prim یا Kruskal | MST روی گراف بدون‌جهت |
| بازه‌های هم‌پوشان | sort + merge scan | بسته/باز بودن endpoint |
| زیرآرایهٔ پیوسته | sliding window / prefix sum | monotonicity شرط پنجره |
| زیرمسئلهٔ تکراری | dynamic programming | state و recurrence کامل |
| همهٔ جواب‌های قیددار | backtracking | state، انتخاب، undo و pruning درست |

جدول فقط نقطهٔ شروع است، نه تصمیم خودکار. اگر پیش‌شرط الگوریتم برقرار نیست، یا باید ورودی را با هزینهٔ معلوم تبدیل کنی یا روش دیگری انتخاب کنی.

## واژه‌نامهٔ کوتاه

- **ناوردا (invariant):** خاصیتی که در تمام تکرارها/حالت‌های ساختار باید برقرار بماند.
- **ADT:** قرارداد عملیات یک نوع داده؛ مستقل از پیاده‌سازی.
- **پایداری مرتب‌سازی (stability):** عناصر هم‌کلید ترتیب اولیه‌شان را حفظ می‌کنند.
- **Amortized:** متوسط هزینه روی دنباله‌ای از عملیات، با کران بدترین دنباله؛ با average-case احتمالاتی یکی نیست.
- **Relaxation:** جایگزینی جواب/فاصله با گزینهٔ بهتر طبق رابطهٔ انتقال.
- **Page I/O:** خواندن/نوشتن بلوک دیسک؛ برای index پایگاه‌داده معمولاً از مقایسهٔ CPU پرهزینه‌تر است.
- **Expected:** امید ریاضی روی تصادف الگوریتم؛ تضمین بدترین حالت نیست.

## پروژهٔ پایانی پیشنهادی

یک سامانهٔ نقشهٔ کوچک بساز. ابتدا تقاطع‌ها و خیابان‌های یک‌طرفه/دوطرفه را در adjacency list مدل کن؛ طول یا زمان سفر را وزن بده؛ BFS را برای کمترین تعداد خیابان و Dijkstra را برای کمترین مجموع زمان پیاده کن؛ مسیر را با `parent` بازسازی کن؛ بعد A* را با heuristic مجاز اضافه کن. تست disconnected، چند مسیر هم‌هزینه، وزن صفر و ورودی خالی بساز. در گزارش، قرارداد، invariant، پیچیدگی، محدودیت وزن و دلیل انتخاب نمایش را بنویس. تمام مفاهیم لازم در فصل‌های ۱، ۵ و ۸ و صفحه‌های زبان منتخب همین پوشه آمده‌اند.
