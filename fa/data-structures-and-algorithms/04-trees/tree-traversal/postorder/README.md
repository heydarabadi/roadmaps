# Post-order Traversal

> نسخهٔ انگلیسی: [English version](../../../../../en/data-structures-and-algorithms/04-trees/tree-traversal/postorder/README.md)

> والد: [Tree Traversal](../README.md) · [فصل درخت‌ها](../../README.md)

## پیش‌نیازها و نقشهٔ ذهنی

درخت دودویی و recursion. ابتدا مفهوم را به‌عنوان یک قرارداد ببین، سپس نمایش حافظه و عملیات را دنبال کن. هدف حفظ‌کردن نام نیست؛ باید بتوانی برای یک ورودی کوچک، state را بعد از هر گام بنویسی.

## ایده از پایه

در postorder ابتدا هر دو زیر‌درخت و بعد ریشه پردازش می‌شوند: Left→Right→Node. هنگام بازدید node، نتیجهٔ فرزندان آماده است.

## مدل، قرارداد و ناوردا

تابع تهی بی‌عمل است؛ روی گره غیرتهی ابتدا post(left)، سپس post(right)، سپس visit(node). در نسخهٔ iterative می‌توان دو stack داشت یا از علامت visited/state برای تشخیص زمان بازگشت استفاده کرد.

ناوردا (invariant) جمله‌ای است که در تمام مراحل الگوریتم باید درست بماند. نوشتن آن پیش از کدنویسی، هم به اثبات درستی کمک می‌کند و هم خطاهای مرزی را آشکار می‌سازد.

## الگوریتم یا عملیات گام‌به‌گام

`post(node): if node==null:return; post(node.left); post(node.right); visit(node)`. برای ارزیابی expression tree، مقدار دو فرزند را محاسبه و بعد عملگر گره را اجرا کن.

در پیاده‌سازی واقعی، قرارداد ورودی/خروجی را دقیق تعریف کن: رفتار ورودی تهی، مقدار تکراری، عنصر پیدا‌نشده و ظرفیت تمام‌شده باید روشن باشد.

## اجرای حل‌شده با ردگیری

درخت A با چپ B، راست C و B با فرزندان D,E: خروجی D,E,B,C,A. برای آزادکردن درخت، ابتدا فرزندان آزاد می‌شوند و سپس گره والد؛ اگر والد زودتر آزاد شود، دسترسی به childها از بین می‌رود.

برای تمرین، جدولی با ستون‌های «گام»، «اندیس/اشاره‌گر»، «بخش فعال»، «تغییر state» و «دلیل» بساز. این روش به‌خصوص برای الگوریتم‌های درجا و تقسیم‌و‌غلبه جلوی پرش ذهنی را می‌گیرد.

## چرا درست است؟

پیش از visit هر گره، همهٔ گره‌های زیر‌درخت چپ و راست آن پردازش شده‌اند. برای محاسبهٔ تابعی روی زیر‌درخت، مقادیر childها آماده و قابل ترکیب‌اند.

اثبات معمولاً سه بخش دارد: (۱) آغاز—ناوردا پیش از نخستین گام درست است؛ (۲) نگهداری—هر گام آن را حفظ می‌کند؛ (۳) پایان—شرط توقف همراه invariant جواب موردنیاز را نتیجه می‌دهد. اگر یکی از این سه بخش نامشخص است، هنوز درک الگوریتم کامل نشده است.

## تحلیل زمان و حافظه

زمان O(n)، فضای stack بازگشتی O(h). اگر الگوریتم خروجی را ذخیره کند O(n) خروجی دارد. نسخهٔ iterative ممکن است تا O(n) حالت نگه دارد، بسته به طراحی.

در Big-O ورودی را تعریف کن (مثلاً n تعداد عناصر)، نوع حالت را نام ببر (بهترین/میانگین/بدترین)، و فضای کمکی را از حافظهٔ خود ورودی جدا کن. مرتبهٔ رشد زمان واقعی بر حسب ثانیه نیست؛ cache، تخصیص حافظه و ثابت‌های پیاده‌سازی هم اثر دارند.

## کاربرد واقعی و انتخاب مناسب

حذف/آزادسازی سلسله‌مراتبی، محاسبهٔ اندازه یا hash زیر‌درخت، ارزیابی expression tree و تولید postfix از کاربردها هستند.

پیش از انتخاب بپرس: چه عملیاتی پرتکرارند؟ آیا ترتیب مهم است؟ دادهٔ ورودی چه اندازه است؟ آیا محدودیت حافظه، latency بدترین‌حالت یا thread-safety داریم؟ ساختار خوب برای workload نامناسب می‌تواند انتخاب بدی باشد.

## خطاهای رایج و edge caseها

برای چاپ ساده خروجی، فراموش‌کردن visit پس از هر دو فرزند ترتیب را عوض می‌کند. درخت تهی و تک‌گرهی را تست کن. در زبان GC، traversal postorder هنوز برای حذف فایل/منابع بیرونی لازم است، حتی اگر حافظه خودکار آزاد شود.

حالت‌های مرزی را جداگانه بررسی کن: ورودی خالی، یک عضو، همهٔ اعضا برابر، هدف غایب، حداقل/حداکثر مقدار و اندازهٔ بزرگ. سرریز عدد صحیح در محاسبهٔ اندیس/ظرفیت نیز بسته به زبان مهم است.

## تمرین‌های مرحله‌ای

۱) postorder درخت ۷ گره‌ای را بنویس. ۲) expression `(2+3)×4` را به درخت و ترتیب ارزیابی تبدیل کن. ۳) چرا حذف directory به‌طور معمول فرزندها را قبل از خود directory حذف می‌کند؟

برای هر تمرین، اول پاسخ ساده و درست بنویس، بعد پیچیدگی را حساب کن، سپس edge case اضافه کن. تمرین را با دست‌کم یک ورودی کوچک ردگیری کن و خروجی را با انتظار مستقل مقایسه کن.

## آزمون جامع با پاسخ تشریحی

ابتدا پاسخ‌ها را نخوان؛ جواب را با استدلال بنویس، سپس توضیح را مقایسه کن.

1. **پرسش:** ترتیب postorder چیست؟
   **پاسخ تشریحی:** Left, Right, Node.
2. **پرسش:** چرا برای محاسبهٔ ریشه مناسب است؟
   **پاسخ تشریحی:** نتیجهٔ دو فرزند پیش از والد آماده است.
3. **پرسش:** کاربرد پاک‌سازی درخت؟
   **پاسخ تشریحی:** ابتدا منابع فرزند، سپس والد.
4. **پرسش:** زمان؟
   **پاسخ تشریحی:** O(n).
5. **پرسش:** فضای recursion؟
   **پاسخ تشریحی:** O(h).

## راهنمای بازگویی از حافظه

بدون نگاه به متن، ایده، پیش‌شرط، invariant، یک ردگیری واقعی، پیچیدگی، edge case و یک کاربرد را در چند دقیقه روی کاغذ توضیح بده. اگر فقط pseudocode را حفظی می‌نویسی اما دلیل درستی یا محدودیت‌ها را نمی‌دانی، یک بار دیگر بخش‌های invariant و خطاها را مرور کن.
