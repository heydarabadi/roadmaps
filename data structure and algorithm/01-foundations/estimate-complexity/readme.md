# چطور پیچیدگی را حساب کنیم؟

> مسیر: [فصل ۱ — پایه‌ها و تحلیل الگوریتم](../readme.md) · پیش‌نیاز پیشنهادی: فصل ۱ و مبانی برنامه‌نویسی · [English](readme.en.md)

## پیش‌نیازها و نقشهٔ ذهنی

حلقه، تابع، recursion و نمادهای مجانبی. ابتدا مفهوم را به‌عنوان یک قرارداد ببین، سپس نمایش حافظه و عملیات را دنبال کن. هدف حفظ‌کردن نام نیست؛ باید بتوانی برای یک ورودی کوچک، state را بعد از هر گام بنویسی.

## ایده از پایه

پیش از کدنویسی تخمین بزن الگوریتم با افزایش ورودی چقدر کار می‌کند و آیا در محدودیت مسئله جا می‌شود. برای تخمین، input size را تعریف و تعداد تکرارها/فراخوانی‌ها را بشمار؛ سپس غالب‌ترین جمله را استخراج کن.

## مدل، قرارداد و ناوردا

یک حلقه nتایی Θ(n)؛ دو حلقه مستقل n,m برابر Θ(nm)؛ حلقهٔ دوبرابری یا نصف‌شونده Θ(log n)؛ loop داخل loopهای وابسته ممکن است n+(n−1)+…+1=Θ(n²) باشد. دو بخش پشت‌سرهم جمع می‌شوند؛ nested loopها معمولاً ضرب می‌شوند.

ناوردا (invariant) جمله‌ای است که در تمام مراحل الگوریتم باید درست بماند. نوشتن آن پیش از کدنویسی، هم به اثبات درستی کمک می‌کند و هم خطاهای مرزی را آشکار می‌سازد.

## الگوریتم یا عملیات گام‌به‌گام

۱) input variables تعریف کن (n عناصر، m یال‌ها). ۲) شمارش primitive عمل‌ها یا recurrence بنویس. ۳) branchها را برای worst/average تحلیل کن. ۴) جمع‌ها/recurrence را حل کن. ۵) جملهٔ غالب را نگه دار. ۶) ساختارهای کتابخانه‌ای، slicing، sort و hash assumptions را اضافه کن.

در پیاده‌سازی واقعی، قرارداد ورودی/خروجی را دقیق تعریف کن: رفتار ورودی تهی، مقدار تکراری، عنصر پیدا‌نشده و ظرفیت تمام‌شده باید روشن باشد.

## اجرای حل‌شده با ردگیری

در `for i=1; i<n; i*=2` مقدار i دوبرابر می‌شود؛ پس k دوری که 2^k≥n لازم است و k=ceil(log₂n)، یعنی Θ(log n). حلقهٔ داخلی j تا i در loop بیرونی، مجموع 1+2+…+n=n(n+1)/2=Θ(n²) می‌دهد.

برای تمرین، جدولی با ستون‌های «گام»، «اندیس/اشاره‌گر»، «بخش فعال»، «تغییر state» و «دلیل» بساز. این روش به‌خصوص برای الگوریتم‌های درجا و تقسیم‌و‌غلبه جلوی پرش ذهنی را می‌گیرد.

## چرا درست است؟

تخمین باید با رفتار واقعی کد همخوان باشد: تعداد iterationها و cost هر iteration را جدا بنویس. یک خط کد مانند `sort()` هزینهٔ کامل الگوریتم کتابخانه است، نه O(1).

اثبات معمولاً سه بخش دارد: (۱) آغاز—ناوردا پیش از نخستین گام درست است؛ (۲) نگهداری—هر گام آن را حفظ می‌کند؛ (۳) پایان—شرط توقف همراه invariant جواب موردنیاز را نتیجه می‌دهد. اگر یکی از این سه بخش نامشخص است، هنوز درک الگوریتم کامل نشده است.

## تحلیل زمان و حافظه

برای گراف adjacency list، traversal O(V+E) است؛ matrix O(V²). برای دو پارامتر مستقل، O(n+m) یا O(nm) حفظ می‌شود. برآورد حافظه را جدا و با n, V, E گزارش کن.

در Big-O ورودی را تعریف کن (مثلاً n تعداد عناصر)، نوع حالت را نام ببر (بهترین/میانگین/بدترین)، و فضای کمکی را از حافظهٔ خود ورودی جدا کن. مرتبهٔ رشد زمان واقعی بر حسب ثانیه نیست؛ cache، تخصیص حافظه و ثابت‌های پیاده‌سازی هم اثر دارند.

## کاربرد واقعی و انتخاب مناسب

کنترل امکان‌پذیری قبل از پیاده‌سازی، انتخاب algorithm در مصاحبه/کار واقعی و توضیح هزینه به تیم. قاعدهٔ «حدود 10^8 عملیات» فقط heuristic وابسته به محیط است، نه تضمین زمان.

پیش از انتخاب بپرس: چه عملیاتی پرتکرارند؟ آیا ترتیب مهم است؟ دادهٔ ورودی چه اندازه است؟ آیا محدودیت حافظه، latency بدترین‌حالت یا thread-safety داریم؟ ساختار خوب برای workload نامناسب می‌تواند انتخاب بدی باشد.

## خطاهای رایج و edge caseها

loop تو در تو همیشه n² نیست: اگر داخلی ثابت/لگاریتمی باشد فرق دارد. دو loop پشت‌سرهم n+n برابر O(n) است نه O(n²). average hash assumptions را با worst-case قاطی نکن.

حالت‌های مرزی را جداگانه بررسی کن: ورودی خالی، یک عضو، همهٔ اعضا برابر، هدف غایب، حداقل/حداکثر مقدار و اندازهٔ بزرگ. سرریز عدد صحیح در محاسبهٔ اندیس/ظرفیت نیز بسته به زبان مهم است.

## تمرین‌های مرحله‌ای

۱) شمارش دقیق اجرای `j=i..n` را برای هر i بنویس. ۲) سه حلقهٔ متوالی n، nlogn و m را ساده کن. ۳) `list.pop(0)` داخل loop چه هزینه‌ای می‌سازد؟

برای هر تمرین، اول پاسخ ساده و درست بنویس، بعد پیچیدگی را حساب کن، سپس edge case اضافه کن. تمرین را با دست‌کم یک ورودی کوچک ردگیری کن و خروجی را با انتظار مستقل مقایسه کن.

## آزمون جامع با پاسخ تشریحی

ابتدا پاسخ‌ها را نخوان؛ جواب را با استدلال بنویس، سپس توضیح را مقایسه کن.

1. **پرسش:** دو حلقهٔ متوالی nتایی؟
   **پاسخ تشریحی:** Θ(n+n)=Θ(n).
2. **پرسش:** دو حلقهٔ تودرتو nتایی؟
   **پاسخ تشریحی:** معمولاً Θ(n²)، اگر هر دو n دور باشند.
3. **پرسش:** i دوبرابر شود؟
   **پاسخ تشریحی:** Θ(log n) دور.
4. **پرسش:** چرا عملیات library باید شمرده شود؟
   **پاسخ تشریحی:** ممکن است خودش O(n), O(log n) یا بیشتر باشد.
5. **پرسش:** برای گراف sparse؟
   **پاسخ تشریحی:** Adjacency list traversal Θ(V+E).
