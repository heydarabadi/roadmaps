## هدف یادگیری

پس از این درس بتوانی مفهوم را با زبان خودت تعریف کنی، در مثال دامنه‌ای تشخیصش بدهی و هزینهٔ انتخاب یا کنارگذاشتنش را توضیح بدهی.

## آموزش

کلاس انتزاعی بخشی از قرارداد یا پیاده‌سازی مشترک را فراهم می‌کند ولی مستقیم نمونه‌سازی نمی‌شود؛ در زبان‌های مختلف محدودیت‌های متفاوت دارد.

## مثال کاربردی

در یک چارچوب parserهای چندفرمتی از base abstract فقط الگوریتم مشترک مطمئن را می‌گیرند.

این مثال آموزشی است و ادعای پیاده‌سازی دقیق یک شرکت مشخص را ندارد. نمونهٔ صنعتی مستند و زمینهٔ آن در فصل «برنامه‌نویسی شیءگرا» پیوند داده شده است.

## تصمیم معماری و محدودیت‌ها

- **چه زمانی به‌کار ببر:** وقتی مسئلهٔ اصلی‌ای که مفهوم حل می‌کند در سامانه واقعاً دیده می‌شود و قراردادش می‌تواند در کد یا آزمون بررسی شود.
- **چه زمانی ساده‌تر بماند:** نوع پایهٔ انتزاعی وارثان را به جزئیات پیاده‌سازی مقید می‌کند.
- **بازبینی:** کلاس انتزاعی را صرفاً برای نگه‌داشتن چند تابع پراکنده نساز.

## کوییز با پاسخ تشریحی

پاسخ را بپوشان و ابتدا با کلمات خودت توضیح بده؛ پاسخ پیشنهادی معیار سنجش است، نه تنها عبارت درست.

1. **این مفهوم دقیقاً چه مسئله‌ای را حل می‌کند؟**
   - پاسخ پیشنهادی: کلاس انتزاعی بخشی از قرارداد یا پیاده‌سازی مشترک را فراهم می‌کند ولی مستقیم نمونه‌سازی نمی‌شود؛ در زبان‌های مختلف محدودیت‌های متفاوت دارد.
2. **در مثال زیر چه تصمیمی می‌گیری و چرا؟**
   - پاسخ پیشنهادی: در یک چارچوب parserهای چندفرمتی از base abstract فقط الگوریتم مشترک مطمئن را می‌گیرند.
3. **چه زمانی انتخاب آن نامناسب یا پرهزینه است؟**
   - پاسخ پیشنهادی: نوع پایهٔ انتزاعی وارثان را به جزئیات پیاده‌سازی مقید می‌کند.
4. **کدام خطای رایج را قبل از ادغام کد بررسی می‌کنی؟**
   - پاسخ پیشنهادی: کلاس انتزاعی را صرفاً برای نگه‌داشتن چند تابع پراکنده نساز.

## آموزش تکمیلی مستقل

#### Abstract class

کلاس انتزاعی مستقیماً نمونه‌سازی نمی‌شود و ممکن است پیاده‌سازی مشترک یا الگوریتم قالب داشته باشد. Template Method وقتی مناسب است که ترتیب مراحل ثابت و یک گام قابل تغییر باشد. اگر زیرکلاس‌ها ترتیب را تغییر می‌دهند یا چند محور مستقل variation هست، composition معمولاً coupling کمتری دارد.

## نمونهٔ کد مرحله‌ای

کلاس انتزاعی زمانی مناسب است که چند پیاده‌سازی علاوه بر قرارداد، invariant و بخشی از الگوریتم مشترک دارند. زیرکلاس باید فقط گام‌های واقعاً متغیر را پیاده کند. اگر همکاری صرفاً قراردادی است یا رفتار در زمان اجرا عوض می‌شود، interface و composition مناسب‌تر است.
**تمرین با پاسخ:** در import، ترتیب validate و persist باید ثابت بماند؛ آن را در متد template نگه دار و فقط parse قالب را abstract کن.

در این طرح C#، نوع‌های پشتیبان کوتاه شده‌اند تا تصمیم طراحی روشن بماند.

~~~csharp
public abstract class Importer
{
    public async Task Import(CancellationToken ct)
    {
        var rows = Parse(await Read(ct));
        Validate(rows);
        await Persist(rows, ct);
    }

    protected abstract Task<string> Read(CancellationToken ct);
    protected abstract IReadOnlyList<Row> Parse(string input);
    protected abstract Task Persist(IReadOnlyList<Row> rows, CancellationToken ct);
}
~~~
