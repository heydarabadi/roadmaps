## هدف یادگیری

پس از این درس بتوانی مفهوم را با زبان خودت تعریف کنی، در مثال دامنه‌ای تشخیصش بدهی و هزینهٔ انتخاب یا کنارگذاشتنش را توضیح بدهی.

## آموزش

به شیء دارای داده بگو عملیاتی را انجام دهد تا منطق شرطی بیرون از مالک state تکثیر نشود.

## مثال کاربردی

به `Order` پیام `cancel(reason)` بده تا خودش eligibility را بررسی کند، نه اینکه بیرون وضعیت را بخواند و set کند.

این مثال آموزشی است و ادعای پیاده‌سازی دقیق یک شرکت مشخص را ندارد. نمونهٔ صنعتی مستند و زمینهٔ آن در فصل «اصول طراحی» پیوند داده شده است.

## تصمیم معماری و محدودیت‌ها

- **چه زمانی به‌کار ببر:** وقتی مسئلهٔ اصلی‌ای که مفهوم حل می‌کند در سامانه واقعاً دیده می‌شود و قراردادش می‌تواند در کد یا آزمون بررسی شود.
- **چه زمانی ساده‌تر بماند:** هماهنگ‌کننده گاهی برای ترتیب use case باید اطلاعات بخواند؛ همهٔ queryها حذف نمی‌شوند.
- **بازبینی:** فقط با جابه‌جایی کد به مدل بی‌دلیل، مسئولیت درست نمی‌شود.

## کوییز با پاسخ تشریحی

پاسخ را بپوشان و ابتدا با کلمات خودت توضیح بده؛ پاسخ پیشنهادی معیار سنجش است، نه تنها عبارت درست.

1. **این مفهوم دقیقاً چه مسئله‌ای را حل می‌کند؟**
   - پاسخ پیشنهادی: به شیء دارای داده بگو عملیاتی را انجام دهد تا منطق شرطی بیرون از مالک state تکثیر نشود.
2. **در مثال زیر چه تصمیمی می‌گیری و چرا؟**
   - پاسخ پیشنهادی: به `Order` پیام `cancel(reason)` بده تا خودش eligibility را بررسی کند، نه اینکه بیرون وضعیت را بخواند و set کند.
3. **چه زمانی انتخاب آن نامناسب یا پرهزینه است؟**
   - پاسخ پیشنهادی: هماهنگ‌کننده گاهی برای ترتیب use case باید اطلاعات بخواند؛ همهٔ queryها حذف نمی‌شوند.
4. **کدام خطای رایج را قبل از ادغام کد بررسی می‌کنی؟**
   - پاسخ پیشنهادی: فقط با جابه‌جایی کد به مدل بی‌دلیل، مسئولیت درست نمی‌شود.

## آموزش تکمیلی مستقل

### ۵. Tell, Don't Ask — بگو، نپرس

وقتی object مالک state و invariant است، به آن operation بده به‌جای آنکه state را بخوانی، بیرون تصمیم بگیری و setter بزنی.

~~~csharp
public void Cancel(CancellationReason reason)
{
    if (Status != OrderStatus.Draft)
        throw new InvalidOperationException();
    Status = OrderStatus.Cancelled;
}
~~~
