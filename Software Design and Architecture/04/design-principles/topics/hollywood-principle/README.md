## هدف یادگیری

پس از این درس بتوانی مفهوم را با زبان خودت تعریف کنی، در مثال دامنه‌ای تشخیصش بدهی و هزینهٔ انتخاب یا کنارگذاشتنش را توضیح بدهی.

## آموزش

جزء پایین‌دست کنترل جریان را برعهده نمی‌گیرد؛ چارچوب یا هماهنگ‌کننده از طریق hook/قرارداد جزء را فراخوانی می‌کند («ما با تو تماس می‌گیریم»).

## مثال کاربردی

چارچوب وب درخواست را به handler تزریق‌شده فراخوانی می‌کند و handler چارچوب را در منطق دامنه وارد نمی‌کند.

این مثال آموزشی است و ادعای پیاده‌سازی دقیق یک شرکت مشخص را ندارد. نمونهٔ صنعتی مستند و زمینهٔ آن در فصل «اصول طراحی» پیوند داده شده است.

## تصمیم معماری و محدودیت‌ها

- **چه زمانی به‌کار ببر:** وقتی مسئلهٔ اصلی‌ای که مفهوم حل می‌کند در سامانه واقعاً دیده می‌شود و قراردادش می‌تواند در کد یا آزمون بررسی شود.
- **چه زمانی ساده‌تر بماند:** کنترل از دست مصرف‌کننده خارج می‌شود و دنبال‌کردن جریان دشوارتر می‌شود.
- **بازبینی:** این اصل را با هر dependency injection یا callback یکی ندان؛ مسیر فراخوانی باید قابل ردیابی بماند.

## کوییز با پاسخ تشریحی

پاسخ را بپوشان و ابتدا با کلمات خودت توضیح بده؛ پاسخ پیشنهادی معیار سنجش است، نه تنها عبارت درست.

1. **این مفهوم دقیقاً چه مسئله‌ای را حل می‌کند؟**
   - پاسخ پیشنهادی: جزء پایین‌دست کنترل جریان را برعهده نمی‌گیرد؛ چارچوب یا هماهنگ‌کننده از طریق hook/قرارداد جزء را فراخوانی می‌کند («ما با تو تماس می‌گیریم»).
2. **در مثال زیر چه تصمیمی می‌گیری و چرا؟**
   - پاسخ پیشنهادی: چارچوب وب درخواست را به handler تزریق‌شده فراخوانی می‌کند و handler چارچوب را در منطق دامنه وارد نمی‌کند.
3. **چه زمانی انتخاب آن نامناسب یا پرهزینه است؟**
   - پاسخ پیشنهادی: کنترل از دست مصرف‌کننده خارج می‌شود و دنبال‌کردن جریان دشوارتر می‌شود.
4. **کدام خطای رایج را قبل از ادغام کد بررسی می‌کنی؟**
   - پاسخ پیشنهادی: این اصل را با هر dependency injection یا callback یکی ندان؛ مسیر فراخوانی باید قابل ردیابی بماند.

## آموزش تکمیلی مستقل

### ۶. Hollywood Principle — کنترل را به چارچوب بسپار

قاعدهٔ «ما با تو تماس می‌گیریم» می‌گوید چارچوب یا هماهنگ‌کننده جریان کنترل را در دست دارد و جزء از طریق hook یا contract فراخوانی می‌شود. نمونه: framework درخواست را به handler تزریق‌شده می‌سپارد؛ handler نباید چرخهٔ سرور را خودش کنترل کند.

این روش extension point و inversion of control را ممکن می‌کند، اما جریان اجرا را کمتر آشکار می‌کند. trace، log و naming روشن لازم است. Dependency Injection به تنهایی Hollywood Principle کامل نیست؛ تمرکز اصل بر کنترل فراخوانی است.

## نمونهٔ کد مرحله‌ای

Hollywood Principle می‌گوید چارچوب جریان کلی را کنترل می‌کند و کد برنامه در نقاط hook فراخوانی می‌شود. این کنترل وارونه، lifecycle را یک‌دست می‌کند، اما اگر hookها مبهم باشند فهم جریان سخت می‌شود.
**تمرین با پاسخ:** برنامه نباید خودش loop میزبان را مدیریت کند؛ callbackهای Start و Stop را پیاده کند و host آن‌ها را در زمان مناسب صدا بزند.

در این طرح C#، نوع‌های پشتیبان کوتاه شده‌اند تا انتخاب طراحی روشن بماند.

~~~csharp
public interface IApplicationLifecycle
{
    Task OnStart(CancellationToken ct);
    Task OnStop(CancellationToken ct);
}

public sealed class Host(IApplicationLifecycle app)
{
    public async Task Run(CancellationToken ct)
    {
        await app.OnStart(ct);
        await WaitForShutdown(ct);
        await app.OnStop(ct);
    }
}
~~~
