# فصل ۶ — ساختمان‌های دادهٔ پیشرفته

> نسخهٔ انگلیسی: [English version](readme.en.md)

ساختارهای تخصصی را وقتی نیاز عملیات خاص و پرتکرار است انتخاب کن.

## ترتیب پیشنهادی

1. پیش‌نیازها و تعریف‌ها را بخوان.
2. مثال هر تاپیک را دستی اجرا کن.
3. تمرین‌ها را انجام بده و بعد پاسخ آزمون را ببین.
4. هنگام پیاده‌سازی، complexity را با operation واقعی کتابخانهٔ زبانت تطبیق بده.

## انتخاب ساختار تخصصی

| نیاز | ساختار | عملیات کلیدی |
|---|---|---|
| پیشوند واژه | Trie | lookup در O(L) |
| prefix sum و point update | Fenwick tree | O(log n) |
| aggregate بازه‌ای متنوع | Segment tree | O(log n)، lazy range update |
| ادغام componentها | DSU | O(α(n)) سرشکن |
| substring روی متن ثابت | Suffix array/tree | index pattern/text |

## مثال انتخاب

اگر مقادیر آرایه تغییر می‌کنند و query جمع prefix داریم، Fenwick ساده است. اگر query min/max یا update بازه‌ای لازم است، segment tree انعطاف بیشتری دارد. اگر شبکه فقط با افزودن اتصال‌ها تغییر می‌کند و پرسش «هم‌component هستند؟» داریم، DSU عالی است؛ اما حذف اتصال مستقیم پشتیبانی نمی‌شود. برای autocomplete ساختار پیشوندی و برای چندین substring search روی متن ثابت suffix index را بررسی کن.

این بخش عنوان‌های گروهی نقشه را نیز پوشش می‌دهد؛ برای درس مستقل هر برگ، README تاپیک را باز کن.

## تاپیک والد نقشه: Advanced Data Structures

### آموزش

ساختارهای پیشرفته برای queryهای خاص طراحی شده‌اند: trie برای prefix، segment/Fenwick برای aggregate بازه، DSU برای اتصال، suffix structures برای متن.

**روش انتخاب/اجرا:** عملیات لازم و محدودیت update/query را بنویس؛ ساده‌ترین ساختار را انتخاب کن؛ پیاده‌سازی را با brute-force روی ورودی تصادفی مقایسه کن.

**پیچیدگی و مبادله:** بسیاری از این ساختارها query/update را از O(n) به O(log n) یا O(L) کاهش می‌دهند، با هزینهٔ حافظه و پیچیدگی پیاده‌سازی.

**تجربهٔ عملی:** autocomplete، شمارش بازه‌ای، اتصال پویا و جست‌وجوی substring.

**دام رایج:** سراغ ساختار پیشرفته فقط برای نیاز مشخص برو؛ جزئیات اندیس‌گذاری و invariantها خطاپذیرند.

### آزمون کوتاه با پاسخ

1. **پرسش:** چرا ساختار تخصصی به‌کار می‌بریم؟
   **پاسخ:** برای بهبود یک query/update پرتکرار نسبت به ساختار ساده.
2. **پرسش:** کدام ساختار برای اتصال مؤلفه‌ها مناسب است؟
   **پاسخ:** Union-Find/DSU.
3. **پرسش:** چه چیزی باید پیش از استفاده مشخص باشد؟
   **پاسخ:** عملیات، محدودیت‌ها، نوع update و هزینهٔ حافظه.


## آزمون جمع‌بندی فصل

۱. Fenwick update مقدار مطلق می‌گیرد یا delta؟ delta. ۲. combine در segment tree چه خاصیتی دارد؟ associative. ۳. DSU چه زمانی delete edge را سخت می‌کند؟ ادغام‌ها قابل rollback جداسازی ساده نیستند. ۴. suffix array چه مرتب می‌کند؟ indexهای suffixها. ۵. Trie prefix را چطور جدا از word تشخیص می‌دهد؟ marker پایان‌واژه. ۶. ساختارها را فقط به‌خاطر O(log n) انتخاب کنیم؟ نه؛ operation، حافظه، write و پیچیدگی پیاده‌سازی را بسنج.

## معیار عبور

برای هر ساختار یک operation که بهینه می‌کند و یک operation که ضعیف می‌کند ذکر کن؛ یک ورودی نمونه را روی state داخلی دست‌نویس اجرا و invariant را ثابت کن.
