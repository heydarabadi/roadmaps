حساب اعتباری رویدادهای `Credited` و `Debited` را نگه می‌دارد و مانده را از آن‌ها می‌سازد.

این مثال آموزشی است و ادعای پیاده‌سازی دقیق یک شرکت مشخص را ندارد. نمونهٔ صنعتی مستند و زمینهٔ آن در فصل «الگوهای معماری» پیوند داده شده است.

## تصمیم معماری و محدودیت‌ها

- **چه زمانی به‌کار ببر:** وقتی مسئلهٔ اصلی‌ای که مفهوم حل می‌کند در سامانه واقعاً دیده می‌شود و قراردادش می‌تواند در کد یا آزمون بررسی شود.
- **چه زمانی ساده‌تر بماند:** نسخه‌بندی رویداد، snapshot، replay و عوارض بیرونی پیچیدگی دارند.

## آموزش تکمیلی مستقل

### ۸. Event Sourcing

در event sourcing، تغییر state به صورت دنبالهٔ eventهای دامنه‌ای تغییرناپذیر ذخیره می‌شود و state فعلی از replay به دست می‌آید. این روش audit، بازسازی projection و پرسش از تاریخچه را ممکن می‌کند؛ اما نیاز همیشگی نیست.

ملاحظات:

- event schema در زمان تغییر می‌کند؛ upcasting یا compatibility لازم است.
- replay باید deterministic باشد و به provider بیرونی وابسته نشود.
- snapshot برای کاهش replay طولانی مفید است.
- دادهٔ حساس، حذف قانونی و retention به طراحی ویژه نیاز دارند.
- اصلاح رویداد اشتباه اغلب با رویداد جبرانی انجام می‌شود.
- eventها را با log فنی یکسان نگیر؛ event باید واقعیت دامنه‌ای معنادار باشد.

## نمودار معماری و خواندن مرحله‌ای

در Event Sourcing، eventهای تغییرناپذیر منبع حقیقت‌اند و state فعلی از replay یا snapshot ساخته می‌شود. audit و بازسازی قوی‌تر می‌شود، اما versioning، ترتیب، حریم داده، projection و اصلاح خطا دشوارترند.
**دام رایج:** event log را backup ساده یا تاریخچهٔ بی‌هزینه ندان.
**تمرین با پاسخ:** schema event عوض می‌شود؛ upcaster یا نسخهٔ سازگار بساز و replay مجموعهٔ eventهای قدیمی را قبل از انتشار بررسی کن.

این یک view ساده است؛ طراحی production باید مالکیت، شکست، امنیت و محدودیت‌های عملیاتی را نیز روشن کند.

~~~text
[Command] ---> [Aggregate] ---> append [Event store]
                       |                     |
                       +---- event stream ----+
                                  |
                                  v
                             [Projection]
                                  |
                                  v
                              [Read view]
~~~

## نمودار معماری و خواندن مرحله‌ای

در Event Sourcing، eventهای تغییرناپذیر منبع حقیقت‌اند و state از replay یا snapshot به دست می‌آید. audit و بازسازی قوی‌تر می‌شود، اما نسخه‌بندی، ordering، حریم داده، projection و جبران خطا دشوارترند.
