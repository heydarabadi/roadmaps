# تمرین DSA با Go

> والد: [انتخاب زبان](../readme.md) · [فصل ۱](../../readme.md) · [English](readme.en.md)

## پیش‌نیازها و نقشهٔ ذهنی

slice، map، function و struct. ابتدا مفهوم را به‌عنوان یک قرارداد ببین، سپس نمایش حافظه و عملیات را دنبال کن. هدف حفظ‌کردن نام نیست؛ باید بتوانی برای یک ورودی کوچک، state را بعد از هر گام بنویسی.

## ایده از پایه

Go ساختارهای ساده و value semantics دارد؛ slice view روی backing array است، map hash-based، و `container/heap` interface نیاز دارد. فهم ظرفیت slice و aliasing جلوی bugهای ظریف را می‌گیرد.

## مدل، قرارداد و ناوردا

Slice شامل pointer/len/cap است؛ append ممکن است backing array را عوض کند. Map برای lookup/update میانگین سریع است، ترتیب iteration تصادفی/تضمین‌نشده است. `container/list` linked list؛ `container/heap` min-heap طبق Less پیاده‌سازی.

ناوردا (invariant) جمله‌ای است که در تمام مراحل الگوریتم باید درست بماند. نوشتن آن پیش از کدنویسی، هم به اثبات درستی کمک می‌کند و هم خطاهای مرزی را آشکار می‌سازد.

## الگوریتم یا عملیات گام‌به‌گام

صف BFS ساده با slice و head index بساز؛ وقتی مصرف prefix زیاد و طولانی است، compact کردن یا ring buffer را بررسی کن. heap type، Len/Less/Swap/Push/Pop را implement و `heap.Push/Pop` فراخوانی کن.

در پیاده‌سازی واقعی، قرارداد ورودی/خروجی را دقیق تعریف کن: رفتار ورودی تهی، مقدار تکراری، عنصر پیدا‌نشده و ظرفیت تمام‌شده باید روشن باشد.

## اجرای حل‌شده با ردگیری

`q:=[]int{s}; for head:=0; head<len(q); head++ { u:=q[head] ... }` از append استفاده می‌کند. اگر q در طول عمر طولانی prefix مصرف‌شده را نگه دارد، نگاشت live objectها به backing array می‌تواند حافظه را نگه دارد؛ گاه copy/compact لازم است.

برای تمرین، جدولی با ستون‌های «گام»، «اندیس/اشاره‌گر»، «بخش فعال»، «تغییر state» و «دلیل» بساز. این روش به‌خصوص برای الگوریتم‌های درجا و تقسیم‌و‌غلبه جلوی پرش ذهنی را می‌گیرد.

## چرا درست است؟

دو slice می‌توانند backing array مشترک داشته باشند؛ تغییر یکی روی دیگری اثر می‌گذارد تا realloc. برای map، nil map قابل read است ولی assignment به آن panic می‌دهد؛ با make مقداردهی کن.

اثبات معمولاً سه بخش دارد: (۱) آغاز—ناوردا پیش از نخستین گام درست است؛ (۲) نگهداری—هر گام آن را حفظ می‌کند؛ (۳) پایان—شرط توقف همراه invariant جواب موردنیاز را نتیجه می‌دهد. اگر یکی از این سه بخش نامشخص است، هنوز درک الگوریتم کامل نشده است.

## تحلیل زمان و حافظه

append amortized O(1)، index O(1)، slice search O(n)، map expected/average O(1)، heap push/pop O(log n). interface و allocationهای فرارکننده ممکن است هزینهٔ واقعی اضافه کنند.

در Big-O ورودی را تعریف کن (مثلاً n تعداد عناصر)، نوع حالت را نام ببر (بهترین/میانگین/بدترین)، و فضای کمکی را از حافظهٔ خود ورودی جدا کن. مرتبهٔ رشد زمان واقعی بر حسب ثانیه نیست؛ cache، تخصیص حافظه و ثابت‌های پیاده‌سازی هم اثر دارند.

## کاربرد واقعی و انتخاب مناسب

سرویس‌های backend و ابزارهای concurrent؛ goroutine برای concurrency، اما الگوریتم چندریسمانی به synchronization/channel و اندازهٔ task مناسب نیاز دارد. shared map برای دسترسی هم‌زمان بدون sync امن نیست.

پیش از انتخاب بپرس: چه عملیاتی پرتکرارند؟ آیا ترتیب مهم است؟ دادهٔ ورودی چه اندازه است؟ آیا محدودیت حافظه، latency بدترین‌حالت یا thread-safety داریم؟ ساختار خوب برای workload نامناسب می‌تواند انتخاب بدی باشد.

## خطاهای رایج و edge caseها

append ممکن است alias را تغییر دهد؛ map iteration order را فرض نکن؛ map concurrent دسترسی امن نیست؛ comparator heap را معکوس و min/max را درست کن؛ حذف از slice با copy عناصر را شیفت می‌دهد.

حالت‌های مرزی را جداگانه بررسی کن: ورودی خالی، یک عضو، همهٔ اعضا برابر، هدف غایب، حداقل/حداکثر مقدار و اندازهٔ بزرگ. سرریز عدد صحیح در محاسبهٔ اندیس/ظرفیت نیز بسته به زبان مهم است.

## تمرین‌های مرحله‌ای

۱) slice len/cap را پس از appendها ردگیری کن. ۲) BFS با head index بنویس. ۳) heap min و max را با Less مقایسه کن.

برای هر تمرین، اول پاسخ ساده و درست بنویس، بعد پیچیدگی را حساب کن، سپس edge case اضافه کن. تمرین را با دست‌کم یک ورودی کوچک ردگیری کن و خروجی را با انتظار مستقل مقایسه کن.

## آزمون جامع با پاسخ تشریحی

ابتدا پاسخ‌ها را نخوان؛ جواب را با استدلال بنویس، سپس توضیح را مقایسه کن.

1. **پرسش:** slice چه سه جزء مهمی دارد؟
   **پاسخ تشریحی:** pointer به backing array، length و capacity.
2. **پرسش:** append چه زمانی alias را می‌شکند؟
   **پاسخ تشریحی:** وقتی ظرفیت کافی نباشد و backing array جدید بگیرد.
3. **پرسش:** map order تضمین دارد؟
   **پاسخ تشریحی:** خیر، نباید به ترتیب iteration تکیه کرد.
4. **پرسش:** heap push/pop؟
   **پاسخ تشریحی:** O(log n).
5. **پرسش:** map همزمان؟
   **پاسخ تشریحی:** نیازمند sync یا ساختار مناسب concurrent است.

## راهنمای بازگویی از حافظه

بدون نگاه به متن، ایده، پیش‌شرط، invariant، یک ردگیری واقعی، پیچیدگی، edge case و یک کاربرد را در چند دقیقه روی کاغذ توضیح بده. اگر فقط pseudocode را حفظی می‌نویسی اما دلیل درستی یا محدودیت‌ها را نمی‌دانی، یک بار دیگر بخش‌های invariant و خطاها را مرور کن.
