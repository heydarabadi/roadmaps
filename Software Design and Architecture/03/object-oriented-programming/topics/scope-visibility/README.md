## آموزش

scope محل اعتبار نام در کد را تعیین می‌کند و visibility مشخص می‌کند کدام کد بیرونی به عضو دسترسی دارد؛ سطح دسترسی بخشی از API و مرز تغییر است.

## مثال کاربردی

قواعد تبدیل وضعیت سفارش private می‌مانند و فقط عملیات دامنهٔ معتبر public هستند.

این مثال آموزشی است و ادعای پیاده‌سازی دقیق یک شرکت مشخص را ندارد. نمونهٔ صنعتی مستند و زمینهٔ آن در فصل «برنامه‌نویسی شیءگرا» پیوند داده شده است.

## تصمیم معماری و محدودیت‌ها

- **چه زمانی به‌کار ببر:** وقتی مسئلهٔ اصلی‌ای که مفهوم حل می‌کند در سامانه واقعاً دیده می‌شود و قراردادش می‌تواند در کد یا آزمون بررسی شود.
- **چه زمانی ساده‌تر بماند:** بسته‌بودن افراطی می‌تواند استفادهٔ مجدد را ببندد؛ بازبودن افراطی coupling می‌سازد.
- **بازبینی:** عمومی‌کردن همه‌چیز برای سرعت امروز، گزینه‌های طراحی آینده را می‌بندد.

## کوییز با پاسخ تشریحی

پاسخ را بپوشان و ابتدا با کلمات خودت توضیح بده؛ پاسخ پیشنهادی معیار سنجش است، نه تنها عبارت درست.

1. **این مفهوم دقیقاً چه مسئله‌ای را حل می‌کند؟**
   - پاسخ پیشنهادی: scope محل اعتبار نام در کد را تعیین می‌کند و visibility مشخص می‌کند کدام کد بیرونی به عضو دسترسی دارد؛ سطح دسترسی بخشی از API و مرز تغییر است.
2. **در مثال زیر چه تصمیمی می‌گیری و چرا؟**
   - پاسخ پیشنهادی: قواعد تبدیل وضعیت سفارش private می‌مانند و فقط عملیات دامنهٔ معتبر public هستند.
3. **چه زمانی انتخاب آن نامناسب یا پرهزینه است؟**
   - پاسخ پیشنهادی: بسته‌بودن افراطی می‌تواند استفادهٔ مجدد را ببندد؛ بازبودن افراطی coupling می‌سازد.
4. **کدام خطای رایج را قبل از ادغام کد بررسی می‌کنی؟**
   - پاسخ پیشنهادی: عمومی‌کردن همه‌چیز برای سرعت امروز، گزینه‌های طراحی آینده را می‌بندد.

## آموزش تکمیلی مستقل

#### Scope و visibility

Scope محدودهٔ اعتبار نام در زبان است: block، function، module یا global. Visibility سطح دسترسی بیرونی است: private، protected، internal/package یا public. این دو مرتبط‌اند اما یکی نیستند.

از کمترین visibility لازم شروع کن. public member قرارداد پشتیبانی‌شدهٔ بیرونی می‌سازد و تغییر آن سازگاری می‌خواهد. protected هم نوعی API برای وارثان است. global mutable state ردیابی تغییر را سخت می‌کند؛ constant تغییرناپذیر خطر کمتری دارد.

## نمونهٔ کد مرحله‌ای

Scope تعیین می‌کند نام کجا معتبر است؛ visibility تعیین می‌کند کدام کد بیرونی عضو را می‌بیند. سطح دسترسی بخشی از API و هزینهٔ تغییر است. کوچک‌ترین دسترسی کافی را انتخاب کن و دادهٔ داخلی را برای راحتی به public تبدیل نکن.
**تمرین با پاسخ:** helper فقط داخل یک کلاس مصرف می‌شود؛ private کافی است. اگر subclass واقعاً باید آن را گسترش دهد، protected را با بررسی قرارداد انتخاب کن.

در این طرح C#، نوع‌های پشتیبان کوتاه شده‌اند تا تصمیم طراحی روشن بماند.

~~~csharp
public class Account
{
    private Money _balance;
    protected virtual void OnBalanceChanged() { }
    public Money Balance => _balance;
    internal void Reconcile(Money value) => _balance = value;
}
~~~
