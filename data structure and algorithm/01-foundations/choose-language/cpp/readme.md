# تمرین DSA با C++

> والد: [انتخاب زبان](../readme.md) · [فصل ۱](../../readme.md) · [English](readme.en.md)

## پیش‌نیازها و نقشهٔ ذهنی

تابع، reference، vector و حلقه. ابتدا مفهوم را به‌عنوان یک قرارداد ببین، سپس نمایش حافظه و عملیات را دنبال کن. هدف حفظ‌کردن نام نیست؛ باید بتوانی برای یک ورودی کوچک، state را بعد از هر گام بنویسی.

## ایده از پایه

C++ کنترل مستقیم‌تر روی حافظه، نوع عدد و containerهای STL می‌دهد؛ در برابر آن، ownership، iterator invalidation و undefined behavior را باید جدی بگیری. STL برای تمرین و محصول ساختارهای کارآمدی دارد.

## مدل، قرارداد و ناوردا

`vector<T>` آرایهٔ پویاست؛ `deque<T>` دو سر؛ `list<T>` linked list؛ `stack`, `queue`, `priority_queue`; `map/set` درخت قرمز-سیاه O(log n)، `unordered_map/set` hash میانگین O(1). `priority_queue` پیش‌فرض max-heap است.

ناوردا (invariant) جمله‌ای است که در تمام مراحل الگوریتم باید درست بماند. نوشتن آن پیش از کدنویسی، هم به اثبات درستی کمک می‌کند و هم خطاهای مرزی را آشکار می‌سازد.

## الگوریتم یا عملیات گام‌به‌گام

BFS: `queue<int> q; vector<char> seen(n);`. گراف weighted و کمینه‌اولویت: `priority_queue<pair<long long,int>, vector<...>, greater<...>>`. `vector` را با `reserve` برای تخمین n آماده کن؛ range-based loop برای پیمایش.

در پیاده‌سازی واقعی، قرارداد ورودی/خروجی را دقیق تعریف کن: رفتار ورودی تهی، مقدار تکراری، عنصر پیدا‌نشده و ظرفیت تمام‌شده باید روشن باشد.

## اجرای حل‌شده با ردگیری

`priority_queue<int,vector<int>,greater<int>> pq;` کمترین عنصر را `top()` می‌دهد. Dijkstra فاصله‌ها را `long long` نگه می‌دارد و زوج‌های قدیمی را با `if(d!=dist[u]) continue;` رد می‌کند.

برای تمرین، جدولی با ستون‌های «گام»، «اندیس/اشاره‌گر»، «بخش فعال»، «تغییر state» و «دلیل» بساز. این روش به‌خصوص برای الگوریتم‌های درجا و تقسیم‌و‌غلبه جلوی پرش ذهنی را می‌گیرد.

## چرا درست است؟

iterator/reference به vector پس از reallocation ممکن است نامعتبر شود؛ insert/erase نیز iteratorهای بعدی را جابه‌جا می‌کنند. comparator برای sort و map باید strict weak ordering داشته باشد.

اثبات معمولاً سه بخش دارد: (۱) آغاز—ناوردا پیش از نخستین گام درست است؛ (۲) نگهداری—هر گام آن را حفظ می‌کند؛ (۳) پایان—شرط توقف همراه invariant جواب موردنیاز را نتیجه می‌دهد. اگر یکی از این سه بخش نامشخص است، هنوز درک الگوریتم کامل نشده است.

## تحلیل زمان و حافظه

vector index O(1)، push_back amortized O(1)، insert وسط O(n). map lookup O(log n)، unordered map average O(1)/worst O(n). `std::sort` O(n log n) و stable نیست؛ `stable_sort` حافظهٔ کمکی دارد.

در Big-O ورودی را تعریف کن (مثلاً n تعداد عناصر)، نوع حالت را نام ببر (بهترین/میانگین/بدترین)، و فضای کمکی را از حافظهٔ خود ورودی جدا کن. مرتبهٔ رشد زمان واقعی بر حسب ثانیه نیست؛ cache، تخصیص حافظه و ثابت‌های پیاده‌سازی هم اثر دارند.

## کاربرد واقعی و انتخاب مناسب

پیاده‌سازی کم‌هزینه، سیستم‌های پرفورمنس، گراف/مسابقه و کتابخانه‌های native. در محصول، RAII و containerهای استاندارد خطاهای حافظه را کاهش می‌دهند؛ raw pointer برای مالکیت جدید به‌ندرت لازم است.

پیش از انتخاب بپرس: چه عملیاتی پرتکرارند؟ آیا ترتیب مهم است؟ دادهٔ ورودی چه اندازه است؟ آیا محدودیت حافظه، latency بدترین‌حالت یا thread-safety داریم؟ ساختار خوب برای workload نامناسب می‌تواند انتخاب بدی باشد.

## خطاهای رایج و edge caseها

signed/unsigned مقایسه، integer overflow، iterator invalidation، reference dangling، recursion عمیق و hash worst-case را در نظر بگیر. `vector<bool>` specialization رفتاری متفاوت دارد. comparator sort نباید `<=` بدهد.

حالت‌های مرزی را جداگانه بررسی کن: ورودی خالی، یک عضو، همهٔ اعضا برابر، هدف غایب، حداقل/حداکثر مقدار و اندازهٔ بزرگ. سرریز عدد صحیح در محاسبهٔ اندیس/ظرفیت نیز بسته به زبان مهم است.

## تمرین‌های مرحله‌ای

۱) stack، queue، ordered map و priority_queue را مقایسه کن. ۲) یک loop vector را طوری تغییر بده که iterator بعد از erase باطل نشود. ۳) Dijkstra را با فاصلهٔ 64-bit بنویس.

برای هر تمرین، اول پاسخ ساده و درست بنویس، بعد پیچیدگی را حساب کن، سپس edge case اضافه کن. تمرین را با دست‌کم یک ورودی کوچک ردگیری کن و خروجی را با انتظار مستقل مقایسه کن.

## آزمون جامع با پاسخ تشریحی

ابتدا پاسخ‌ها را نخوان؛ جواب را با استدلال بنویس، سپس توضیح را مقایسه کن.

1. **پرسش:** priority_queue پیش‌فرض چیست؟
   **پاسخ تشریحی:** max-heap.
2. **پرسش:** vector append؟
   **پاسخ تشریحی:** amortized O(1).
3. **پرسش:** map و unordered_map؟
   **پاسخ تشریحی:** درخت O(log n)، hash average O(1).
4. **پرسش:** چرا reserve؟
   **پاسخ تشریحی:** کاهش reallocهای احتمالی وقتی اندازه تخمینی معلوم است.
5. **پرسش:** چه وقت iterator vector باطل می‌شود؟
   **پاسخ تشریحی:** به‌ویژه reallocation و تغییرهای ساختاری مانند insert/erase.

## راهنمای بازگویی از حافظه

بدون نگاه به متن، ایده، پیش‌شرط، invariant، یک ردگیری واقعی، پیچیدگی، edge case و یک کاربرد را در چند دقیقه روی کاغذ توضیح بده. اگر فقط pseudocode را حفظی می‌نویسی اما دلیل درستی یا محدودیت‌ها را نمی‌دانی، یک بار دیگر بخش‌های invariant و خطاها را مرور کن.
