# عقب‌گرد

> مسیر: [فصل ۸ — الگوهای حل مسئله](../README.md) · پیش‌نیاز پیشنهادی: فصل ۱ و مبانی برنامه‌نویسی

## پیش‌نیازها و نقشهٔ ذهنی

DFS، recursion و constraint. ابتدا مفهوم را به‌عنوان یک قرارداد ببین، سپس نمایش حافظه و عملیات را دنبال کن. هدف حفظ‌کردن نام نیست؛ باید بتوانی برای یک ورودی کوچک، state را بعد از هر گام بنویسی.

## ایده از پایه

Backtracking یک جواب را مرحله‌به‌مرحله می‌سازد؛ انتخاب نامعتبر یا بن‌بست را زود تشخیص می‌دهد، انتخاب را undo می‌کند و شاخهٔ بعدی را می‌آزماید. این DFS در فضای جواب‌هاست.

## مدل، قرارداد و ناوردا

state فعلی، گزینه‌های بعدی و constraintها را مشخص کن. pruning باید فقط شاخه‌هایی را حذف کند که هیچ جواب معتبری ندارند (برای یافتن یک جواب) یا بهبود نمی‌دهند (برای optimization با bound درست).

ناوردا (invariant) جمله‌ای است که در تمام مراحل الگوریتم باید درست بماند. نوشتن آن پیش از کدنویسی، هم به اثبات درستی کمک می‌کند و هم خطاهای مرزی را آشکار می‌سازد.

## الگوریتم یا عملیات گام‌به‌گام

search(state): اگر کامل است پاسخ را ثبت/برگردان؛ برای هر choice مجاز: apply؛ اگر هنوز می‌تواند جواب بدهد search؛ undo. undo لازم است اگر state مشترک mutate شده؛ copy هر state ساده‌تر اما پرهزینه‌تر است.

در پیاده‌سازی واقعی، قرارداد ورودی/خروجی را دقیق تعریف کن: رفتار ورودی تهی، مقدار تکراری، عنصر پیدا‌نشده و ظرفیت تمام‌شده باید روشن باشد.

## اجرای حل‌شده با ردگیری

N-Queens: در هر سطر یک ستون انتخاب کن؛ ستون و دو قطر اشغال‌شده را set نگه دار. وقتی خانه با هیچ queen قبلی حمله ندارد، قرار بده و سطر بعدی برو؛ اگر به انتها رسیدی جواب است؛ سپس remove و گزینهٔ بعد را امتحان کن.

برای تمرین، جدولی با ستون‌های «گام»، «اندیس/اشاره‌گر»، «بخش فعال»، «تغییر state» و «دلیل» بساز. این روش به‌خصوص برای الگوریتم‌های درجا و تقسیم‌و‌غلبه جلوی پرش ذهنی را می‌گیرد.

## چرا درست است؟

پیش از recursion، state یک prefix معتبر از جواب است؛ هیچ constraint شکسته نشده. apply و undo باید state را دقیقاً به وضعیت پیشین بازگردانند.

اثبات معمولاً سه بخش دارد: (۱) آغاز—ناوردا پیش از نخستین گام درست است؛ (۲) نگهداری—هر گام آن را حفظ می‌کند؛ (۳) پایان—شرط توقف همراه invariant جواب موردنیاز را نتیجه می‌دهد. اگر یکی از این سه بخش نامشخص است، هنوز درک الگوریتم کامل نشده است.

## تحلیل زمان و حافظه

معمولاً نمایی/فاکتوریلی در بدترین‌حالت؛ pruning تعداد شاخهٔ واقعی را کم می‌کند ولی الزاماً worst-case را تغییر نمی‌دهد. حافظه برابر عمق recursion + state auxiliary است.

در Big-O ورودی را تعریف کن (مثلاً n تعداد عناصر)، نوع حالت را نام ببر (بهترین/میانگین/بدترین)، و فضای کمکی را از حافظهٔ خود ورودی جدا کن. مرتبهٔ رشد زمان واقعی بر حسب ثانیه نیست؛ cache، تخصیص حافظه و ثابت‌های پیاده‌سازی هم اثر دارند.

## کاربرد واقعی و انتخاب مناسب

پازل، زمان‌بندی با constraint، تولید ترکیب‌ها، solverهای کوچک و جست‌وجوی طراحی. برای مسائل بزرگ‌تر SAT/constraint solver یا branch-and-bound تخصصی ممکن است لازم شود.

پیش از انتخاب بپرس: چه عملیاتی پرتکرارند؟ آیا ترتیب مهم است؟ دادهٔ ورودی چه اندازه است؟ آیا محدودیت حافظه، latency بدترین‌حالت یا thread-safety داریم؟ ساختار خوب برای workload نامناسب می‌تواند انتخاب بدی باشد.

## خطاهای رایج و edge caseها

undo ناقص state شاخه‌های بعدی را خراب می‌کند. pruning غیرمعتبر جواب را حذف می‌کند. اگر فقط یک جواب می‌خواهی پس از یافتن، زودتر خارج شو. خروجی همهٔ جواب‌ها ذاتاً می‌تواند نمایی باشد.

حالت‌های مرزی را جداگانه بررسی کن: ورودی خالی، یک عضو، همهٔ اعضا برابر، هدف غایب، حداقل/حداکثر مقدار و اندازهٔ بزرگ. سرریز عدد صحیح در محاسبهٔ اندیس/ظرفیت نیز بسته به زبان مهم است.

## تمرین‌های مرحله‌ای

۱) subset sum را با include/exclude حل کن و sum جاری را نگه دار. ۲) N-Queens N=4 را مرحله‌ای رسم کن. ۳) invariant و undo هر انتخاب را مشخص کن.

برای هر تمرین، اول پاسخ ساده و درست بنویس، بعد پیچیدگی را حساب کن، سپس edge case اضافه کن. تمرین را با دست‌کم یک ورودی کوچک ردگیری کن و خروجی را با انتظار مستقل مقایسه کن.

## آزمون جامع با پاسخ تشریحی

ابتدا پاسخ‌ها را نخوان؛ جواب را با استدلال بنویس، سپس توضیح را مقایسه کن.

1. **پرسش:** Backtracking چیست؟
   **پاسخ تشریحی:** جست‌وجوی DFS در فضای جواب با بازگشت از انتخاب‌های بن‌بست.
2. **پرسش:** چه چیزی prefix معتبر می‌ماند؟
   **پاسخ تشریحی:** state قبل از هر call باید همهٔ constraintها را رعایت کند.
3. **پرسش:** pruning چه شرطی دارد؟
   **پاسخ تشریحی:** نباید شاخهٔ دارای جواب معتبر/بهتر را حذف کند.
4. **پرسش:** هزینهٔ بدترین؟
   **پاسخ تشریحی:** اغلب نمایی یا فاکتوریلی.
5. **پرسش:** چرا undo لازم است؟
   **پاسخ تشریحی:** برای بازگرداندن state مشترک پیش از شاخهٔ بعدی.

## راهنمای بازگویی از حافظه

بدون نگاه به متن، ایده، پیش‌شرط، invariant، یک ردگیری واقعی، پیچیدگی، edge case و یک کاربرد را در چند دقیقه روی کاغذ توضیح بده. اگر فقط pseudocode را حفظی می‌نویسی اما دلیل درستی یا محدودیت‌ها را نمی‌دانی، یک بار دیگر بخش‌های invariant و خطاها را مرور کن.
