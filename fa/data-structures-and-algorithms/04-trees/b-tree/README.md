# درخت B

> مسیر: [فصل ۴ — درخت‌ها و هیپ](../README.md) · پیش‌نیاز پیشنهادی: فصل ۱ و مبانی برنامه‌نویسی

## پیش‌نیازها و نقشهٔ ذهنی

درخت چندراهه، مرتب‌سازی کلید و صفحهٔ حافظه. ابتدا مفهوم را به‌عنوان یک قرارداد ببین، سپس نمایش حافظه و عملیات را دنبال کن. هدف حفظ‌کردن نام نیست؛ باید بتوانی برای یک ورودی کوچک، state را بعد از هر گام بنویسی.

## ایده از پایه

B-tree درخت جست‌وجوی چندراههٔ متوازن است. node می‌تواند چند separator و child داشته باشد؛ fanout زیاد ارتفاع را کم می‌کند و از این رو برای disk/page storage مناسب است. این درس مدل ساختار را پوشش می‌دهد؛ تفاوت با B+ tree را جدا می‌خوانیم.

## مدل، قرارداد و ناوردا

برای B-tree با حداقل درجهٔ t، node غیرریشه حداکثر 2t−1 و حداقل t−1 کلید و حداکثر 2t فرزند دارد؛ ریشه استثنا دارد. کلیدهای k، k+1 بازهٔ فرزند می‌سازند. همهٔ برگ‌ها هم‌عمق‌اند. برخی کتاب‌ها order را بر اساس حداکثر فرزند تعریف می‌کنند، پس قرارداد را تبدیل کن.

ناوردا (invariant) جمله‌ای است که در تمام مراحل الگوریتم باید درست بماند. نوشتن آن پیش از کدنویسی، هم به اثبات درستی کمک می‌کند و هم خطاهای مرزی را آشکار می‌سازد.

## الگوریتم یا عملیات گام‌به‌گام

جست‌وجو: کلیدها را در node مرتب بررسی؛ اگر برابر شد key/payload را پیدا؛ در غیر این صورت child بازهٔ متناظر را انتخاب. درج top-down: پیش از ورود به child پر، آن را split کن؛ میانه به parent می‌رود. حذف: پیش از رفتن به child حداقلی، از sibling قرض بگیر یا merge کن تا underflow مدیریت شود.

در پیاده‌سازی واقعی، قرارداد ورودی/خروجی را دقیق تعریف کن: رفتار ورودی تهی، مقدار تکراری، عنصر پیدا‌نشده و ظرفیت تمام‌شده باید روشن باشد.

## اجرای حل‌شده با ردگیری

t=2، حداکثر 3 key و 4 child در هر node. ریشه [10,20] سه بازه دارد. درج 15 در child میان می‌رود. اگر child پر [12,15,18] باشد، 15 به parent promote و child به [12] و [18] split می‌شود؛ separatorهای root به‌روزرسانی می‌شوند.

برای تمرین، جدولی با ستون‌های «گام»، «اندیس/اشاره‌گر»، «بخش فعال»، «تغییر state» و «دلیل» بساز. این روش به‌خصوص برای الگوریتم‌های درجا و تقسیم‌و‌غلبه جلوی پرش ذهنی را می‌گیرد.

## چرا درست است؟

node occupancy در حد مجاز است؛ keyها مرتب؛ هر child بازهٔ بین separatorهای دو طرف را نگه می‌دارد؛ تمام برگ‌ها در عمق یکسان‌اند. Root split ارتفاع را یک واحد زیاد می‌کند، merge root ممکن است آن را کم کند.

اثبات معمولاً سه بخش دارد: (۱) آغاز—ناوردا پیش از نخستین گام درست است؛ (۲) نگهداری—هر گام آن را حفظ می‌کند؛ (۳) پایان—شرط توقف همراه invariant جواب موردنیاز را نتیجه می‌دهد. اگر یکی از این سه بخش نامشخص است، هنوز درک الگوریتم کامل نشده است.

## تحلیل زمان و حافظه

ارتفاع O(log_t n) و search/insert/delete O(log_t n) node/page visits. داخل node با binary search O(log t) مقایسه یا linear scan کوچک. انتخاب t بر اساس اندازهٔ page و fanout انجام می‌شود.

در Big-O ورودی را تعریف کن (مثلاً n تعداد عناصر)، نوع حالت را نام ببر (بهترین/میانگین/بدترین)، و فضای کمکی را از حافظهٔ خود ورودی جدا کن. مرتبهٔ رشد زمان واقعی بر حسب ثانیه نیست؛ cache، تخصیص حافظه و ثابت‌های پیاده‌سازی هم اثر دارند.

## کاربرد واقعی و انتخاب مناسب

database index و file system. هر node معمولاً با یک page دیسک/بلوک خواندن سازگار می‌شود؛ کاهش height یعنی random I/O کمتر. Buffer pool می‌تواند nodeهای بالایی را در حافظه نگه دارد.

پیش از انتخاب بپرس: چه عملیاتی پرتکرارند؟ آیا ترتیب مهم است؟ دادهٔ ورودی چه اندازه است؟ آیا محدودیت حافظه، latency بدترین‌حالت یا thread-safety داریم؟ ساختار خوب برای workload نامناسب می‌تواند انتخاب بدی باشد.

## خطاهای رایج و edge caseها

تعریف minimum degree با order را اشتباه نکن. split باید separator را به parent ببرد، نه فقط فرزندها را دو نیم کند. در B-tree payload ممکن است در internal node هم باشد؛ B+ tree فرق دارد.

حالت‌های مرزی را جداگانه بررسی کن: ورودی خالی، یک عضو، همهٔ اعضا برابر، هدف غایب، حداقل/حداکثر مقدار و اندازهٔ بزرگ. سرریز عدد صحیح در محاسبهٔ اندیس/ظرفیت نیز بسته به زبان مهم است.

## تمرین‌های مرحله‌ای

۱) occupancy برای t=3 را حساب کن. ۲) درج‌هایی طراحی کن که split برگ‌مانند node و root رخ دهد. ۳) برای lookup در height=4 چند page در مسیر خوانده می‌شود؟

برای هر تمرین، اول پاسخ ساده و درست بنویس، بعد پیچیدگی را حساب کن، سپس edge case اضافه کن. تمرین را با دست‌کم یک ورودی کوچک ردگیری کن و خروجی را با انتظار مستقل مقایسه کن.

## آزمون جامع با پاسخ تشریحی

ابتدا پاسخ‌ها را نخوان؛ جواب را با استدلال بنویس، سپس توضیح را مقایسه کن.

1. **پرسش:** حداکثر keyهای node برای حداقل درجه t؟
   **پاسخ تشریحی:** 2t−1.
2. **پرسش:** حداکثر فرزند؟
   **پاسخ تشریحی:** 2t.
3. **پرسش:** برگ‌ها چه شرطی دارند؟
   **پاسخ تشریحی:** همه هم‌عمق‌اند.
4. **پرسش:** چرا B-tree fanout بالا می‌خواهد؟
   **پاسخ تشریحی:** کاهش ارتفاع و page I/O.
5. **پرسش:** فرق B+؟
   **پاسخ تشریحی:** در B+ معمولاً payloadها در برگ متمرکزند و برگ‌ها پیوند می‌خورند.
