# دو اشاره‌گر

> نسخهٔ انگلیسی: [English version](../../../../en/data-structures-and-algorithms/08-problem-solving-techniques/two-pointers/README.md)

> مسیر: [فصل ۸ — الگوهای حل مسئله](../README.md) · پیش‌نیاز پیشنهادی: فصل ۱ و مبانی برنامه‌نویسی

## پیش‌نیازها و نقشهٔ ذهنی

آرایه/رشته، حلقه و گاهی ترتیب داده. ابتدا مفهوم را به‌عنوان یک قرارداد ببین، سپس نمایش حافظه و عملیات را دنبال کن. هدف حفظ‌کردن نام نیست؛ باید بتوانی برای یک ورودی کوچک، state را بعد از هر گام بنویسی.

## ایده از پایه

دو index را با رابطه‌ای هدفمند جابه‌جا می‌کنیم تا دوباره‌کاری کم شود. الگوهای رایج دو سر آرایه، دو اشاره‌گر هم‌جهت، یا اشاره‌گرهای slow/fast هستند. مرتب‌بودن داده اغلب شرط کلیدی است.

## مدل، قرارداد و ناوردا

پیش از حرکت، ثابت کن pointerها چه فضای کاندیدی را حذف می‌کنند. در sorted two-sum، اگر مجموع کم است، کوچک‌ترین عنصر فعلی را با بزرگ‌ترین جفت ممکن امتحان کرده‌ایم؛ پس left++ امن است.

ناوردا (invariant) جمله‌ای است که در تمام مراحل الگوریتم باید درست بماند. نوشتن آن پیش از کدنویسی، هم به اثبات درستی کمک می‌کند و هم خطاهای مرزی را آشکار می‌سازد.

## الگوریتم یا عملیات گام‌به‌گام

برای target sum روی آرایهٔ مرتب: l=0,r=n−1؛ تا l<r: sum؛ اگر برابر پاسخ، اگر کمتر l++، اگر بیشتر r−−. هر گام یک عضو را حذف می‌کند و O(n) می‌شود. برای حذف duplicateهای مجاور نیز write pointer فشرده‌سازی می‌کند.

در پیاده‌سازی واقعی، قرارداد ورودی/خروجی را دقیق تعریف کن: رفتار ورودی تهی، مقدار تکراری، عنصر پیدا‌نشده و ظرفیت تمام‌شده باید روشن باشد.

## اجرای حل‌شده با ردگیری

[1,2,4,6,9], target=10: 1+9=10، پاسخ (0,4). برای target=8: 1+9>8 پس r به 6؛ 1+6<8 پس l به 2؛ 2+6=8.

برای تمرین، جدولی با ستون‌های «گام»، «اندیس/اشاره‌گر»، «بخش فعال»، «تغییر state» و «دلیل» بساز. این روش به‌خصوص برای الگوریتم‌های درجا و تقسیم‌و‌غلبه جلوی پرش ذهنی را می‌گیرد.

## چرا درست است؟

برای دو سر sorted، همهٔ جفت‌هایی که left فعلی را با راست‌های حذف‌شده می‌سازند به دلیل مجموع کوچک، از هدف کمتر/مساوی‌اند یا در جهت حذف مجازند؛ استدلال دقیق وابسته به شرط است.

اثبات معمولاً سه بخش دارد: (۱) آغاز—ناوردا پیش از نخستین گام درست است؛ (۲) نگهداری—هر گام آن را حفظ می‌کند؛ (۳) پایان—شرط توقف همراه invariant جواب موردنیاز را نتیجه می‌دهد. اگر یکی از این سه بخش نامشخص است، هنوز درک الگوریتم کامل نشده است.

## تحلیل زمان و حافظه

معمول O(n) زمان و O(1) فضای اضافی. اگر sort لازم باشد، هزینهٔ O(n log n) و از دست‌رفتن index اصلی را لحاظ کن؛ pair original indices را نگه دار اگر خروجی به آن نیاز دارد.

در Big-O ورودی را تعریف کن (مثلاً n تعداد عناصر)، نوع حالت را نام ببر (بهترین/میانگین/بدترین)، و فضای کمکی را از حافظهٔ خود ورودی جدا کن. مرتبهٔ رشد زمان واقعی بر حسب ثانیه نیست؛ cache، تخصیص حافظه و ثابت‌های پیاده‌سازی هم اثر دارند.

## کاربرد واقعی و انتخاب مناسب

sorted two-sum، partition، deduplicate، palindrome، merge دو دنبالهٔ مرتب و container water. در linked list ممکن است حرکت اشاره‌گر معادل دسترسی O(1) باشد؛ در آرایه دسترسی index سریع است.

پیش از انتخاب بپرس: چه عملیاتی پرتکرارند؟ آیا ترتیب مهم است؟ دادهٔ ورودی چه اندازه است؟ آیا محدودیت حافظه، latency بدترین‌حالت یا thread-safety داریم؟ ساختار خوب برای workload نامناسب می‌تواند انتخاب بدی باشد.

## خطاهای رایج و edge caseها

بدون sorted بودن، حرکت greedy left/right معتبر نیست. شرط l<r جلوی استفادهٔ دوباره از یک عنصر را می‌گیرد. duplicate و tie را دقیق اداره کن.

حالت‌های مرزی را جداگانه بررسی کن: ورودی خالی، یک عضو، همهٔ اعضا برابر، هدف غایب، حداقل/حداکثر مقدار و اندازهٔ بزرگ. سرریز عدد صحیح در محاسبهٔ اندیس/ظرفیت نیز بسته به زبان مهم است.

## تمرین‌های مرحله‌ای

۱) دو اشاره‌گر را برای targetهای کمتر/برابر/بیشتر ردگیری کن. ۲) آرایهٔ مرتب را in-place یکتا کن. ۳) ثابت کن چرا برای target sum حرکت هر سمت امن است.

برای هر تمرین، اول پاسخ ساده و درست بنویس، بعد پیچیدگی را حساب کن، سپس edge case اضافه کن. تمرین را با دست‌کم یک ورودی کوچک ردگیری کن و خروجی را با انتظار مستقل مقایسه کن.

## آزمون جامع با پاسخ تشریحی

ابتدا پاسخ‌ها را نخوان؛ جواب را با استدلال بنویس، سپس توضیح را مقایسه کن.

1. **پرسش:** دو اشاره‌گر چه می‌خواهد؟
   **پاسخ تشریحی:** حرکت دو index با invariantی که کاندیدها را کاهش دهد.
2. **پرسش:** two-sum دو سر معمولاً چه پیش‌نیاز دارد؟
   **پاسخ تشریحی:** آرایهٔ مرتب.
3. **پرسش:** زمان؟
   **پاسخ تشریحی:** یک pass O(n).
4. **پرسش:** اگر sort کنیم چه می‌شود؟
   **پاسخ تشریحی:** هزینه O(n log n) و احتمال از دست رفتن index اولیه.
5. **پرسش:** چه شرطی duplicate استفاده را محدود می‌کند؟
   **پاسخ تشریحی:** l<r.

## راهنمای بازگویی از حافظه

بدون نگاه به متن، ایده، پیش‌شرط، invariant، یک ردگیری واقعی، پیچیدگی، edge case و یک کاربرد را در چند دقیقه روی کاغذ توضیح بده. اگر فقط pseudocode را حفظی می‌نویسی اما دلیل درستی یا محدودیت‌ها را نمی‌دانی، یک بار دیگر بخش‌های invariant و خطاها را مرور کن.
