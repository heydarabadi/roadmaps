# فیلتر، Operator، Projection و Cursor

> **English edition:** [Read this lesson in English](../../../../en/mongodb/02-operations/queries-cursors/README.md).

> **هدف یادگیری:** عملگرهای query، آرایه، سند توکار و pagination را درست به کار ببرید.

## جایگاه در مسیر
این درس بخشی از فصل مربوط است. مثال‌ها برای محیط آزمایشی‌اند؛ نسخه و قابلیت deployment خود را در مستندات رسمی بررسی کنید.

## آموزش
Filter سندهای مطابق شرط را انتخاب می‌کند. عملگرهای مقایسه‌ای $eq، $gt، $gte، $lt و $ne؛ منطقی $and، $or، $not و $nor؛ و $exists، $type و $regex برای فیلترهای متنوع‌اند. برای فیلد توکار dot notation به کار می‌رود. Projection با مقدار 1/0 fieldها را انتخاب می‌کند؛ $slice می‌تواند تعداد عضوهای آرایهٔ خروجی را محدود کند. $elemMatch چند شرط را روی همان عضو آرایه اعمال می‌کند.

find() یک cursor می‌دهد، نه الزاماً آرایهٔ کامل. cursor را batchای مصرف کنید. skip بزرگ گران می‌شود؛ برای صفحه‌بندی پرترافیک keyset pagination با کلید sort یکتا را بررسی کنید. countDocuments با filter می‌شمارد؛ estimatedDocumentCount تخمین کل collection است.

## تدریس کامل: ساخت filterهای درست

### برابری و مقایسه

{status:"paid"} برابری را می‌سنجد. برای range از $gt، $gte، $lt، $lte استفاده کنید. شرط‌های هم‌سطح معمولاً AND ضمنی هستند. برای OR صریح بنویسید:

~~~javascript
db.orders.find({
  $or: [
    { status: "paid" },
    { status: "shipped" }
  ]
})
~~~

$in می‌گوید مقدار field یکی از چند گزینه باشد. $exists وجود field را می‌سنجد؛ نبودن field با مقدار null فرق دارد. $type نوع BSON را بررسی می‌کند.

### سند توکار و آرایه

برای فیلد توکار از dot notation استفاده کنید: {"address.city":"Tehran"}. برای بررسی آرایه، $all، $size، $in و $elemMatch کاربرد دارند. اگر sku و qty باید در همان عضو آرایه باشند، از $elemMatch استفاده کنید:

~~~javascript
db.orders.find({
  items: { $elemMatch: { sku: "KB-01", qty: { $gte: 2 } } }
})
~~~

بدون $elemMatch شرط‌های path ممکن است به عضوهای متفاوت همان آرایه بخورند و معنای مطلوب را ندهند.

### Projection

Projection را در find به شکل سندی از 1 و 0 می‌نویسیم: 1 برای نگه‌داشتن و 0 برای حذف field. معمولاً inclusion و exclusion را مخلوط نمی‌کنیم؛ استثنای رایج حذف _id از projection انتخابی است. این‌ها operatorهای مستقل `$include`/`$exclude` نیستند؛ روش projection هستند. برای مثال `find(filter, { name: 1, price: 1, _id: 0 })` فقط همان دو field را برمی‌گرداند. برای محدودکردن آرایه می‌توان نوشت `find({}, { items: { $slice: 5 } })`. projection ترافیک شبکه و مصرف حافظه را کم می‌کند، اما جای index مناسب را نمی‌گیرد.

### Regex و امنیت

Regex برای الگوی متنی ساده مفید است؛ regex با ابتدای آزاد می‌تواند collection را گران اسکن کند. ورودی query را مستقیم به filter تبدیل نکنید. API باید fieldهای مجاز، operatorهای مجاز، طول ورودی، بازهٔ زمانی و page size را کنترل کند. این هم امنیت است و هم مدیریت هزینه.

### تمرین ذهنی

برای query «سفارش‌های باز مشتری X در بازهٔ زمانی» فیلتر status، customerId و دو حد Date را بنویسید؛ بعد index مناسب را از sort و الگوی query استخراج کنید. اول صحت معنایی را ثابت کنید، سپس کارایی را با explain بسنجید.

## مثال
~~~javascript
db.orders.find({
  status: { $in: ["paid", "shipped"] },
  "shipping.city": "تهران",
  items: { $elemMatch: { sku: "A-2", qty: { $gte: 2 } } }
}).sort({ createdAt: -1, _id: -1 }).limit(50)
~~~

## تجربهٔ واقعی یا سناریوی کاربردی
فیلتر پنل پشتیبانی باید userId و بازهٔ زمان را با نوع درست و سقف محدود کند؛ query خام کاربر را عبور ندهید. برای sort و pagination، index را با query تطبیق دهید.

## خطاهای رایج
- چند شرط آرایه‌ای بدون $elemMatch.
- regex آزاد و گران.
- یکی گرفتن null با نبودن فیلد.
- مصرف تمام cursor در حافظه.
- skip بسیار بزرگ.

## تمرین
1. سفارش‌های پرداخت‌شدهٔ یک هفته را برگردانید.
2. صفحهٔ بعدی را با کلیدهای createdAt و _id طراحی کنید.

## آزمون و پاسخ
1. **پرسش:** $or چه می‌کند؟
   **پاسخ:** حداقل یکی از شرط‌ها باید برقرار باشد.
2. **پرسش:** $elemMatch برای چیست؟
   **پاسخ:** الزام چند شرط به یک عضو آرایه.
3. **پرسش:** find چه برمی‌گرداند؟
   **پاسخ:** Cursor قابل پیمایش.
4. **پرسش:** چرا باید از «چند شرط آرایه‌ای بدون $elemMatch.» پرهیز کرد؟
   **پاسخ:** دو شرط مستقل روی مسیرهای یک آرایه ممکن است با دو عضو متفاوت آن برقرار شوند. اگر شرط‌ها باید دربارهٔ یک عضو باشند، آن‌ها را در `$elemMatch` قرار دهید.
5. **مسئلهٔ کاربردی:** سفارش‌های پرداخت‌شدهٔ یک هفته را برگردانید.
   **پاسخ نمونه:** برای شرط‌های مقایسه از $gte/$lt، ترکیب OR از $or، سند توکار از dot notation و شرط‌های یک عضو آرایه از $elemMatch استفاده کنید؛ خروجی را با projection و pagination محدود کنید.

## آزمون تکمیلی — مفاهیم و تصمیم‌گیری

6. **پرسش:** $elemMatch چه تضمینی می‌دهد؟
   **پاسخ:** چند شرط روی یک عضو آرایه اعمال می‌شوند.
7. **پرسش:** $exists:false با null چه فرق دارد؟
   **پاسخ:** اولی نبودن field را می‌سنجد؛ null یک مقدار موجود نیز می‌تواند باشد.
8. **پرسش:** projection چه چیزی را کاهش می‌دهد؟
   **پاسخ:** اندازهٔ پاسخ و انتقال/حافظهٔ مصرف‌شده.
9. **پرسش:** چرا regex با ابتدای آزاد پرهزینه است؟
   **پاسخ:** ممکن است نتواند از ترتیب index برای محدودکردن جست‌وجو استفاده کند.
10. **پرسش:** چرا filter خام کاربر را اجرا نمی‌کنیم؟
   **پاسخ:** ممکن است operator تزریقی و query پرهزینه یا ناامن وارد شود.
