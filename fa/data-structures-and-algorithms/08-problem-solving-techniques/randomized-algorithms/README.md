# الگوریتم تصادفی

> نسخهٔ انگلیسی: [English version](../../../../en/data-structures-and-algorithms/08-problem-solving-techniques/randomized-algorithms/README.md)

> مسیر: [فصل ۸ — الگوهای حل مسئله](../README.md) · پیش‌نیاز پیشنهادی: فصل ۱ و مبانی برنامه‌نویسی

## پیش‌نیازها و نقشهٔ ذهنی

احتمال پایه، الگوریتم و complexity موردانتظار. ابتدا مفهوم را به‌عنوان یک قرارداد ببین، سپس نمایش حافظه و عملیات را دنبال کن. هدف حفظ‌کردن نام نیست؛ باید بتوانی برای یک ورودی کوچک، state را بعد از هر گام بنویسی.

## ایده از پایه

الگوریتم از تصادف کنترل‌شده برای سرعت یا سادگی استفاده می‌کند. Las Vegas همیشه جواب درست می‌دهد ولی زمان تصادفی دارد؛ Monte Carlo زمان/تعداد گام محدود دارد اما احتمال خطا. نوع تضمین را صریح بنویس.

## مدل، قرارداد و ناوردا

قرعه‌کشی باید unbiased باشد تا همهٔ گزینه‌ها شانس برابر داشته باشند. Expected runtime روی تصادف الگوریتم محاسبه می‌شود؛ worst-case ممکن است هنوز بد باشد. Seed ثابت تکرارپذیری تست را می‌دهد؛ seed امن رمزنگاری نیاز جدا دارد.

ناوردا (invariant) جمله‌ای است که در تمام مراحل الگوریتم باید درست بماند. نوشتن آن پیش از کدنویسی، هم به اثبات درستی کمک می‌کند و هم خطاهای مرزی را آشکار می‌سازد.

## الگوریتم یا عملیات گام‌به‌گام

Randomized Quickselect pivot را یکنواخت انتخاب می‌کند؛ پاسخ همواره درست، زمان موردانتظار O(n)، worst O(n²): Las Vegas. الگوریتم primality احتمالی با تعداد round بیشتر احتمال خطا را کاهش می‌دهد: Monte Carlo. Reservoir sampling اندازهٔ k را از stream با احتمال برابر انتخاب می‌کند.

در پیاده‌سازی واقعی، قرارداد ورودی/خروجی را دقیق تعریف کن: رفتار ورودی تهی، مقدار تکراری، عنصر پیدا‌نشده و ظرفیت تمام‌شده باید روشن باشد.

## اجرای حل‌شده با ردگیری

Reservoir k=1: عضو اول را نگه‌دار. برای عضو i از n (1-based)، با احتمال 1/i جایگزین کن. در پایان هر عضو احتمال 1/n دارد؛ چون احتمال انتخاب در گام i برابر 1/i و بعد جایگزین‌نشدن تا n برابر i/n است.

برای تمرین، جدولی با ستون‌های «گام»، «اندیس/اشاره‌گر»، «بخش فعال»، «تغییر state» و «دلیل» بساز. این روش به‌خصوص برای الگوریتم‌های درجا و تقسیم‌و‌غلبه جلوی پرش ذهنی را می‌گیرد.

## چرا درست است؟

برای reservoir، پس از پردازش i عنصر، هر عنصر احتمال k/i انتخاب در reservoir را دارد (برای k کلی الگوریتم دقیق sampling لازم است). برای pivot، تصادفی‌بودن از وابستگی کارایی به ترتیب adversarial ورودی می‌کاهد.

اثبات معمولاً سه بخش دارد: (۱) آغاز—ناوردا پیش از نخستین گام درست است؛ (۲) نگهداری—هر گام آن را حفظ می‌کند؛ (۳) پایان—شرط توقف همراه invariant جواب موردنیاز را نتیجه می‌دهد. اگر یکی از این سه بخش نامشخص است، هنوز درک الگوریتم کامل نشده است.

## تحلیل زمان و حافظه

Randomized Quickselect expected O(n)، worst O(n²)؛ reservoir O(n) زمان و O(k) فضا؛ randomized hash table expected O(1) تحت hash assumptions. احتمال خطا/زمان باید همراه اعداد پارامتر گزارش شود.

در Big-O ورودی را تعریف کن (مثلاً n تعداد عناصر)، نوع حالت را نام ببر (بهترین/میانگین/بدترین)، و فضای کمکی را از حافظهٔ خود ورودی جدا کن. مرتبهٔ رشد زمان واقعی بر حسب ثانیه نیست؛ cache، تخصیص حافظه و ثابت‌های پیاده‌سازی هم اثر دارند.

## کاربرد واقعی و انتخاب مناسب

sampling دادهٔ بزرگ، A/B experiment، randomized load balancing، pivot انتخابی، و الگوریتم‌های cryptographic با CSPRNG مناسب. تصادف در امنیت باید از منبع امن بیاید، نه PRNG معمولی.

پیش از انتخاب بپرس: چه عملیاتی پرتکرارند؟ آیا ترتیب مهم است؟ دادهٔ ورودی چه اندازه است؟ آیا محدودیت حافظه، latency بدترین‌حالت یا thread-safety داریم؟ ساختار خوب برای workload نامناسب می‌تواند انتخاب بدی باشد.

## خطاهای رایج و edge caseها

«تصادفی» به معنی unbiased نیست. seed و concurrency ممکن است نتایج را تغییر دهد. expected case تضمین worst-case نیست. خطای Monte Carlo را با تکرار/تحلیل کاهش بده؛ برای randomness امنیتی از API امن استفاده کن.

حالت‌های مرزی را جداگانه بررسی کن: ورودی خالی، یک عضو، همهٔ اعضا برابر، هدف غایب، حداقل/حداکثر مقدار و اندازهٔ بزرگ. سرریز عدد صحیح در محاسبهٔ اندیس/ظرفیت نیز بسته به زبان مهم است.

## تمرین‌های مرحله‌ای

۱) احتمال ماندن عنصر اول در reservoir پس از n را حساب کن. ۲) فرق Las Vegas/Monte Carlo را با مثال بگو. ۳) quicksort با pivot تصادفی را روی ورودی مرتب تحلیل کن.

برای هر تمرین، اول پاسخ ساده و درست بنویس، بعد پیچیدگی را حساب کن، سپس edge case اضافه کن. تمرین را با دست‌کم یک ورودی کوچک ردگیری کن و خروجی را با انتظار مستقل مقایسه کن.

## آزمون جامع با پاسخ تشریحی

ابتدا پاسخ‌ها را نخوان؛ جواب را با استدلال بنویس، سپس توضیح را مقایسه کن.

1. **پرسش:** Las Vegas چه تضمین می‌دهد؟
   **پاسخ تشریحی:** جواب درست، اما runtime تصادفی.
2. **پرسش:** Monte Carlo؟
   **پاسخ تشریحی:** زمان/تلاش محدود و احتمال خطا.
3. **پرسش:** random pivot چه اثری دارد؟
   **پاسخ تشریحی:** کارایی موردانتظار را از ترتیب ورودی مستقل‌تر می‌کند.
4. **پرسش:** seed ثابت چه فایده‌ای دارد؟
   **پاسخ تشریحی:** تکرارپذیری و debug.
5. **پرسش:** برای secret چه RNG لازم است؟
   **پاسخ تشریحی:** مولد شبه‌تصادفی رمزنگاری‌شده (CSPRNG).
