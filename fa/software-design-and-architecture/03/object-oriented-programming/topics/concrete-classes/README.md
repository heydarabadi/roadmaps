## هدف یادگیری

پس از این درس بتوانی مفهوم را با زبان خودت تعریف کنی، در مثال دامنه‌ای تشخیصش بدهی و هزینهٔ انتخاب یا کنارگذاشتنش را توضیح بدهی.

## آموزش

کلاس عینی قرارداد لازم را پیاده می‌کند و می‌تواند نمونه‌سازی شود؛ آن باید رفتار کامل و معتبر برای کاربرد هدف داشته باشد.

## مثال کاربردی

`StripeGateway` یک adapter عینی است که قرارداد پرداخت را برای یک درگاه مشخص پیاده می‌کند.

این مثال آموزشی است و ادعای پیاده‌سازی دقیق یک شرکت مشخص را ندارد. نمونهٔ صنعتی مستند و زمینهٔ آن در فصل «برنامه‌نویسی شیءگرا» پیوند داده شده است.

## تصمیم معماری و محدودیت‌ها

- **چه زمانی به‌کار ببر:** وقتی مسئلهٔ اصلی‌ای که مفهوم حل می‌کند در سامانه واقعاً دیده می‌شود و قراردادش می‌تواند در کد یا آزمون بررسی شود.
- **چه زمانی ساده‌تر بماند:** کلاس عینی را مستقیم در همهٔ مصرف‌کننده‌ها ساختن، تعویض و آزمون را سخت می‌کند.
- **بازبینی:** ساخت و تزریق وابستگی را از منطق use case جدا کن.

## کوییز با پاسخ تشریحی

پاسخ را بپوشان و ابتدا با کلمات خودت توضیح بده؛ پاسخ پیشنهادی معیار سنجش است، نه تنها عبارت درست.

1. **این مفهوم دقیقاً چه مسئله‌ای را حل می‌کند؟**
   - پاسخ پیشنهادی: کلاس عینی قرارداد لازم را پیاده می‌کند و می‌تواند نمونه‌سازی شود؛ آن باید رفتار کامل و معتبر برای کاربرد هدف داشته باشد.
2. **در مثال زیر چه تصمیمی می‌گیری و چرا؟**
   - پاسخ پیشنهادی: `StripeGateway` یک adapter عینی است که قرارداد پرداخت را برای یک درگاه مشخص پیاده می‌کند.
3. **چه زمانی انتخاب آن نامناسب یا پرهزینه است؟**
   - پاسخ پیشنهادی: کلاس عینی را مستقیم در همهٔ مصرف‌کننده‌ها ساختن، تعویض و آزمون را سخت می‌کند.
4. **کدام خطای رایج را قبل از ادغام کد بررسی می‌کنی؟**
   - پاسخ پیشنهادی: ساخت و تزریق وابستگی را از منطق use case جدا کن.

## آموزش تکمیلی مستقل

#### Concrete class

کلاس عینی قرارداد را کامل پیاده می‌کند و قابل ساخت است. StripeGateway نمونهٔ adapter concrete است. composition root یا factory باید وابستگی‌های حساس را پیکربندی کند؛ callerهای متعدد نباید خودشان درگاه واقعی را new کنند. interface را فقط به خاطر «شاید روزی» نساز.

## نمونهٔ کد مرحله‌ای

کلاس concrete جزئیات اجرایی را فراهم می‌کند و مستقیماً ساخته می‌شود. ساختش را در composition root نگه دار تا قانون کسب‌وکار به SQL، SDK یا شبکه گره نخورد. برای هر کلاس interface نساز؛ مرز زمانی لازم است که variation، ownership یا آزمون آن را توجیه کند.
**تمرین با پاسخ:** repository واقعی در کجا به برنامه وصل می‌شود؟ در composition root؛ use case فقط قرارداد ذخیره‌سازی را می‌بیند.

در این طرح C#، نوع‌های پشتیبان کوتاه شده‌اند تا تصمیم طراحی روشن بماند.

~~~csharp
public interface IOrderRepository
{
    Task<Order?> Find(OrderId id, CancellationToken ct);
}

services.AddScoped<IOrderRepository, SqlOrderRepository>();
~~~
