# تمرین DSA با Python

> والد: [انتخاب زبان](../readme.md) · [فصل ۱](../../readme.md) · [English](readme.en.md)

## پیش‌نیازها و نقشهٔ ذهنی

متغیر، تابع، شرط، حلقه و لیست. ابتدا مفهوم را به‌عنوان یک قرارداد ببین، سپس نمایش حافظه و عملیات را دنبال کن. هدف حفظ‌کردن نام نیست؛ باید بتوانی برای یک ورودی کوچک، state را بعد از هر گام بنویسی.

## ایده از پایه

Python برای بیان روشن الگوریتم و نمونه‌سازی سریع مناسب است. زبان ابزار مسئله است: پیچیدگی ساختارهای داخلی، هزینهٔ objectها و رفتار mutableها را باید جدا از ظاهر کوتاه کد بشناسی.

## مدل، قرارداد و ناوردا

`list` آرایهٔ پویا است؛ دسترسی index O(1)، append سرشکن O(1)، insert/pop ابتدا O(n). `dict` و `set` hash-based و عملیات میانگین O(1) دارند. `collections.deque` صف دوطرفه است و append/pop دو سر O(1). `heapq` min-heap است. `bisect` روی لیست مرتب مرز دودویی می‌یابد اما درج همچنان O(n) است.

ناوردا (invariant) جمله‌ای است که در تمام مراحل الگوریتم باید درست بماند. نوشتن آن پیش از کدنویسی، هم به اثبات درستی کمک می‌کند و هم خطاهای مرزی را آشکار می‌سازد.

## الگوریتم یا عملیات گام‌به‌گام

Stack: `stack.append(x)` و `stack.pop()`. Queue: `deque.append(x)` و `popleft()`. BFS: صف را با مبدأ شروع، هنگام اولین دیدن neighbor visited کن و enqueue. Priority queue: `heapq.heappush(h,(priority,item))`; برای max-heap از منفی priority یا API نسخهٔ هدف استفاده کن.

در پیاده‌سازی واقعی، قرارداد ورودی/خروجی را دقیق تعریف کن: رفتار ورودی تهی، مقدار تکراری، عنصر پیدا‌نشده و ظرفیت تمام‌شده باید روشن باشد.

## اجرای حل‌شده با ردگیری

BFS اسکلت: `q=deque([s]); seen={s}`؛ تا q: `u=q.popleft()`؛ برای v در adj[u] اگر ندیده، seen.add(v)، q.append(v). visited هنگام enqueue است تا رأس چندبار در صف نرود. دیکشنری parent مسیر را می‌سازد.

برای تمرین، جدولی با ستون‌های «گام»، «اندیس/اشاره‌گر»، «بخش فعال»، «تغییر state» و «دلیل» بساز. این روش به‌خصوص برای الگوریتم‌های درجا و تقسیم‌و‌غلبه جلوی پرش ذهنی را می‌گیرد.

## چرا درست است؟

برای list، index معتبر `0..len-1` است. برای dict، کلیدها باید hashable و hash/equality پایدار داشته باشند. برای heap، فقط ریشه کمینه است؛ کل آرایه مرتب نیست.

اثبات معمولاً سه بخش دارد: (۱) آغاز—ناوردا پیش از نخستین گام درست است؛ (۲) نگهداری—هر گام آن را حفظ می‌کند؛ (۳) پایان—شرط توقف همراه invariant جواب موردنیاز را نتیجه می‌دهد. اگر یکی از این سه بخش نامشخص است، هنوز درک الگوریتم کامل نشده است.

## تحلیل زمان و حافظه

Python int اندازهٔ ثابت machine integer نیست و رشد می‌کند؛ slicing list رشته/لیست جدید می‌سازد و O(k) است؛ `x in list` O(n)، `x in set/dict` میانگین O(1). حافظهٔ objectها از آرایهٔ native بیشتر است و constant factorها روی محدودیت مسابقه اثر دارند.

در Big-O ورودی را تعریف کن (مثلاً n تعداد عناصر)، نوع حالت را نام ببر (بهترین/میانگین/بدترین)، و فضای کمکی را از حافظهٔ خود ورودی جدا کن. مرتبهٔ رشد زمان واقعی بر حسب ثانیه نیست؛ cache، تخصیص حافظه و ثابت‌های پیاده‌سازی هم اثر دارند.

## کاربرد واقعی و انتخاب مناسب

پروتوتایپ الگوریتم، پردازش داده و تمرین مصاحبه. برای CPU-heavy loopهای بزرگ ممکن است overhead interpreter محسوس شود؛ profiling و کتابخانهٔ بهینه/کد native را پس از اثبات نیاز بررسی کن.

پیش از انتخاب بپرس: چه عملیاتی پرتکرارند؟ آیا ترتیب مهم است؟ دادهٔ ورودی چه اندازه است؟ آیا محدودیت حافظه، latency بدترین‌حالت یا thread-safety داریم؟ ساختار خوب برای workload نامناسب می‌تواند انتخاب بدی باشد.

## خطاهای رایج و edge caseها

`list.pop(0)` صف مناسبی نیست چون بقیه جابه‌جا می‌شوند. کپی slice پنهان، `sort()` که in-place و `sorted()` که خروجی تازه می‌سازد، tuple priority در heap برای tie، و recursion limit را بشناس. تغییر default mutable در آرگومان تابع دام رایج است.

حالت‌های مرزی را جداگانه بررسی کن: ورودی خالی، یک عضو، همهٔ اعضا برابر، هدف غایب، حداقل/حداکثر مقدار و اندازهٔ بزرگ. سرریز عدد صحیح در محاسبهٔ اندیس/ظرفیت نیز بسته به زبان مهم است.

## تمرین‌های مرحله‌ای

۱) stack، queue و min-heap را فقط با API استاندارد بساز. ۲) membership در list/dict را برای n بزرگ از نظر مرتبه مقایسه کن. ۳) یک BFS با `deque` بنویس و حافظهٔ visited را تحلیل کن.

برای هر تمرین، اول پاسخ ساده و درست بنویس، بعد پیچیدگی را حساب کن، سپس edge case اضافه کن. تمرین را با دست‌کم یک ورودی کوچک ردگیری کن و خروجی را با انتظار مستقل مقایسه کن.

## آزمون جامع با پاسخ تشریحی

ابتدا پاسخ‌ها را نخوان؛ جواب را با استدلال بنویس، سپس توضیح را مقایسه کن.

1. **پرسش:** صف سریع از چه چیزی؟
   **پاسخ تشریحی:** collections.deque با popleft.
2. **پرسش:** heapq چه نوع heap است؟
   **پاسخ تشریحی:** min-heap.
3. **پرسش:** `x in list` چه زمان دارد؟
   **پاسخ تشریحی:** O(n).
4. **پرسش:** چرا slicing هزینه دارد؟
   **پاسخ تشریحی:** بخش تازه‌ای کپی می‌شود، معمولاً O(k).
5. **پرسش:** دیکشنری چه قیدی روی کلید دارد؟
   **پاسخ تشریحی:** Hashable باشد و hash/equality آن پایدار بماند.

## راهنمای بازگویی از حافظه

بدون نگاه به متن، ایده، پیش‌شرط، invariant، یک ردگیری واقعی، پیچیدگی، edge case و یک کاربرد را در چند دقیقه روی کاغذ توضیح بده. اگر فقط pseudocode را حفظی می‌نویسی اما دلیل درستی یا محدودیت‌ها را نمی‌دانی، یک بار دیگر بخش‌های invariant و خطاها را مرور کن.
