# درخت پاره‌خطی (Segment Tree)

> نسخهٔ انگلیسی: [English version](../../../../en/data-structures-and-algorithms/06-advanced-data-structures/segment-tree/README.md)

> مسیر: [فصل ۶ — ساختمان‌های دادهٔ پیشرفته](../README.md) · پیش‌نیاز پیشنهادی: فصل ۱ و مبانی برنامه‌نویسی

## پیش‌نیازها و نقشهٔ ذهنی

درخت بازگشتی، آرایه و associative operation. ابتدا مفهوم را به‌عنوان یک قرارداد ببین، سپس نمایش حافظه و عملیات را دنبال کن. هدف حفظ‌کردن نام نیست؛ باید بتوانی برای یک ورودی کوچک، state را بعد از هر گام بنویسی.

## ایده از پایه

Segment tree بازه را به قطعه‌های نیم‌شونده می‌شکند و aggregate هر قطعه را ذخیره می‌کند. range query فقط nodeهای کاملاً پوشانندهٔ بخش درخواست‌شده را ترکیب می‌کند؛ update نقطه‌ای فقط مسیر برگ تا ریشه را اصلاح می‌کند.

## مدل، قرارداد و ناوردا

عملیات ترکیب باید associative باشد (مثل جمع، min، max، gcd، ترکیب تابع). identity برای بازهٔ خالی لازم است: جمع 0، min معمولاً +∞. اندازهٔ درخت معمولاً نزدیک 4n در نمایش recursive یا 2×power-of-two در نمایش iterative است.

ناوردا (invariant) جمله‌ای است که در تمام مراحل الگوریتم باید درست بماند. نوشتن آن پیش از کدنویسی، هم به اثبات درستی کمک می‌کند و هم خطاهای مرزی را آشکار می‌سازد.

## الگوریتم یا عملیات گام‌به‌گام

query(node,L,R,ql,qr): اگر بیرون است identity؛ اگر کاملاً داخل است tree[node]؛ وگرنه query دو نیمه و combine. update: در برگ مقدار را عوض کن؛ هنگام بازگشت combine فرزندها. lazy propagation برای range update، تغییر را در node ذخیره و در صورت نیاز به فرزندان push می‌کند.

در پیاده‌سازی واقعی، قرارداد ورودی/خروجی را دقیق تعریف کن: رفتار ورودی تهی، مقدار تکراری، عنصر پیدا‌نشده و ظرفیت تمام‌شده باید روشن باشد.

## اجرای حل‌شده با ردگیری

A=[2,1,5,3] و query sum [1,3) یعنی 1+5=6. قطعه‌های node شامل [1,2) و [2,3) مستقیم جواب می‌دهند و جمع می‌شوند؛ range [0,4) از ریشه یک‌جا برگردانده می‌شود.

برای تمرین، جدولی با ستون‌های «گام»، «اندیس/اشاره‌گر»، «بخش فعال»، «تغییر state» و «دلیل» بساز. این روش به‌خصوص برای الگوریتم‌های درجا و تقسیم‌و‌غلبه جلوی پرش ذهنی را می‌گیرد.

## چرا درست است؟

مقدار هر node برابر aggregate بازهٔ خودش است. update مسیرهای شامل index را اصلاح می‌کند، پس invariant بالای مسیر دوباره برقرار می‌شود. query قطعه‌های disjointی را انتخاب می‌کند که اجتماعشان دقیقاً بازهٔ درخواست است.

اثبات معمولاً سه بخش دارد: (۱) آغاز—ناوردا پیش از نخستین گام درست است؛ (۲) نگهداری—هر گام آن را حفظ می‌کند؛ (۳) پایان—شرط توقف همراه invariant جواب موردنیاز را نتیجه می‌دهد. اگر یکی از این سه بخش نامشخص است، هنوز درک الگوریتم کامل نشده است.

## تحلیل زمان و حافظه

ساخت O(n)، نقطه‌ای update O(log n)، range query O(log n) برای عملیات استاندارد و حافظه O(n). با lazy propagation، range update/query معمولاً O(log n) اما correctness وابسته به push/pull درست است.

در Big-O ورودی را تعریف کن (مثلاً n تعداد عناصر)، نوع حالت را نام ببر (بهترین/میانگین/بدترین)، و فضای کمکی را از حافظهٔ خود ورودی جدا کن. مرتبهٔ رشد زمان واقعی بر حسب ثانیه نیست؛ cache، تخصیص حافظه و ثابت‌های پیاده‌سازی هم اثر دارند.

## کاربرد واقعی و انتخاب مناسب

range sum/min/max، frequency/coverage، maximum subarray، و تغییرهای پویا در دادهٔ ترتیبی. segment tree نسبت به Fenwick انعطاف‌پذیرتر است، اما کد و حافظه بیشتری دارد.

پیش از انتخاب بپرس: چه عملیاتی پرتکرارند؟ آیا ترتیب مهم است؟ دادهٔ ورودی چه اندازه است؟ آیا محدودیت حافظه، latency بدترین‌حالت یا thread-safety داریم؟ ساختار خوب برای workload نامناسب می‌تواند انتخاب بدی باشد.

## خطاهای رایج و edge caseها

شرط overlapهای disjoint/full/partial را دقیق کن. بازهٔ inclusive/half-open را یکدست نگه دار. combine باید associative باشد. lazy tag باید هنگام push در طول بازه درست اعمال شود؛ فقط یک مثال ساده برای اثبات کافی نیست.

حالت‌های مرزی را جداگانه بررسی کن: ورودی خالی، یک عضو، همهٔ اعضا برابر، هدف غایب، حداقل/حداکثر مقدار و اندازهٔ بزرگ. سرریز عدد صحیح در محاسبهٔ اندیس/ظرفیت نیز بسته به زبان مهم است.

## تمرین‌های مرحله‌ای

۱) tree جمع ۸ عضو را رسم کن. ۲) query [2,6) و update نقطه‌ای را ردگیری کن. ۳) برای range-add و range-sum، معنی lazy tag و طول قطعه را تعریف کن.

برای هر تمرین، اول پاسخ ساده و درست بنویس، بعد پیچیدگی را حساب کن، سپس edge case اضافه کن. تمرین را با دست‌کم یک ورودی کوچک ردگیری کن و خروجی را با انتظار مستقل مقایسه کن.

## آزمون جامع با پاسخ تشریحی

ابتدا پاسخ‌ها را نخوان؛ جواب را با استدلال بنویس، سپس توضیح را مقایسه کن.

1. **پرسش:** کدام خاصیت combine لازم است؟
   **پاسخ تشریحی:** Associativity.
2. **پرسش:** ساخت زمان؟
   **پاسخ تشریحی:** O(n).
3. **پرسش:** query/update معمول؟
   **پاسخ تشریحی:** O(log n).
4. **پرسش:** lazy propagation چه می‌کند؟
   **پاسخ تشریحی:** به‌تعویق‌انداختن range update روی فرزندان تا هنگام نیاز.
5. **پرسش:** Fenwick یا segment tree؟
   **پاسخ تشریحی:** Fenwick برای prefix/range sum ساده؛ segment tree برای aggregateها و عملیات بازه‌ای متنوع.
