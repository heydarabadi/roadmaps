## هدف یادگیری

پس از این درس بتوانی مفهوم را با زبان خودت تعریف کنی، در مثال دامنه‌ای تشخیصش بدهی و هزینهٔ انتخاب یا کنارگذاشتنش را توضیح بدهی.

## آموزش

use case یک هدف قابل مشاهدهٔ کاربر یا سامانه را هماهنگ می‌کند؛ orchestration و مرز تراکنش را نگه می‌دارد اما قواعد دامنه را تصاحب نمی‌کند.

## مثال کاربردی

`PlaceOrder` اعتبار سبد، رزرو موجودی و درخواست پرداخت را با سیاست‌های خطا هماهنگ می‌کند.

این مثال آموزشی است و ادعای پیاده‌سازی دقیق یک شرکت مشخص را ندارد. نمونهٔ صنعتی مستند و زمینهٔ آن در فصل «الگوهای نرم‌افزار سازمانی» پیوند داده شده است.

## تصمیم معماری و محدودیت‌ها

- **چه زمانی به‌کار ببر:** وقتی مسئلهٔ اصلی‌ای که مفهوم حل می‌کند در سامانه واقعاً دیده می‌شود و قراردادش می‌تواند در کد یا آزمون بررسی شود.
- **چه زمانی ساده‌تر بماند:** تعداد زیاد کلاس use case ممکن است تکرار boilerplate بسازد.
- **بازبینی:** use case را به کنترلر دیتابیس یا محل همهٔ قواعد کسب‌وکار تبدیل نکن.

## کوییز با پاسخ تشریحی

پاسخ را بپوشان و ابتدا با کلمات خودت توضیح بده؛ پاسخ پیشنهادی معیار سنجش است، نه تنها عبارت درست.

1. **این مفهوم دقیقاً چه مسئله‌ای را حل می‌کند؟**
   - پاسخ پیشنهادی: use case یک هدف قابل مشاهدهٔ کاربر یا سامانه را هماهنگ می‌کند؛ orchestration و مرز تراکنش را نگه می‌دارد اما قواعد دامنه را تصاحب نمی‌کند.
2. **در مثال زیر چه تصمیمی می‌گیری و چرا؟**
   - پاسخ پیشنهادی: `PlaceOrder` اعتبار سبد، رزرو موجودی و درخواست پرداخت را با سیاست‌های خطا هماهنگ می‌کند.
3. **چه زمانی انتخاب آن نامناسب یا پرهزینه است؟**
   - پاسخ پیشنهادی: تعداد زیاد کلاس use case ممکن است تکرار boilerplate بسازد.
4. **کدام خطای رایج را قبل از ادغام کد بررسی می‌کنی؟**
   - پاسخ پیشنهادی: use case را به کنترلر دیتابیس یا محل همهٔ قواعد کسب‌وکار تبدیل نکن.

## آموزش تکمیلی مستقل

### ۳. Use Case

Use case یک هدف قابل مشاهدهٔ کاربر/سامانه را هماهنگ می‌کند: ثبت سفارش، لغو رزرو، بازپرداخت. ورودی و خروجی application را تعریف می‌کند و transaction boundary، authorization check یا workflow را مدیریت می‌کند. قواعد domain باید به object/policy دامنه‌ای واگذار شوند تا use case به script نامنسجم تبدیل نشود.

یک use case می‌تواند مراحل اعتبارسنجی، بارگذاری aggregate، فراخوانی behavior، ذخیره و انتشار پیام را هماهنگ کند. وابستگی شبکه و دیتابیس را مستقیم در آن پنهان نکن؛ failure و retry اثر دارند.

## نمونهٔ کد مرحله‌ای

Use case یک هدف کاربر/سیستم را از ورودی تا خروجی هماهنگ می‌کند؛ اعتبارسنجی ورودی، فراخوانی policyها، transaction boundary و outcome را آشکار می‌سازد. آن را از controller و جزئیات framework جدا نگه دار.
**دام رایج:** use case را به service عمومی با عملیات نامرتبط تبدیل نکن.
**تمرین با پاسخ:** برای ثبت سفارش، ورودی لازم، مجوز، قواعد، persistence، event و نتیجهٔ خطا را به‌ترتیب مشخص کن؛ هر کدام را به همکار مناسب بسپار.

در این طرح C#، نوع‌های پشتیبان کوتاه شده‌اند تا مرز الگو روشن بماند.

~~~csharp
public sealed class PlaceOrder(
    ICustomerAccess customers,
    IOrderRepository orders,
    IUnitOfWork unitOfWork)
{
    public async Task<PlaceOrderResult> Execute(PlaceOrderInput input, CancellationToken ct)
    {
        // authorize, create valid order, persist, commit, return outcome
    }
}
~~~
