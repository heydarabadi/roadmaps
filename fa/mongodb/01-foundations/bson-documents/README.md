> **هدف یادگیری:** تفاوت JSON و BSON و محدودیت‌های سند را بشناسید.

## جایگاه در مسیر
این درس بخشی از فصل مربوط است. مثال‌ها برای محیط آزمایشی‌اند؛ نسخه و قابلیت deployment خود را در مستندات رسمی بررسی کنید.

### فهرست نوع‌های BSON که باید بشناسید

| نوع | کاربرد و احتیاط |
|---|---|
| String | متن و identifierهای متنی؛ قالب و طول را کنترل کنید. |
| Boolean | flagهای درست/نادرست. |
| Int32 و Int64/Long | عدد صحیح؛ محدودهٔ نوع و driver را در نظر بگیرید. |
| Double | محاسبهٔ اعشاری تقریبی؛ برای مبلغ دقیق مناسب نیست. |
| Decimal128 | مقدارهای اعشاری دقیق‌تر مثل پول. |
| Date | زمان واقعی به صورت UTC millisecond؛ برای تاریخ اپ مناسب است. |
| Timestamp | نوع داخلی/فنی با semantics متفاوت از Date؛ زمان کاربر را با Date ذخیره کنید. |
| ObjectId | identifier رایج شامل زمان تقریبی؛ کلید کسب‌وکاری یا ساعت دقیق نیست. |
| Binary | دادهٔ باینری؛ اندازه و encoding را مشخص کنید. |
| Array و Object | فهرست و ساختار توکار؛ رشد آرایه را محدود کنید. |
| Null و field غایب | دو حالت متفاوت برای query و validation؛ سیاست مشخص داشته باشید. |
| Regular Expression | الگویی برای متن؛ type مربوط به ذخیرهٔ regex است و با عملگر queryِ `$regex` یکی نیست. |
| JavaScript | نوع قدیمی برای ذخیرهٔ کد؛ برای منطق برنامه به کار نبرید. |
| MinKey و MaxKey | sentinelهای حد مقایسه؛ به ندرت field عادی برنامه هستند. |
| Undefined، Symbol، DBPointer و JavaScript with scope | نوع‌های قدیمی/deprecated؛ در schema جدید استفاده نکنید. |

این جدول همهٔ نوع‌های BSON را در سطح آشنایی معرفی می‌کند. برای کاربردهای معمول، روی String، Boolean، Object، Array، Binary/UUID، ObjectId، Date، Null، Int32، Int64، Double و Decimal128 تمرکز کنید. JavaScript، JavaScript with scope، DBPointer، Undefined و Symbol میراثی‌اند و نباید برای طراحی جدید انتخاب شوند. نوع Regex در BSON وجود دارد، اما معمولاً برنامه فقط الگوی query را با `$regex` می‌فرستد؛ نیازی نیست رشتهٔ regex را به‌عنوان دادهٔ دامنه ذخیره کنید.

### Count، Null و missing را جدا بفهمید

در query، `{ field: null }` سندهایی را match می‌کند که مقدار field آن‌ها null است یا field اصلاً وجود ندارد. برای تفکیک، `{ field: { $exists: true, $eq: null } }` را برای null موجود و `{ field: { $exists: false } }` را برای نبودن field به کار ببرید. اگر نوع باید Date باشد از `$type` یا validation استفاده کنید. دادهٔ مبهم معمولاً نشان‌دهندهٔ writerهای ناسازگار است.


## آموزش
JSON قالب متنی تبادل داده است؛ BSON نمایش دودویی مورد استفادهٔ MongoDB و دارای نوع‌های افزوده مانند ObjectId، Date، Decimal128، Binary، Timestamp و integerهای مشخص است. برای پول، floating point می‌تواند گردکردن ایجاد کند؛ نوع دقیق و قاعدهٔ واحد پول را انتخاب کنید.

فیلد _id در collection یکتا است و در صورت تعیین‌نشدن معمولاً ObjectId ساخته می‌شود. ObjectId شناسهٔ کاربردی است، نه ساعت دقیق یا کلید بیزنسی. حداکثر اندازهٔ سند 16 MiB است. تاریخ را Date نگه دارید، نه رشته. آرایهٔ نامحدود و سند غول‌آسا در نهایت به محدودیت و هزینهٔ query می‌رسند.

## تدریس کامل از صفر: JSON، BSON و سند

### JSON و BSON چه فرقی دارند؟

JSON قالبی متنی و قابل‌خواندن برای تبادل داده است؛ BSON نمایش دودویی‌ای است که MongoDB برای سندها به کار می‌برد. BSON نوع‌های صریح‌تری دارد، از جمله Date، ObjectId، Binary، Decimal128، Timestamp و عددهای صحیح با پهنای مشخص. وقتی سند از شبکه می‌گذرد، driver مقدارهای زبان را به BSON سازگار تبدیل می‌کند و در پاسخ آن‌ها را دوباره به نوع‌های زبان نگاشت می‌کند.

### انتخاب نوع مهم است

- String برای نام، کد و متن کوتاه.
- Boolean برای مقدار درست/نادرست.
- Date برای لحظهٔ زمانی؛ زمان را معمولاً UTC نگه دارید.
- Int32/Int64 برای شمارش‌های صحیح در محدودهٔ تعریف‌شده.
- Double برای اندازه‌گیری تقریبی که خطای اعشاری‌اش پذیرفتنی است.
- Decimal128 برای مبالغی که دقت اعشاری مهم دارند.
- Array برای تعداد محدودی عضو مرتبط.
- Object برای ساختار توکار مثل address.
- ObjectId برای شناسهٔ خودکار رایج MongoDB؛ شناسهٔ دامنه مثل invoiceNumber را همچنان جدا نگه دارید.
- Binary برای دادهٔ باینری؛ فایل‌های بزرگ را بی‌برنامه داخل سند قرار ندهید.

### مثال نوع‌گذاری و پرس‌وجو

~~~javascript
use learning

db.measurements.insertOne({
  sensorId: "S-17",
  observedAt: ISODate("2026-11-10T08:00:00Z"),
  temperature: 22.75,
  price: NumberDecimal("12.40"),
  labels: ["pump", "north"],
  location: { building: "A", floor: 2 },
  active: true
})

db.measurements.find({
  observedAt: { $gte: ISODate("2026-11-01T00:00:00Z") },
  "location.building": "A"
})
~~~

اگر observedAt به شکل رشته ذخیره می‌شد، مقایسه و sort به قالب رشته وابسته می‌شد. اگر price از چند نوع مختلف ساخته شود، جمع‌زدن ممکن است تبدیل یا خطای ناخواسته داشته باشد.

### _id و ObjectId

هر سند collection باید _id یکتا داشته باشد. اگر ننویسید، driver معمولاً ObjectId ایجاد می‌کند. ObjectId برای شناسایی سند و lookup مناسب است؛ به عنوان شمارهٔ سفارش قابل‌نمایش به مشتری یا ساعت دقیق رخداد از آن استفاده نکنید. شناسهٔ کسب‌وکاری را با constraint یکتا یا index مناسب مدل کنید.

ObjectId دوازده بایت دارد: چهار بایت زمان با دقت ثانیه، پنج بایت تصادفی و سه بایت شمارنده. به همین دلیل تقریباً بر اساس زمان مرتب می‌شود، اما timestamp دقیق و ترتیب تضمین‌شدهٔ دو ObjectId در یک ثانیه نیست؛ ساعت clientها هم ممکن است متفاوت باشد.

### سند و محدودیت اندازه

سند شامل fieldها، سندهای توکار و آرایه است. حد سند 16 MiB است. این محدودیت همراه با concurrency، index و query باید در مدل‌سازی دیده شود. آرایهٔ کامنت‌های بی‌انتها را در user embed نکنید؛ collection جدا و query با userId بسازید. برای فایل بزرگ راهکار ذخیرهٔ شیء/stream را بررسی کنید؛ GridFS فقط وقتی نیازهایش با کار سازگار است انتخاب شود.

### شناسهٔ Binary، UUID و مقدارهای ویژه

Binary یک رشته از byteها با subtype است. UUID زیرنوع مشخصی از Binary است؛ driver زبان شما باید codec و representation سازگار داشته باشد تا UUID واحدی به byteهای متفاوت تبدیل نشود. MinKey و MaxKey برای مقایسه و مرزهای داخلی مفیدند، نه جایگزین مقدار عادی مثل `null` یا عدد. Null مقدار صریح است؛ field غایب اطلاعات متفاوتی می‌دهد. از ابتدای طراحی تصمیم بگیرید که «نامعلوم»، «هنوز تنظیم نشده» و «پاک‌شده» را چگونه بازنمایی می‌کنید.

### تمرین نوع داده

یک فاکتور را مدل کنید:
- شناسهٔ داخلی و شمارهٔ قابل‌نمایش جدا.
- تاریخ صدور به صورت Date.
- تعداد کالا به صورت integer.
- مبلغ به صورت Decimal128 و همراه currency.
- اقلام فاکتور با محدودیت رشد روشن.
- وضعیت با رشتهٔ کنترل‌شده یا enum در برنامه.

پیش از ساخت index یا aggregation مطمئن شوید writerها نوع یکسان ذخیره می‌کنند. schema validation می‌تواند جلوی بخشی از خطاها را بگیرد.

## مثال
~~~javascript
db.measurements.insertOne({
  sensorId: "S-17",
  at: ISODate("2026-11-10T08:00:00Z"),
  value: NumberDecimal("12.345"),
  tags: ["pump", "line-2"],
  location: { building: "A", floor: 2 }
})
~~~

## تجربهٔ واقعی یا سناریوی کاربردی
در سامانهٔ مالی، ذخیرهٔ مبلغ به صورت Double می‌تواند خطای دقت ایجاد کند. از Decimal128 و قواعد گردکردن دامنه استفاده کنید؛ تاریخچهٔ بدون سقف را هم جداگانه طراحی کنید.

## خطاهای رایج
- ذخیرهٔ تاریخ به صورت رشته.
- استفاده از Double برای مبلغ دقیق.
- آرایهٔ بی‌انتها داخل یک سند.
- فرض دقت زمانی قطعی از ObjectId.

## تمرین
1. برای سند customer و order نوع BSON هر فیلد را انتخاب کنید.
2. توضیح دهید چرا رویدادهای نامحدود را نباید در سند user جمع کرد.

## آزمون و پاسخ
1. **پرسش:** BSON چه تفاوتی با JSON دارد؟
   **پاسخ:** BSON دودویی است و نوع‌های بیشتری دارد.
2. **پرسش:** Decimal128 کجا مفید است؟
   **پاسخ:** برای اعداد اعشاری دقیق، مثل مبلغ.
3. **پرسش:** حد اندازهٔ سند چیست؟
   **پاسخ:** 16 MiB.
4. **پرسش:** چرا باید از ذخیرهٔ تاریخ به‌صورت رشته پرهیز کرد؟
   **پاسخ:** رشته یک مقدار متنی است؛ queryهای زمانی و محاسبات تاریخ به تبدیل و قالب سازگار وابسته می‌شوند. BSON Date را ذخیره کنید و timezone را در قرارداد برنامه روشن کنید.
5. **مسئلهٔ کاربردی:** برای سند customer و order نوع BSON هر فیلد را انتخاب کنید.
   **پاسخ نمونه:** برای پول Decimal128، برای timestamp Date، برای identifier ObjectId یا کلید دامنه، و برای تاریخچهٔ نامحدود collection جدا انتخاب کنید؛ اندازهٔ سند باید زیر 16 MiB بماند.

## آزمون تکمیلی — مفاهیم و تصمیم‌گیری

6. **پرسش:** چرا تاریخ را Date ذخیره می‌کنیم؟
   **پاسخ:** برای مقایسه و sort زمانی با نوع معتبر، نه ترتیب متنی.
7. **پرسش:** چرا مبلغ را Decimal128 می‌گذاریم؟
   **پاسخ:** برای جلوگیری از خطاهای اعشاری Double در مقدارهای دقیق.
8. **پرسش:** آیا ObjectId شمارهٔ سفارش است؟
   **پاسخ:** نه الزاماً؛ شناسهٔ دامنه را جدا تعریف کنید.
9. **پرسش:** حد اندازهٔ سند چقدر است؟
   **پاسخ:** 16 MiB.
10. **پرسش:** آرایهٔ نامحدود چه خطری دارد؟
   **پاسخ:** سند بزرگ و پرهزینه می‌شود و ممکن است از حد مجاز عبور کند.
