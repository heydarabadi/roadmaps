## پیش‌نیازها و نقشهٔ ذهنی

آرایه یا فهرست پیوندی و توابع. ابتدا مفهوم را به‌عنوان یک قرارداد ببین، سپس نمایش حافظه و عملیات را دنبال کن. هدف حفظ‌کردن نام نیست؛ باید بتوانی برای یک ورودی کوچک، state را بعد از هر گام بنویسی.

## ایده از پایه

پشته دنباله‌ای با سیاست LIFO است: آخرین عنصری که وارد می‌شود، اولین عنصری است که خارج می‌شود. فقط یک سر به نام top برای افزودن و برداشتن استفاده می‌شود؛ این محدودیت رفتار را قابل پیش‌بینی می‌کند.

## مدل، قرارداد و ناوردا

عملیات اصلی push(x)، pop()، peek()/top() و isEmpty() هستند. pop روی پشتهٔ خالی باید خطای کنترل‌شده بدهد یا نتیجهٔ اختیاری برگرداند. پیاده‌سازی آرایه‌ای از انتهای آرایه استفاده می‌کند؛ پیاده‌سازی پیوندی از head. قرارداد پشته مستقل از این پیاده‌سازی است.

ناوردا (invariant) جمله‌ای است که در تمام مراحل الگوریتم باید درست بماند. نوشتن آن پیش از کدنویسی، هم به اثبات درستی کمک می‌کند و هم خطاهای مرزی را آشکار می‌سازد.

## الگوریتم یا عملیات گام‌به‌گام

push(x): اگر ظرفیت محدود پر است، overflow را مدیریت کن؛ وگرنه top را یک واحد بالا ببر و x را بنویس. pop(): اگر خالی است underflow؛ وگرنه مقدار top را ذخیره کن، top را کم کن و مقدار ذخیره‌شده را بده. در نسخهٔ پویا resize سیاست ظرفیتی دارد.

در پیاده‌سازی واقعی، قرارداد ورودی/خروجی را دقیق تعریف کن: رفتار ورودی تهی، مقدار تکراری، عنصر پیدا‌نشده و ظرفیت تمام‌شده باید روشن باشد.

## اجرای حل‌شده با ردگیری

عبارت `(2+3)×4` را ارزیابی کن. عددها و نتایج را push می‌کنیم؛ هنگام دیدن `+` دو مقدار بالای پشته را pop می‌کنیم: 2 و 3؛ 5 را push می‌کنیم؛ بعد 4 و 5 برای ضرب مصرف و 20 push می‌شود. برای پرانتزها نیز موقع دیدن `(` علامت را نگه می‌داریم و با `)` تا آن علامت تخلیه می‌کنیم.

برای تمرین، جدولی با ستون‌های «گام»، «اندیس/اشاره‌گر»، «بخش فعال»، «تغییر state» و «دلیل» بساز. این روش به‌خصوص برای الگوریتم‌های درجا و تقسیم‌و‌غلبه جلوی پرش ذهنی را می‌گیرد.

## چرا درست است؟

top همیشه به آخرین عضو زنده اشاره می‌کند. پس از k بار push و pop، ترتیب خروج معکوس ترتیب ورود عناصر باقی‌مانده است. عمق پشته در الگوریتم بازگشتی با بیشترین تعداد فراخوانی‌های هم‌زمان برابر است.

اثبات معمولاً سه بخش دارد: (۱) آغاز—ناوردا پیش از نخستین گام درست است؛ (۲) نگهداری—هر گام آن را حفظ می‌کند؛ (۳) پایان—شرط توقف همراه invariant جواب موردنیاز را نتیجه می‌دهد. اگر یکی از این سه بخش نامشخص است، هنوز درک الگوریتم کامل نشده است.

## تحلیل زمان و حافظه

push و pop و peek در پیاده‌سازی معمول O(1) سرشکن‌اند؛ حافظه O(n). رشد آرایه می‌تواند push منفرد را O(n) کند. بازگشت نیز از call stack سیستم استفاده می‌کند و عمق خیلی زیاد ممکن است stack overflow ایجاد کند.

در Big-O ورودی را تعریف کن (مثلاً n تعداد عناصر)، نوع حالت را نام ببر (بهترین/میانگین/بدترین)، و فضای کمکی را از حافظهٔ خود ورودی جدا کن. مرتبهٔ رشد زمان واقعی بر حسب ثانیه نیست؛ cache، تخصیص حافظه و ثابت‌های پیاده‌سازی هم اثر دارند.

## کاربرد واقعی و انتخاب مناسب

undo/redo، تاریخچهٔ مرورگر، پیمایش عمقی، ارزیابی عبارت، بررسی جفت‌بودن پرانتزها و مدیریت فراخوانی توابع همگی رفتار stack دارند. برای undo چندمرحله‌ای معمولاً دو stack برای undo و redo نگه داشته می‌شود.

پیش از انتخاب بپرس: چه عملیاتی پرتکرارند؟ آیا ترتیب مهم است؟ دادهٔ ورودی چه اندازه است؟ آیا محدودیت حافظه، latency بدترین‌حالت یا thread-safety داریم؟ ساختار خوب برای workload نامناسب می‌تواند انتخاب بدی باشد.

## خطاهای رایج و edge caseها

ترتیب عملوندها در عملگرهای غیربدیل مثل تفریق مهم است: operand راست زودتر pop می‌شود. خالی بودن پیش از pop/peek را کنترل کن. recursion عمق پنهان دارد؛ حلقهٔ تکراری گاهی حافظهٔ قابل‌کنترل‌تری می‌دهد.

حالت‌های مرزی را جداگانه بررسی کن: ورودی خالی، یک عضو، همهٔ اعضا برابر، هدف غایب، حداقل/حداکثر مقدار و اندازهٔ بزرگ. سرریز عدد صحیح در محاسبهٔ اندیس/ظرفیت نیز بسته به زبان مهم است.

## تمرین‌های مرحله‌ای

۱) با stack پرانتزهای `([{}])` و `([)]` را بررسی کن. ۲) postfix `5 2 3 * +` را گام‌به‌گام ارزیابی کن. ۳) DFS بازگشتی را به DFS صریح با stack تبدیل کن و تفاوت ترتیب همسایه‌ها را ببین.

برای هر تمرین، اول پاسخ ساده و درست بنویس، بعد پیچیدگی را حساب کن، سپس edge case اضافه کن. تمرین را با دست‌کم یک ورودی کوچک ردگیری کن و خروجی را با انتظار مستقل مقایسه کن.

## آزمون جامع با پاسخ تشریحی

ابتدا پاسخ‌ها را نخوان؛ جواب را با استدلال بنویس، سپس توضیح را مقایسه کن.

1. **پرسش:** معنای LIFO چیست؟
   **پاسخ تشریحی:** آخرین عنصر واردشده، اولین عنصر خارج‌شده است.
2. **پرسش:** pop روی پشتهٔ خالی چه مشکلی دارد؟
   **پاسخ تشریحی:** underflow؛ API باید خطای امن یا مقدار اختیاری بدهد.
3. **پرسش:** چرا ارزیابی postfix stack می‌خواهد؟
   **پاسخ تشریحی:** عملوندهای آماده را تا رسیدن عملگر نگه می‌دارد و وابستگی به پرانتز را کم می‌کند.
4. **پرسش:** پیچیدگی push چیست؟
   **پاسخ تشریحی:** در پیاده‌سازی معمول O(1) سرشکن؛ رشد آرایه می‌تواند یک عملیات O(n) شود.
5. **پرسش:** یک ریسک recursion عمیق چیست؟
   **پاسخ تشریحی:** مصرف call stack و stack overflow.

## راهنمای بازگویی از حافظه
