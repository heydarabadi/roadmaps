# یکنواختی — Be consistent

## هدف درس

بتوانی مسئلهٔ این اصل را تشخیص بدهی، آن را در کد به‌کار ببری، trade-off را توضیح بدهی و در آزمون از نتیجه دفاع کنی.

## آموزش دقیق

کد یک تیم زبان مشترک است. وقتی خطاها، زمان‌ها، نام‌ها و ساختارهای مشابه در هر بخش شکل متفاوتی دارند، خواننده باید در هر فایل قرارداد تازه‌ای یاد بگیرد. یکدستی این بار ذهنی را کم می‌کند و بازبینی را به رفتار و طراحی معطوف می‌سازد.

۱. تفاوت‌های کم‌ارزش را مشخص کن: قالب‌بندی، ترتیب import، سبک نام‌گذاری، واحدها و شکل خطای قابل انتظار.
۲. آن‌ها را در قرارداد کوتاه و قابل جست‌وجو ثبت کن.
۳. formatter و linter را برای قواعد مکانیکی اجرا کن؛ قواعد معنایی به بازبینی و آزمون نیاز دارند.
۴. یکدستی را هنگام توسعهٔ جدید رعایت کن و تغییر کد قدیمی را مرحله‌ای انجام بده؛ تغییر سراسری قالب را با تغییر منطق مخلوط نکن.

## سناریوی عملی

فرض کن یک endpoint برای خطا null برمی‌گرداند، دومی exception پرتاب می‌کند و سومی شیء Result دارد. مصرف‌کننده نمی‌داند کدام قرارداد معتبر است. برای شکست مورد انتظار یک شکل روشن انتخاب کن و exception را برای نقص غیرمنتظره نگه دار. در مقابل، خطای «پرداخت رد شد» و «فایل تنظیمات پیدا نشد» ممکن است هر دو envelope مشترک داشته باشند، اما کد و اقدام اصلاحی آن‌ها باید جدا بماند.

## مرز و هزینه

یکنواختی کور تفاوت واقعی حوزه‌ها را پنهان می‌کند؛ قرارداد نادرست نیز خطا را در کل مخزن تکثیر می‌کند. پیش از قاعده‌گذاری، آن را روی چند مثال واقعی امتحان کن. ابزار یک نسخهٔ مشترک لازم دارد، وگرنه formatterهای متفاوت فایل‌ها را پیوسته جابه‌جا می‌کنند.

## تمرین

سه ماژول را مقایسه کن. برای تاریخ، خطای مورد انتظار و نام‌گذاری API قرارداد بنویس و مشخص کن کدام را ابزار می‌تواند اعمال کند.

## نمونهٔ کد/قرارداد

~~~python
@dataclass(frozen=True)
class Result:
    value: object | None = None
    error_code: str | None = None

    @property
    def ok(self):
        return self.error_code is None
~~~

## تمرین سنجش

نمونه‌ای از کد خودت یا یک پروژهٔ آموزشی انتخاب کن. مفهوم را در یک تغییر کوچک اعمال کن، آزمونی برای رفتار مرزی اضافه کن و با یک جمله ثبت کن که چه چیزی خواناتر یا امن‌تر شد.

## کوییز با پاسخ تشریحی

پیش از دیدن پاسخ، دلیل خودت را بنویس. پاسخ پیشنهادی باید با زمینه هماهنگ باشد؛ اگر گزینهٔ دیگری داری، trade-off آن را هم بیان کن.

1. **چه چیزی باید یکدست شود؟**
   - پاسخ تشریحی: قراردادهای مشابه و کم‌ارزش از نظر دامنه؛ قالب، واحدها و شکل خطا، نه تفاوت معنایی واقعی.
2. **چرا ابزار خودکار ارزش دارد؟**
   - پاسخ تشریحی: قواعد مکانیکی را بی‌وقفه اجرا می‌کند و از بحث تکراری در review جلوگیری می‌کند.
3. **چطور تغییر سراسری را امن می‌کنی؟**
   - پاسخ تشریحی: آن را از تغییر رفتاری جدا می‌کنم، diff محدود می‌سازم و مرحله‌ای پیش می‌روم.
