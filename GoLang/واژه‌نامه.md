# واژه‌نامهٔ Go، انگلیسی به فارسی

<div dir="rtl">

این واژه‌نامه در کنار درس‌هاست، نه جایگزین تعریف هر مفهوم در متن. در اصطلاحات فنی، واژهٔ انگلیسی را هم نگه دار؛ اسم package، command و type را ترجمه نکن.

## زبان و داده

| اصطلاح | معنی و توضیح |
|---|---|
| Go / Golang | نام زبان Go؛ «Golang» بیشتر برای جست‌وجو به کار می‌رود. |
| Source code | کد منبعی که برنامه‌نویس می‌نویسد. |
| Compiler | کامپایلر؛ source را تحلیل و به برنامهٔ قابل‌اجرا یا شکل میانی تبدیل می‌کند. |
| Type | نوع؛ مجموعهٔ مقادیر مجاز و عملیات تعریف‌شده برای آن‌ها. |
| Zero value | مقدار صفر پیش‌فرض هر نوع؛ در Go مقدار اولیهٔ متغیر بدون initializer. |
| Variable | متغیر؛ جایگاهی با نام و نوع برای نگه‌داری مقدار. |
| Constant | ثابت؛ مقدار compile-time تغییرناپذیر که با <code>const</code> تعریف می‌شود. |
| Scope | محدودهٔ دید یک نام در بخشی از برنامه. |
| Shadowing | سایه‌اندازی؛ تعریف نامی هم‌نام در scope داخلی که نام بیرونی را موقتاً پنهان می‌کند. |
| Type conversion | تبدیل صریح مقدار از یک نوع به نوع دیگر؛ به‌طور معمول Go تبدیل ضمنی عددی انجام نمی‌دهد. |
| Signed integer | عدد صحیح علامت‌دار، با مقادیر منفی، صفر و مثبت. |
| Unsigned integer | عدد صحیح بدون علامت؛ مقادیر منفی ندارد. |
| Floating-point | عدد ممیز شناور تقریبی؛ equality مستقیم برای بعضی محاسبات مناسب نیست. |
| Complex number | عدد مختلط شامل بخش حقیقی و موهومی. |
| Rune | نام Go برای مقدار Unicode code point از نوع <code>int32</code>. |
| Byte | alias نوع <code>uint8</code>؛ یک بایت داده، نه لزوماً یک نویسهٔ کامل. |
| UTF-8 | روش کدگذاری Unicode با طول یک تا چهار byte برای هر code point. |
| Grapheme cluster | چیزی که کاربر معمولاً یک نویسه می‌بیند؛ ممکن است چند rune داشته باشد. |
| Array | آرایه با طول ثابت که طول آن بخشی از type است و value مستقل دارد. |
| Slice | پنجره‌ای پویا روی یک array پشتیبان، با طول و ظرفیت. |
| Backing array | آرایهٔ پشتیبان slice؛ چند slice ممکن است دادهٔ مشترک داشته باشند. |
| Length | طول؛ تعداد عضوهای قابل‌دسترسی فعلی slice یا string. |
| Capacity | ظرفیت slice از عنصر اول تا انتهای array پشتیبان. |
| Map | نگاشت کلید به مقدار؛ ترتیب iteration آن تضمین نشده است. |
| Comma-ok idiom | دریافت هم‌زمان value و bool برای تشخیص وجود کلید، assertion یا receive. |
| Struct | ترکیب fieldهای نام‌دار با type مشخص. |
| Struct tag | metadata رشته‌ای کنار field که packageهایی مثل JSON تفسیر می‌کنند. |
| Embedding | قرار دادن type در struct/interface دیگر برای composition و promotion برخی memberها. |
| Promotion | دسترسی کوتاه‌تر به field یا method از مسیر type embedded. |
| Composite literal | ساخت مقدار array/slice/map/struct با syntax literal. |

## تابع، حافظه و abstraction

| اصطلاح | معنی و توضیح |
|---|---|
| Function | تابع مستقل با ورودی/خروجی مشخص. |
| Method | تابعی با receiver که به یک type متصل است. |
| Receiver | مقدار یا pointerای که در تعریف method به method داده می‌شود. |
| Value receiver | receiver که کپی مقدار را می‌گیرد. |
| Pointer receiver | receiver pointer که می‌تواند شیء اصلی را تغییر دهد و از کپی بزرگ جلوگیری کند. |
| Variadic function | تابعی که تعداد متغیر آرگومان‌های هم‌نوع می‌گیرد. |
| Closure | تابعی که متغیرهای scope بیرونی را capture می‌کند. |
| Callback | تابعی که به کد دیگری داده می‌شود تا هنگام رویداد/نیاز اجرا شود. |
| Pointer | مقداری که نشانی یک مقدار دیگر را نگه می‌دارد. |
| Nil | مقدار نبودن برای pointer، map، slice، channel، function و interface؛ رفتار نوع‌مند دارد. |
| Typed nil | pointer/interface داخلی nil که داخل interface غیرnil قرار گرفته است. |
| Aliasing | دسترسی چند نام یا reference به دادهٔ مشترک. |
| Escape analysis | تحلیل کامپایلر برای عمر و جایگاه احتمالی مقدار؛ stack/heap تصمیم اجرایی است. |
| Garbage collector | runtimeای که objectهای heap غیرقابل‌دسترسی را بازیافت می‌کند. |
| Heap | حافظه برای داده‌هایی که عمرشان از stack frame فراتر می‌رود یا runtime آن را لازم می‌داند. |
| Stack | حافظهٔ frameهای فراخوانی function؛ مدل implementation است و نباید به آدرس ثابت تکیه کرد. |
| Interface | قرارداد رفتار مبتنی بر مجموعهٔ method؛ پیاده‌سازی در Go ضمنی است. |
| Method set | مجموعهٔ methodهایی که یک type یا pointer type برای interface satisfaction ارائه می‌دهد. |
| Type assertion | استخراج type concrete از interface با بررسی runtime. |
| Type switch | switch بر اساس type واقعی مقدار داخل interface. |
| Generic | تعریف تابع، type یا method با type parameter و constraint. |
| Type parameter | پارامتر نوعی که هنگام استفاده با type argument جایگزین می‌شود. |
| Type argument | نوع مشخصی که برای type parameter انتخاب می‌شود. |
| Constraint | محدودیت عملیات/typeهایی که generic code می‌تواند روی type parameter انجام دهد. |
| Type set | مجموعهٔ typeهای مجاز یک interface constraint. |
| Type inference | استنتاج خودکار type argumentها از مقدار/زمینهٔ استفاده. |
| Reflection | بررسی و دستکاری اطلاعات type/value در runtime با package <code>reflect</code>. |
| Unsafe | قابلیت‌های سطح پایین package <code>unsafe</code> که ضمانت type safety را دور می‌زنند. |
| ABI | قرارداد سطح پایین میان caller و callee یا binary؛ جزئیات داخلی و نسخه‌پذیری باید بررسی شود. |

## سازمان، خطا و کتابخانه

| اصطلاح | معنی و توضیح |
|---|---|
| Package | واحد گروه‌بندی source و نام import در Go. |
| Module | مجموعهٔ packageها با مسیر module و dependency metadata در <code>go.mod</code>. |
| Module path | شناسهٔ import عمومی module، غالباً مسیر repository با version major در صورت نیاز. |
| Dependency | module یا package دیگری که کد از آن استفاده می‌کند. |
| Semantic versioning | قرارداد نسخهٔ major/minor/patch برای میزان سازگاری تغییر. |
| Vendor directory | کپی dependencyها در پوشهٔ <code>vendor</code> برای buildهای کنترل‌شده. |
| Exported | نامی که با حرف بزرگ آغاز می‌شود و از packageهای دیگر قابل‌دسترسی است. |
| Internal package | package زیر پوشهٔ <code>internal</code> که import آن محدود به درخت مجاز است. |
| Error value | مقداری که interface <code>error</code> را پیاده می‌کند و failure را صریح گزارش می‌دهد. |
| Error wrapping | افزودن context به error و نگه‌داشتن زنجیرهٔ علت با <code>%w</code>. |
| Sentinel error | error package-level شناخته‌شده که با <code>errors.Is</code> قابل‌مقایسه است. |
| Panic | توقف عادی جریان اجرای goroutine و اجرای deferها تا recover یا پایان process. |
| Recover | گرفتن panic فقط در اجرای همان goroutine و مرزهای طراحی‌شده. |
| Defer | ثبت فراخوانی برای اجرا هنگام برگشت function؛ مناسب cleanup و release. |
| Standard library | packageهای توزیع‌شده همراه Go، مثل <code>net/http</code> و <code>encoding/json</code>. |
| I/O | ورودی/خروجی؛ خواندن یا نوشتن فایل، شبکه، حافظه و stream. |
| Serialization | تبدیل ساختار داده به قالب قابل‌ذخیره/ارسال مانند JSON. |
| Marshal / Unmarshal | نام‌گذاری رایج Go برای encode و decode در packageهایی مانند JSON. |
| Context | شیء انتقال cancellation، deadline و دادهٔ request-scoped میان لایه‌ها. |
| Deadline | آخرین زمان مجاز برای پایان یک عملیات. |
| Timeout | سقف مدت انتظار؛ در network و I/O برای نگه‌نداشتن resource مهم است. |

## هم‌روندی، تست و عملیات

| اصطلاح | معنی و توضیح |
|---|---|
| Concurrency | پیشرفت چند کار در بازهٔ زمانی مشترک؛ الزاماً اجرای هم‌زمان روی CPU نیست. |
| Parallelism | اجرای واقعی چند کار در یک لحظه روی چند core/processor. |
| Goroutine | واحد اجرای سبک‌وزن زمان‌بندی‌شده توسط Go runtime. |
| Channel | مسیر type-safe برای ارسال value میان goroutineها. |
| Buffered channel | channel با ظرفیت صف؛ send ممکن است بدون receive فوری موفق شود تا buffer پر شود. |
| Select | ساختار انتظار بر چند channel operation یا cancellation. |
| Mutex | قفل انحصاری برای محافظت از دادهٔ مشترک. |
| WaitGroup | ابزار انتظار برای پایان تعداد مشخصی کار. |
| Race condition | نتیجه‌ای وابسته به ترتیب اجرای هم‌زمان کارها، حتی اگر دسترسی data race نباشد. |
| Data race | دسترسی هم‌زمان به یک memory location که حداقل یکی write است و synchronization ندارد. |
| Worker pool | تعداد محدودی worker برای پردازش تعداد زیادی job. |
| Fan-in | ترکیب چند جریان/خروجی به یک جریان. |
| Fan-out | توزیع کار یا داده به چند consumer/worker. |
| Backpressure | بازخوردی که سرعت تولید را با ظرفیت مصرف هماهنگ می‌کند. |
| Goroutine leak | goroutineی که پس از تمام‌شدن هدف کاری همچنان منتظر یا مسدود می‌ماند. |
| Unit test | تست رفتاری کوچک برای یک واحد با dependencyهای کنترل‌شده. |
| Integration test | تست تعامل چند جزء یا boundary واقعی‌تر. |
| Table-driven test | اجرای یک منطق تست روی مجموعهٔ caseهای داده‌محور. |
| Stub | وابستگی آزمایشی که پاسخ کنترل‌شده می‌دهد. |
| Fake | پیاده‌سازی سادهٔ کارا برای تست، مثلاً repository حافظه‌ای. |
| Mock | test double که فراخوانی‌ها/تعامل‌های مورد انتظار را ثبت و بررسی می‌کند. |
| Benchmark | اندازه‌گیری تکرارشوندهٔ هزینهٔ کد تحت workload تعریف‌شده. |
| Coverage | نسبت بخش‌های اجراشدهٔ کد در test؛ به‌تنهایی کیفیت یا درستی را اثبات نمی‌کند. |
| Fuzzing | تولید خودکار ورودی‌های متنوع برای کشف panic و bugهای ورودی. |
| Profiling | گردآوری شواهد CPU، heap، allocation، blocking یا goroutine برای یافتن bottleneck. |
| Trace | timeline رویدادهای runtime برای تحلیل scheduler و blocking. |
| Linter | ابزار تحلیل ایستا برای style، bug pattern و قاعده‌های کیفیت. |
| Vulnerability | ضعف قابل‌بهره‌برداری در کد، dependency، configuration یا عملیات. |
| Cross-compilation | ساخت binary برای OS/architecture متفاوت از ماشین build. |
| Build constraint | شرط انتخاب فایل‌های Go بر اساس OS، architecture یا tag. |
| cgo | اتصال Go به C و ABI/libraryهای native؛ پیچیدگی build و portability دارد. |
| Graceful shutdown | توقف کنترل‌شدهٔ پذیرش کار جدید و drain/cleanup منابع فعال. |
| SLO | هدف سطح خدمت برای تجربهٔ کاربر، مانند latency یا availability. |
| SSRF | وادارکردن server به درخواست مقصدی که attacker انتخاب کرده و ممکن است داخلی/ممنوع باشد. |
