# فصل ۰۸ — امنیت و حفاظت از ظرفیت سرویس

**زبان:** فارسی · [نسخهٔ انگلیسی](README.en.md)  

سرویسی که در بار عادی سریع است، با یک ورودی پرهزینه، وابستگی آسیب‌پذیر یا درخواست نامجاز می‌تواند منابعش را از دست بدهد. امنیت بخشی از دسترس‌پذیری و قابلیت اتکای Backend است: باید مشخص شود چه کسی مجاز به چه کاری است، هر کار چه بودجه‌ای دارد و تغییرات نرم‌افزار چگونه بازبینی می‌شوند. کاهش latency از راه حذف اعتبارسنجی، مجوز، رمزنگاری یا کنترل سوءاستفاده، بهینه‌سازی قابل قبول این مجموعه نیست.

این فصل چهار مورد Security در [نقشه راه Backend Performance](https://roadmap.sh/backend-performance-best-practices) را پوشش می‌دهد. **بررسی منابع: ۲۰۲۶-۱۱-۱۱؛ تکمیل آموزشی: ۲۰۲۶-۱۱-۱۱**. اصطلاح‌های پایه، مثال‌ها و مسیر حل تمرین‌ها داخل هر درس آمده‌اند؛ خواندن منبع بیرونی برای فهم فصل لازم نیست. لینک‌ها مطالعهٔ اختیاری و مرجع رسمی‌اند. نمونه‌ها آموزشی، مستقل از زبان و اجرا‌نشده‌اند؛ عددهای آن‌ها هدف عمومی ظرفیت، خط‌مشی امنیتی سازمان یا گزارش عملکرد یک شرکت نیستند.

## پیش‌نیاز و مسیر مطالعه

آشنایی مقدماتی با HTTP، برنامه و منابع سیستم برای شروع کافی است؛ dependency مستقیم/غیرمستقیم، session، tenant، latency صدکی، quota و artifact در درس مربوط تعریف می‌شوند. برای تمرین‌های کاغذی حساب ابری یا ابزار اسکن لازم نیست. تمرین عملی فقط در محیطی انجام می‌شود که برای آن مجوز دارید.

برای مشکل عملیاتی، ابتدا مسیر مصرف منابع را ببینید: درخواست ورودی ← بررسی‌های ارزان و محدودیت اندازه ← احراز هویت ← مجوز و سهمیه هویتی ← اجرای کار با deadline و هم‌زمانی محدود. ترتیب دقیق به endpoint و مدل تهدید بستگی دارد؛ کنترل اولیه ناشناس، کنترل نهایی tenant و بررسی مجوز یکدیگر را تکمیل می‌کنند. هر درس این زنجیره را باز می‌کند تا برای فهم همان موضوع لازم نباشد بیرون از مجموعه جست‌وجو کنید.

## سناریوی پیوسته فصل

فروشگاهی آموزشی امکان تولید گزارش سفارش دارد. کتابخانه PDF و وابستگی‌های غیرمستقیم آن در inventory ثبت می‌شوند. کاربر واردشده فقط گزارش tenant مجاز خود را می‌گیرد؛ تغییر شناسه سفارش نباید مرز دسترسی را عوض کند. تعداد export، اندازه بازه گزارش، اندازه فایل، worker هم‌زمان و هزینه سرویس خارجی سقف دارند. release جدید کتابخانه ابتدا در محیط کنترل‌شده از نظر صحت، امنیت، زمان و حافظه بررسی می‌شود؛ در بازبینی بعدی، مسیرهای قدیمی و workerها نیز مرور می‌شوند.

این سناریو فرضی است. [OWASP API4:2023](https://api-security.owasp.org/editions/2023/en/0xa4-unrestricted-resource-consumption/) مصرف CPU/حافظه و هزینه سرویس‌های پولی را در دامنه مصرف نامحدود منابع قرار می‌دهد. یک پاسخ کوچک نیز ممکن است برای تولیدش query، پردازش یا پیامک گران مصرف کند؛ محدودکردن تعداد درخواست به‌تنهایی کافی نیست.

## چک‌لیست مرور فصل

- [ ] inventory وابستگی با artifact مستقر و مالک به‌روزرسانی پیوند دارد.
- [ ] اسکن بدون finding را معادل نبود آسیب‌پذیری نمی‌دانم.
- [ ] Authentication، Authorization و quota را جدا و مکمل می‌دانم.
- [ ] مجوز شیء/عملیات/tenant در هر درخواست و مسیر worker اجرا می‌شود.
- [ ] هزینه auth، cache مجوز و revocation با حفظ کنترل‌ها اندازه‌گیری می‌شود.
- [ ] نرخ، burst، هم‌زمانی، payload، deadline و هزینه خارجی هرکدام بودجه دارند.
- [ ] رفتار خرابی limiter/identity/policy صریح و قابل مشاهده است.
- [ ] یافته امنیتی مالک، موعد، مدرک اصلاح و بازبینی مجدد دارد.
- [ ] بازگشت نسخه، کنترل حفاظتی لازم را حذف یا نسخه آسیب‌پذیر را بی‌برنامه احیا نمی‌کند.
