# توابع خالص — Pure functions


> **زبان:** [نسخهٔ انگلیسی](../../../../en/01/clean-code/topics/pure-functions/README.md)

[فصل کد تمیز](../../README.md) · [فهرست دوره](../../../../00-index.md)

## هدف درس

بتوانی مسئلهٔ این اصل را تشخیص بدهی، آن را در کد به‌کار ببری، trade-off را توضیح بدهی و در آزمون از نتیجه دفاع کنی.

## آموزش دقیق

تابع خالص برای ورودی یکسان همواره خروجی یکسان دارد و هنگام اجرا اثر قابل مشاهده‌ای بیرون از خودش ایجاد نمی‌کند. خواندن ساعت، شبکه، فایل، random یا global تابع را به وضعیت بیرونی وابسته می‌کند. نوشتن فایل، ارسال پیام و تغییر state مشترک اثر جانبی‌اند.

برای جداکردن محاسبه:
۱. زمان، نرخ، تنظیم و دادهٔ محیطی را در لبهٔ برنامه بخوان.
۲. آن‌ها را به تابع بده تا تصمیم فقط از ورودی‌ها به دست آید.
۳. اثر را بعد از محاسبه در لایهٔ application یا adapter اجرا کن.
۴. حالت‌های دامنه و مرز گردکردن را با آزمون صریح کن.

## سناریوی عملی: مالیات

تابع محاسبهٔ مالیات نباید خودش از تنظیمات نرخ بخواند. adapter نرخ موثر بر سفارش را از منبع معتبر می‌گیرد، تابع آن را ورودی می‌گیرد و نتیجه را برمی‌گرداند. در این حالت می‌توان نرخ‌ها و rounding مختلف را بدون شبکه آزمایش کرد.

## مرز و هزینه

سامانهٔ واقعی ناچار به I/O است؛ هدف حذف اثر جانبی نیست، بلکه جمع‌کردن آن در مرزهای آشکار است. تابع خالص گاهی پارامترهای بسیار می‌گیرد؛ یک context تغییرناپذیر و دامنه‌ای ممکن است مناسب باشد، اما bag عمومی وابستگی را پنهان می‌کند. خالص بودن به‌تنهایی امنیت یا درستی تجاری را اثبات نمی‌کند.

## تمرین

تابعی را که به ساعت یا global وابسته است بازطراحی کن؛ داده را از بیرون بگیر و آزمونی بنویس که بدون شبکه، sleep یا state مشترک اجرا شود.

## نمونهٔ کد/قرارداد

~~~python
def tax_cents(subtotal_cents: int, rate_basis_points: int) -> int:
    # 10000 basis points equals 100 percent.
    return (subtotal_cents * rate_basis_points + 5_000) // 10_000
~~~

## تمرین سنجش

نمونه‌ای از کد خودت یا یک پروژهٔ آموزشی انتخاب کن. مفهوم را در یک تغییر کوچک اعمال کن، آزمونی برای رفتار مرزی اضافه کن و با یک جمله ثبت کن که چه چیزی خواناتر یا امن‌تر شد.

## کوییز با پاسخ تشریحی

پیش از دیدن پاسخ، دلیل خودت را بنویس. پاسخ پیشنهادی باید با زمینه هماهنگ باشد؛ اگر گزینهٔ دیگری داری، trade-off آن را هم بیان کن.

1. **چرا تابع خالص تست‌پذیر است؟**
   - پاسخ تشریحی: نتیجه از ورودی معلوم می‌شود و آزمون به زمان یا زیرساخت واقعی وابسته نیست.
2. **چه چیزی تابع را ناخالص می‌کند؟**
   - پاسخ تشریحی: خواندن وضعیت مخفی یا ایجاد اثر قابل مشاهده مانند شبکه، فایل یا تغییر state مشترک.
3. **آیا سامانه کاملاً خالص می‌شود؟**
   - پاسخ تشریحی: خیر؛ I/O ضروری است. آن را از محاسبه و قواعد دامنه جدا و محدود می‌کنیم.
