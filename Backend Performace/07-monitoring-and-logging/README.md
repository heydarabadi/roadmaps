# فصل ۷ — پایش و لاگ‌گیری | Monitoring & Logging

**زبان:** فارسی · [English version](README.en.md)


بهینه‌سازی بدون مشاهده، ممکن است فقط یک نمودار را بهتر کند و تجربه کاربر را بدتر. این فصل از یک پرسش شروع می‌کند: «چه سهمی از کارهای کاربر با نتیجه درست و در مهلت مناسب تمام می‌شود؟» سپس داده لازم برای پاسخ، مسیر جمع‌آوری و هزینه تولید آن را طراحی می‌کند.

**تاریخ بررسی منابع: <span dir="ltr">2026-11-10</span>.** موضوع‌ها از بخش Monitoring & Logging در [نقشه‌راه Backend Performance](https://roadmap.sh/backend-performance-best-practices) آمده‌اند. اعداد مثال‌ها فرض آموزشی‌اند. Prometheus، Grafana و ELK نمونه ابزارند؛ انتخاب آن‌ها الزام این بسته نیست.

هر راهنما پیش‌نیازها، سازوکار، تصمیم‌ها، مثال کامل، تمرین حل‌شده و پاسخ آزمون را در همان صفحه توضیح می‌دهد. منابع بیرونی هر درس برای مطالعهٔ بیشتر و ردیابی منشأ فنی‌اند؛ برای فهم درس یا ادامهٔ ترتیب مطالعه لازم نیستند.

## سناریوی پیونددهنده

API گزارش‌گیری ظرف ۳۰ میلی‌ثانیه کار را می‌پذیرد، ولی کاربر نتیجه را بعداً دریافت می‌کند. نمودار زمان پاسخ API می‌تواند خوب باشد، درحالی‌که Jobها ساعت‌ها در صف مانده‌اند. پس هم نرخ پذیرش/شکست API و هم سن صف و زمان «پذیرش تا نتیجه» را می‌سنجیم. Trace مسیر یک تلاش و Log جزئیات خطا را نشان می‌دهد؛ شناسه Job تلاش‌های مختلف را به هم وصل می‌کند.

اگر هنگام حادثه تعداد لاگ‌ها ده برابر شود، ارسال مستقیم آن‌ها ممکن است درخواست را کند کند. صف غیرهمگام این انتظار را موقتاً جابه‌جا می‌کند؛ صف نامحدود حافظه را می‌خورد و صف محدود به سیاست پُرشدن نیاز دارد. اگر Collector یا محل ذخیره داده قطع شود، داشبورد بی‌خطا لزوماً نشانه سلامت سرویس نیست. هر سه درس این زنجیره را از دید کاربر تا مقصد داده دنبال می‌کنند.

## چک‌لیست مرور فصل

- [ ] واحد کار، جمعیت درخواست‌ها، بازه زمانی و تعریف موفقیت در مهلت معلوم است.
- [ ] Counter، Gauge و توزیع زمان پاسخ را درست انتخاب و تجمیع می‌کنم.
- [ ] شناسه درخواست/Trace در Log می‌آید، نه به‌عنوان Label نامحدود متریک.
- [ ] هزینه CPU، حافظه، شبکه و ذخیره داده پایش بودجه دارد.
- [ ] برای No Data، قطع Collector و خراب‌شدن مسیر هشدار، مشاهده مستقل دارم.
- [ ] هشدار مالک، اقدام بعدی و لینک بررسی دارد؛ نمودار تنها کافی نیست.
- [ ] صف لاگ محدود است و حذف، انتظار، Flush و Crash قرارداد مشخص دارند.
- [ ] لاگ تشخیصی را با سابقه ضروری کسب‌وکار و Audit پایدار اشتباه نمی‌گیرم.
