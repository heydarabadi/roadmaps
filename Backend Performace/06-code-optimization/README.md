# فصل ۶ — بهینه‌سازی کد (Code Optimization)

**زبان:** فارسی · [English version](README.en.md)


بهینه‌سازی یعنی رسیدن به رفتار درست با زمان، حافظه و هزینهٔ مناسب برای بار واقعی. هدف این فصل، پیدا کردن کار اضافی و محدود کردن مصرف منابع است. کوتاه‌تر شدن کد یا تغییر زبان به‌تنهایی معیار موفقیت نیست؛ تجربهٔ کاربر، نرخ خطا و هزینهٔ هر عملیات باید بهتر شوند.

پیش‌نیاز: چرخهٔ درخواست HTTP، مفهوم CPU و حافظه، I/O، صدک‌های تأخیر و آشنایی مقدماتی با ساختار داده. تاریخ بررسی منابع: **۲۰۲۶-۱۱-۱۰**. موضوع‌ها از [Backend Performance roadmap](https://roadmap.sh/backend-performance-best-practices) گرفته شده‌اند؛ مثال‌های عددی این فصل آموزشی‌اند و نتیجهٔ اجرای محلی یا تولید نیستند.

## سناریوی پیونددهندهٔ فصل

یک سرویس گزارش‌گیری فرضی در ساعت اوج، هم پاسخ فهرست را کند می‌کند و هم هنگام Export حافظهٔ زیادی می‌گیرد. قبل از بازنویسی، Profile نشان می‌دهد گزارش همهٔ ردیف‌ها را Buffer می‌کند و برای هر شناسه یک فراخوانی سریال دارد. Trace نیز نشان می‌دهد دریافت قیمت وابستگی اصلی پاسخ تعاملی است.

1. خط مبنا را برای فهرست و Export جدا ثبت کنید: p50/p95/p99، خطا، throughput پذیرفته‌شده و تکمیل‌شده، حافظهٔ اوج و CPU به ازای درخواست موفق.
2. برای Export، Streaming با بافر محدود و لغو هنگام قطع کلاینت را بررسی کنید؛ برای lookupها، داده‌ساختار یا Batching را با همان ورودی بسنجید.
3. مسیر درخواست را رسم و کار مستقل را با هم‌زمانی محدود اجرا کنید؛ کار غیرضروری را حذف کنید و کار قابل‌تأخیر را طبق قرارداد محصول به پس‌زمینه ببرید.
4. Deadline مشترک و Retry محدود بگذارید؛ در زمان اشباع، تلاش اضافی نباید ظرفیت را مصرف کند.
5. فقط اگر شواهد باقی‌مانده Runtime یا نیاز به مقیاس مستقل را نشان می‌دهند، نمونهٔ محدود تغییر زبان یا استخراج سرویس بسازید.
6. در همان شرایط بار مقایسه کنید و در صورت رشد خطا، هزینه یا p99 برگردید. کاهش CPU همراه با افت خروجی موفق، بهبود محسوب نمی‌شود.

## چک‌لیست مرور فصل

- [ ] مسئله با Route، نوع ورودی، بار و هدف قابل‌اندازه‌گیری بیان شده است.
- [ ] Profiling و انتخاب مسیر بحرانی پیش از بازنویسی انجام شده است.
- [ ] حافظه، CPU، زمان انتظار و تعداد فراخوانی‌ها جدا بررسی شده‌اند.
- [ ] رشد ورودی، کلاینت کند، خطای جزئی و قطع درخواست در طراحی حضور دارند.
- [ ] Timeout، Retry و Batching تحت یک بودجهٔ محدود کار می‌کنند.
- [ ] پیشنهاد Go/Rust یا Microservices به شاهد محدودیت و هزینهٔ مهاجرت متصل است.
- [ ] مثال آموزشی، سند عملیاتی و تجربهٔ گزارش‌شدهٔ شرکت باهم اشتباه نشده‌اند.
- [ ] نتیجه با بار نماینده و معیارهای صحت/خطا/هزینه ارزیابی می‌شود.
