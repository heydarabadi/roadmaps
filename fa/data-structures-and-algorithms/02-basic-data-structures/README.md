# فصل ۲ — ساختمان‌های دادهٔ پایه

> نسخهٔ انگلیسی: [English version](../../../en/data-structures-and-algorithms/02-basic-data-structures/README.md)

ساختار را با عملیات پرتکرار مسئله هماهنگ کن و هزینهٔ هر عملیات را پیش از انتخاب ببین.

## ترتیب پیشنهادی

1. پیش‌نیازها و تعریف‌ها را بخوان.
2. مثال هر تاپیک را دستی اجرا کن.
3. تمرین‌ها را انجام بده و بعد پاسخ آزمون را ببین.
4. هنگام پیاده‌سازی، complexity را با operation واقعی کتابخانهٔ زبانت تطبیق بده.

## انتخاب ساختار بر پایهٔ workload

سناریو: یک cache کلید-مقدار با سقف اندازه می‌خواهیم. lookup با کلید مهم است، پس hash map مناسب است؛ حذف قدیمی‌ترین/کم‌استفاده‌ترین نیز باید سریع باشد، پس یک فهرست دوطرفه برای ترتیب لازم می‌شود. این ترکیب نشان می‌دهد ساختارها را می‌توان کنار هم گذاشت و یک ADT را با چند representation پیاده کرد.

| نیاز پرتکرار | ساختار معمول | نکتهٔ هزینه‌ای |
|---|---|---|
| دسترسی مستقیم و پیمایش فشرده | آرایهٔ پویا | index O(1)، درج وسط O(n) |
| درج/حذف پس از گرهٔ معلوم | linked list | پیدا کردن خود گره هنوز O(n) است |
| آخرین‌وارد، اولین‌خارج | stack | push/pop از top |
| اولین‌وارد، اولین‌خارج | queue/deque | سر صف را با جابه‌جایی آرایه پیاده نکن |
| lookup کلید | hash table | میانگین O(1)، worst-case بالقوه O(n) |

## اجرای کامل انتخاب

برای صف پیام، ابتدا تضمین کن آیا ترتیب FIFO الزام محصول است. اگر بله، هر پیام در انتها اضافه و از ابتدا مصرف می‌شود. صف bounded رفتار پرشدن دارد: block، reject، drop-oldest یا رشد؛ انتخاب این policy بر قابلیت اطمینان اثر می‌گذارد. اگر هم‌زمان چند worker صف را مصرف می‌کنند، queue استاندارد ساده لزوماً thread-safe نیست و synchronization لازم است.

این بخش عنوان‌های گروهی نقشه را نیز پوشش می‌دهد؛ برای درس مستقل هر برگ، README تاپیک را باز کن.

## تاپیک والد نقشه: Basic Data Structures

### آموزش

ساختارهای پایهٔ نقشه شامل Array، Linked List، Queue، Stack و Hash Table است. هرکدام ترتیب و عملیات پرتکرار متفاوتی را بهینه می‌کنند.

**روش انتخاب/اجرا:** برای هر نیاز، عملیات پرتکرار را فهرست کن: دسترسی اندیسی، افزودن دو سر، LIFO/FIFO، یا lookup کلید؛ سپس پیچیدگی و locality حافظه را مقایسه کن.

**پیچیدگی و مبادله:** آرایه برای دسترسی مستقیم، صف برای FIFO، پشته برای LIFO، لیست برای درج با اشاره‌گر آماده و هش برای عضویت/lookup میانگین سریع مناسب است.

**تجربهٔ عملی:** این ساختارها در runtimeها، cache، صف پیام، پردازش batch و پیاده‌سازی APIهای استاندارد استفاده می‌شوند.

**دام رایج:** یک ساختار را به‌خاطر اسم رایج انتخاب نکن؛ نیاز ترتیب، resize، برخورد هش و حذف را بسنج.

### آزمون کوتاه با پاسخ

1. **پرسش:** کدام ساختار دسترسی بر پایهٔ اندیس می‌دهد؟
   **پاسخ:** آرایه.
2. **پرسش:** برای پردازش FIFO کدام ساختار مناسب است؟
   **پاسخ:** صف؛ دو سر باید با هزینهٔ کم مدیریت شوند.
3. **پرسش:** در hash table چه فرضی باید دربارهٔ O(1) داشت؟
   **پاسخ:** معمولاً میانگین است؛ برخوردها می‌توانند worst-case را افزایش دهند.


## آزمون جمع‌بندی فصل

۱. چرا آرایه برای خواندن عضو i بهتر از linked list است؟ آدرس مستقیم دارد. ۲. چه وقت درج linked list واقعاً O(1) است؟ وقتی محل/predecessor از قبل شناخته شده باشد. ۳. تفاوت stack و queue چیست؟ LIFO در برابر FIFO. ۴. چرا `list.pop(0)` برای BFS مناسب نیست؟ ممکن است عناصر را جابه‌جا و هر dequeue را خطی کند. ۵. hash برابر یعنی کلید برابر است؟ نه؛ equality بررسی نهایی است. ۶. چه چیزی LRU cache را عملی می‌کند؟ hash map برای یافتن node و doubly linked list برای جابه‌جایی/حذف O(1).

## معیار عبور

برای یک برنامهٔ واقعی، پنج عملیات پرتکرار را بنویس، اندازهٔ داده و نسبت read/write را تخمین بزن، بعد دو ساختار ممکن و trade-offشان را مقایسه کن. complexity کتابخانهٔ زبان خودت را نیز کنترل کن؛ نام متد به‌تنهایی کافی نیست.
