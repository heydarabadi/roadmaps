> مسیر: [فصل ۸ — الگوهای حل مسئله](../README.md) · پیش‌نیاز پیشنهادی: فصل ۱ و مبانی برنامه‌نویسی

## پیش‌نیازها و نقشهٔ ذهنی

بازگشت، آرایه و شمارش حالت. ابتدا مفهوم را به‌عنوان یک قرارداد ببین، سپس نمایش حافظه و عملیات را دنبال کن. هدف حفظ‌کردن نام نیست؛ باید بتوانی برای یک ورودی کوچک، state را بعد از هر گام بنویسی.

## ایده از پایه

DP پاسخ زیرمسئله‌های تکراری را یک بار محاسبه و ذخیره می‌کند. دو نشانهٔ رایج: optimal substructure (جواب از جواب‌های فرعی ساخته می‌شود) و overlapping subproblems.

## مدل، قرارداد و ناوردا

تعریف state باید بگوید دقیقاً چه اطلاعاتی مسئلهٔ فرعی را تعیین می‌کند؛ recurrence رابطهٔ stateهاست؛ base case شروع؛ evaluation order وابستگی‌ها را رعایت می‌کند. Memoization از بالا‌به‌پایین cache دارد؛ tabulation از پایین‌به‌بالا جدول می‌سازد.

ناوردا (invariant) جمله‌ای است که در تمام مراحل الگوریتم باید درست بماند. نوشتن آن پیش از کدنویسی، هم به اثبات درستی کمک می‌کند و هم خطاهای مرزی را آشکار می‌سازد.

## الگوریتم یا عملیات گام‌به‌گام

Fibonacci: dp[0]=0, dp[1]=1؛ برای i≥2، dp[i]=dp[i−1]+dp[i−2]. Knapsack: dp[i][w] بیشترین ارزش از i شیء با ظرفیت w؛ recurrence یا شیء i را نمی‌گیریم یا می‌گیریم و ظرفیتش کم می‌شود. با state و recurrence، بعد بهینه‌سازی حافظه را جدا انجام بده.

در پیاده‌سازی واقعی، قرارداد ورودی/خروجی را دقیق تعریف کن: رفتار ورودی تهی، مقدار تکراری، عنصر پیدا‌نشده و ظرفیت تمام‌شده باید روشن باشد.

## اجرای حل‌شده با ردگیری

Stairs با گام 1 یا 2: ways[n]=ways[n−1]+ways[n−2]، ways[0]=1. n=4: ways 1,1,2,3,5؛ جواب 5. مسیرهای [1+1+1+1,1+1+2,...] را با recurrence دسته‌بندی می‌کنیم.

برای تمرین، جدولی با ستون‌های «گام»، «اندیس/اشاره‌گر»، «بخش فعال»، «تغییر state» و «دلیل» بساز. این روش به‌خصوص برای الگوریتم‌های درجا و تقسیم‌و‌غلبه جلوی پرش ذهنی را می‌گیرد.

## چرا درست است؟

در tabulation، پیش از محاسبهٔ dp[i] همهٔ stateهای موردنیاز recurrence آماده‌اند و معنا/واحد dp با تعریف state همخوان است. در memoization، cache کلید state کامل را دارد تا نتیجهٔ دو زیرمسئلهٔ متفاوت قاطی نشود.

اثبات معمولاً سه بخش دارد: (۱) آغاز—ناوردا پیش از نخستین گام درست است؛ (۲) نگهداری—هر گام آن را حفظ می‌کند؛ (۳) پایان—شرط توقف همراه invariant جواب موردنیاز را نتیجه می‌دهد. اگر یکی از این سه بخش نامشخص است، هنوز درک الگوریتم کامل نشده است.

## تحلیل زمان و حافظه

معمولاً تعداد stateها × هزینهٔ transition. Fibonacci O(n) زمان و O(n) یا O(1) حافظه؛ knapsack 0/1 O(nW) زمان/حافظهٔ بهینه‌شده O(W) است، که pseudo-polynomial است چون به مقدار عددی W وابسته است.

در Big-O ورودی را تعریف کن (مثلاً n تعداد عناصر)، نوع حالت را نام ببر (بهترین/میانگین/بدترین)، و فضای کمکی را از حافظهٔ خود ورودی جدا کن. مرتبهٔ رشد زمان واقعی بر حسب ثانیه نیست؛ cache، تخصیص حافظه و ثابت‌های پیاده‌سازی هم اثر دارند.

## کاربرد واقعی و انتخاب مناسب

برنامه‌ریزی مسیر، تخصیص بودجه، alignment رشته/DNA، sequence model و تصمیم‌های مرحله‌ای. گاهی مسئله state-space بسیار بزرگ دارد و approximation/heuristic لازم می‌شود.

پیش از انتخاب بپرس: چه عملیاتی پرتکرارند؟ آیا ترتیب مهم است؟ دادهٔ ورودی چه اندازه است؟ آیا محدودیت حافظه، latency بدترین‌حالت یا thread-safety داریم؟ ساختار خوب برای workload نامناسب می‌تواند انتخاب بدی باشد.

## خطاهای رایج و edge caseها

state ناقص، base case اشتباه، ترتیب حلقهٔ 0/1 knapsack (باید w نزولی) و ناممکن‌گرفتن محدودیت‌ها خطاست. memoization حافظه و recursion دارد؛ tabulation همهٔ stateها را شاید بی‌نیاز بسازد.

حالت‌های مرزی را جداگانه بررسی کن: ورودی خالی، یک عضو، همهٔ اعضا برابر، هدف غایب، حداقل/حداکثر مقدار و اندازهٔ بزرگ. سرریز عدد صحیح در محاسبهٔ اندیس/ظرفیت نیز بسته به زبان مهم است.

## تمرین‌های مرحله‌ای

۱) state/recurrence/base برای coin change بساز و مشخص کن تعداد راه یا حداقل سکه چیست. ۲) Fibonacci را memoized و iterative بنویس. ۳) توضیح بده چرا knapsack O(nW) polynomial در تعداد بیت‌های W نیست.

برای هر تمرین، اول پاسخ ساده و درست بنویس، بعد پیچیدگی را حساب کن، سپس edge case اضافه کن. تمرین را با دست‌کم یک ورودی کوچک ردگیری کن و خروجی را با انتظار مستقل مقایسه کن.

## آزمون جامع با پاسخ تشریحی

ابتدا پاسخ‌ها را نخوان؛ جواب را با استدلال بنویس، سپس توضیح را مقایسه کن.

1. **پرسش:** چه چیزی از محاسبهٔ تکراری جلوگیری می‌کند؟
   **پاسخ تشریحی:** ذخیرهٔ پاسخ stateها در cache/جدول.
2. **پرسش:** state چیست؟
   **پاسخ تشریحی:** تعریف دقیق مسئلهٔ کوچک‌تر و اطلاعات لازم برای حل آن.
3. **پرسش:** زمان DP چگونه تخمین زده می‌شود؟
   **پاسخ تشریحی:** تعداد state × هزینهٔ transition هر state.
4. **پرسش:** memoization چیست؟
   **پاسخ تشریحی:** top-down recursion همراه cache.
5. **پرسش:** O(nW) در knapsack چرا pseudo-polynomial است؟
   **پاسخ تشریحی:** وابسته به مقدار W است، نه فقط تعداد بیت‌های نمایش ورودی.

## راهنمای بازگویی از حافظه

بدون نگاه به متن، ایده، پیش‌شرط، invariant، یک ردگیری واقعی، پیچیدگی، edge case و یک کاربرد را در چند دقیقه روی کاغذ توضیح بده. اگر فقط pseudocode را حفظی می‌نویسی اما دلیل درستی یا محدودیت‌ها را نمی‌دانی، یک بار دیگر بخش‌های invariant و خطاها را مرور کن.
