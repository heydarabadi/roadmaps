# توابع

> مسیر: [فصل ۱ — پایه‌ها و تحلیل الگوریتم](../readme.md) · پیش‌نیاز پیشنهادی: فصل ۱ و مبانی برنامه‌نویسی · [English](readme.en.md)

## پیش‌نیازها و نقشهٔ ذهنی

متغیر، expression و block. ابتدا مفهوم را به‌عنوان یک قرارداد ببین، سپس نمایش حافظه و عملیات را دنبال کن. هدف حفظ‌کردن نام نیست؛ باید بتوانی برای یک ورودی کوچک، state را بعد از هر گام بنویسی.

## ایده از پایه

تابع رفتار را با نام و قرارداد مستقل می‌کند. تابع خوب می‌گوید چه ورودی می‌گیرد، چه نتیجه/side effectی دارد، چه پیش‌شرطی لازم است و چه هزینه‌ای می‌آورد. الگوریتم‌های بازگشتی و modular از همین abstraction استفاده می‌کنند.

## مدل، قرارداد و ناوردا

پارامترها ورودی تابع‌اند؛ local state فقط در scope تعریف‌شده معتبر است؛ return پاسخ را به caller می‌دهد. pass-by-value/reference semantics به زبان و نوع وابسته است. تابع pure ورودی را نمی‌تغیرد و خروجی‌اش فقط به ورودی وابسته است؛ side effect باید مستند باشد.

ناوردا (invariant) جمله‌ای است که در تمام مراحل الگوریتم باید درست بماند. نوشتن آن پیش از کدنویسی، هم به اثبات درستی کمک می‌کند و هم خطاهای مرزی را آشکار می‌سازد.

## الگوریتم یا عملیات گام‌به‌گام

تابع `contains(A,x)`: ورودی sequence A و هدف x؛ خروجی boolean؛ پیش‌شرط هیچ؛ postcondition اگر true است indexی با A[i]=x وجود دارد. پیاده‌سازی خطی همهٔ خانه‌ها را بررسی می‌کند؛ invariant می‌گوید prefix قبلی هدف ندارد.

در پیاده‌سازی واقعی، قرارداد ورودی/خروجی را دقیق تعریف کن: رفتار ورودی تهی، مقدار تکراری، عنصر پیدا‌نشده و ظرفیت تمام‌شده باید روشن باشد.

## اجرای حل‌شده با ردگیری

تابع sumRange(l,r) بازهٔ نیمه‌باز [l,r) را جمع می‌کند. برای empty range l=r خروجی 0 (identity) است. نام‌گذاری endpointها و بازهٔ half-open مرزهای query را ساده می‌کند.

برای تمرین، جدولی با ستون‌های «گام»، «اندیس/اشاره‌گر»، «بخش فعال»، «تغییر state» و «دلیل» بساز. این روش به‌خصوص برای الگوریتم‌های درجا و تقسیم‌و‌غلبه جلوی پرش ذهنی را می‌گیرد.

## چرا درست است؟

precondition قبل از call، invariant درون loop/function، postcondition هنگام return. ترکیب قراردادها به caller اجازه می‌دهد correctness را مرحله‌ای استدلال کند.

اثبات معمولاً سه بخش دارد: (۱) آغاز—ناوردا پیش از نخستین گام درست است؛ (۲) نگهداری—هر گام آن را حفظ می‌کند؛ (۳) پایان—شرط توقف همراه invariant جواب موردنیاز را نتیجه می‌دهد. اگر یکی از این سه بخش نامشخص است، هنوز درک الگوریتم کامل نشده است.

## تحلیل زمان و حافظه

هزینهٔ call معمول ثابت است اما خود body جدا تحلیل می‌شود. recursion stack، ساختن return collection و clone پارامترها فضا/زمان اضافه می‌کنند. helperی که داخل loop فراخوانی می‌شود، cost آن در تعداد call ضرب می‌شود.

در Big-O ورودی را تعریف کن (مثلاً n تعداد عناصر)، نوع حالت را نام ببر (بهترین/میانگین/بدترین)، و فضای کمکی را از حافظهٔ خود ورودی جدا کن. مرتبهٔ رشد زمان واقعی بر حسب ثانیه نیست؛ cache، تخصیص حافظه و ثابت‌های پیاده‌سازی هم اثر دارند.

## کاربرد واقعی و انتخاب مناسب

تفکیک parser، algorithm، data access و presentation؛ unit test مستقل؛ reuse و خوانایی. در API عمومی، خطا را با exception/result مشخص منتقل کن.

پیش از انتخاب بپرس: چه عملیاتی پرتکرارند؟ آیا ترتیب مهم است؟ دادهٔ ورودی چه اندازه است؟ آیا محدودیت حافظه، latency بدترین‌حالت یا thread-safety داریم؟ ساختار خوب برای workload نامناسب می‌تواند انتخاب بدی باشد.

## خطاهای رایج و edge caseها

global mutable state، نام مبهم، side effect پنهان، return ناقص در branch و aliasing. تابعی به نام sort ممکن است ورودی را mutate کند یا خروجی جدید دهد؛ قرارداد را بررسی کن.

حالت‌های مرزی را جداگانه بررسی کن: ورودی خالی، یک عضو، همهٔ اعضا برابر، هدف غایب، حداقل/حداکثر مقدار و اندازهٔ بزرگ. سرریز عدد صحیح در محاسبهٔ اندیس/ظرفیت نیز بسته به زبان مهم است.

## تمرین‌های مرحله‌ای

۱) قرارداد binary search را بنویس. ۲) یک تابع pure و یک تابع با side effect بساز و فرق تست را بگو. ۳) call count یک helper O(n) داخل loop nتایی را تحلیل کن.

برای هر تمرین، اول پاسخ ساده و درست بنویس، بعد پیچیدگی را حساب کن، سپس edge case اضافه کن. تمرین را با دست‌کم یک ورودی کوچک ردگیری کن و خروجی را با انتظار مستقل مقایسه کن.

## آزمون جامع با پاسخ تشریحی

ابتدا پاسخ‌ها را نخوان؛ جواب را با استدلال بنویس، سپس توضیح را مقایسه کن.

1. **پرسش:** چهار جزء قرارداد؟
   **پاسخ تشریحی:** ورودی، خروجی، پیش‌شرط/پس‌شرط و side effect.
2. **پرسش:** تابع pure چیست؟
   **پاسخ تشریحی:** خروجی به ورودی وابسته و state بیرونی را تغییر نمی‌دهد.
3. **پرسش:** تابع O(n) در loop nتایی؟
   **پاسخ تشریحی:** مجموع O(n²).
4. **پرسش:** scope چه می‌کند؟
   **پاسخ تشریحی:** محدودهٔ قابل‌دسترسی بودن نام‌ها را تعیین می‌کند.
5. **پرسش:** چرا half-open range؟
   **پاسخ تشریحی:** طول r−l است و بازهٔ خالی l=r را ساده می‌سازد.

## راهنمای بازگویی از حافظه

بدون نگاه به متن، ایده، پیش‌شرط، invariant، یک ردگیری واقعی، پیچیدگی، edge case و یک کاربرد را در چند دقیقه روی کاغذ توضیح بده. اگر فقط pseudocode را حفظی می‌نویسی اما دلیل درستی یا محدودیت‌ها را نمی‌دانی، یک بار دیگر بخش‌های invariant و خطاها را مرور کن.
