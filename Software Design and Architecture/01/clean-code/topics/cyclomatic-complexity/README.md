# پیچیدگی دوری — Cyclomatic Complexity


> **زبان:** [نسخهٔ انگلیسی](../../../../en/01/clean-code/topics/cyclomatic-complexity/README.md)

[فصل کد تمیز](../../README.md) · [فهرست دوره](../../../../00-index.md)

## هدف درس

بتوانی مسئلهٔ این اصل را تشخیص بدهی، آن را در کد به‌کار ببری، trade-off را توضیح بدهی و در آزمون از نتیجه دفاع کنی.

## آموزش دقیق

پیچیدگی دوری تعداد مسیرهای مستقل کنترل را تقریب می‌زند. تابع خطی مقدار پایهٔ ۱ دارد؛ if، case، حلقه و بعضی شرط‌های کوتاه‌مدار مسیر تازه می‌سازند. برای گراف کنترل، M = E - N + 2P است؛ در تابع متصل معمولاً تعداد نقاط تصمیم به‌اضافهٔ یک تخمین ساده است.

هر مسیر می‌تواند حالت دیگری برای فهم و آزمون باشد. اگر تابع سفارش شرط‌های کشور، نوع مشتری، تخفیف و زمان را باهم دارد، ممکن است چند قاعدهٔ مستقل در جای نامناسب جمع شده باشند. ابتدا مسیرها را با واژگان دامنه فهرست کن؛ سپس guard clause، جدول سیاست یا جداسازی قاعده را بررسی کن.

## مثال

شرط لغو سفارش باید وضعیت پرداخت، ارسال و مهلت را بررسی کند. تقسیم بی‌دلیل هر شرط به کلاس تازه شاخص را کم می‌کند اما پیچیدگی واقعی را حذف نمی‌کند. شاخص ابزار هشدار است، نه هدف معماری.

## محدودیت

اندازه‌گیری نمی‌فهمد شرط‌ها معنادارند یا نه. یک تصمیم دشوار می‌تواند complexity پایین داشته باشد؛ تابعی قابل‌خواندن هم ممکن است عدد بالاتری بگیرد. از آستانه برای یافتن کد نیازمند بازبینی استفاده کن و روند را بسنج، نه برای قبولی خودکار هر طراحی.

## تمرین

برای یک تابع، branchها را بشمار، مسیرهای دامنه‌ای را نام‌گذاری و آزمون متناظر را مشخص کن. بعد از refactor بررسی کن آیا تعداد مفهوم‌هایی که باید هم‌زمان بفهمی کم شده یا فقط به فایل‌های بیشتری منتقل شده‌اند.

## نمونهٔ کد/قرارداد

~~~python
def can_cancel(order, now):
    if order.is_cancelled:
        return False
    if order.is_shipped:
        return False
    if now >= order.cancellation_deadline:
        return False
    return True
~~~

## تمرین سنجش

نمونه‌ای از کد خودت یا یک پروژهٔ آموزشی انتخاب کن. مفهوم را در یک تغییر کوچک اعمال کن، آزمونی برای رفتار مرزی اضافه کن و با یک جمله ثبت کن که چه چیزی خواناتر یا امن‌تر شد.

## کوییز با پاسخ تشریحی

پیش از دیدن پاسخ، دلیل خودت را بنویس. پاسخ پیشنهادی باید با زمینه هماهنگ باشد؛ اگر گزینهٔ دیگری داری، trade-off آن را هم بیان کن.

1. **شاخص پیچیدگی دوری چه چیزی را تقریب می‌زند؟**
   - پاسخ تشریحی: تعداد مسیرهای مستقل کنترل و بار احتمالی فهم و آزمون.
2. **چه چیزی را ثابت نمی‌کند؟**
   - پاسخ تشریحی: عدد کم به تنهایی سادگی یا کیفیت کلی را ثابت نمی‌کند.
3. **چه زمانی branch را جدا می‌کنی؟**
   - پاسخ تشریحی: وقتی قاعده انسجام یا دلیل تغییر جدا دارد، نه فقط برای پایین‌آوردن عدد.
