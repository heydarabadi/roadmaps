# الگوریتم چندریسمانی

> مسیر: [فصل ۸ — الگوهای حل مسئله](../README.md) · پیش‌نیاز پیشنهادی: فصل ۱ و مبانی برنامه‌نویسی

## پیش‌نیازها و نقشهٔ ذهنی

الگوریتم ترتیبی، thread، synchronization و race. ابتدا مفهوم را به‌عنوان یک قرارداد ببین، سپس نمایش حافظه و عملیات را دنبال کن. هدف حفظ‌کردن نام نیست؛ باید بتوانی برای یک ورودی کوچک، state را بعد از هر گام بنویسی.

## ایده از پایه

کار را میان چند worker تقسیم می‌کنیم تا latency یا throughput بهتر شود. مدل درست باید هم درستی هم‌زمانی، هزینهٔ زمان‌بندی/ارتباط، و میزان کار قابل‌موازی‌شدن را حساب کند.

## مدل، قرارداد و ناوردا

Work T1 مجموع عملیات و span T∞ طولانی‌ترین زنجیرهٔ وابستگی‌اند. با P worker، زمان حداقل max(T1/P,T∞) است؛ overhead واقعی بیشتر می‌شود. race زمانی است که چند thread به state مشترک هم‌زمان دسترسی دارند و دست‌کم یک نوشتن بی‌هماهنگی رخ می‌دهد.

ناوردا (invariant) جمله‌ای است که در تمام مراحل الگوریتم باید درست بماند. نوشتن آن پیش از کدنویسی، هم به اثبات درستی کمک می‌کند و هم خطاهای مرزی را آشکار می‌سازد.

## الگوریتم یا عملیات گام‌به‌گام

برای reduce آرایه: تقسیم به chunkهای disjoint؛ هر thread مجموع محلی را حساب کند؛ سپس partial sumها با tree reduction ترکیب شوند. این روش از lock در هر عنصر پرهیز می‌کند. برای shared mutable state از lock/atomic و قرارداد memory visibility استفاده کن.

در پیاده‌سازی واقعی، قرارداد ورودی/خروجی را دقیق تعریف کن: رفتار ورودی تهی، مقدار تکراری، عنصر پیدا‌نشده و ظرفیت تمام‌شده باید روشن باشد.

## اجرای حل‌شده با ردگیری

جمع n عضو: تقسیم به P chunk با اندازهٔ نزدیک n/P؛ هرکدام sum محلی O(n/P)، سپس ترکیب P نتیجه O(log P) با درخت موازی یا O(P) ترتیبی. اگر chunkها روی یک متغیر مشترک بدون lock جمع شوند، updateها lost می‌شوند.

برای تمرین، جدولی با ستون‌های «گام»، «اندیس/اشاره‌گر»، «بخش فعال»، «تغییر state» و «دلیل» بساز. این روش به‌خصوص برای الگوریتم‌های درجا و تقسیم‌و‌غلبه جلوی پرش ذهنی را می‌گیرد.

## چرا درست است؟

هر عنصر دقیقاً به یک chunk تعلق دارد و هر partial sum دقیقاً مجموع همان chunk است؛ مرحلهٔ reduce هر partial را یک‌بار ترکیب می‌کند. thread safety باید تضمین کند publication و ترتیب دسترسی معتبر است.

اثبات معمولاً سه بخش دارد: (۱) آغاز—ناوردا پیش از نخستین گام درست است؛ (۲) نگهداری—هر گام آن را حفظ می‌کند؛ (۳) پایان—شرط توقف همراه invariant جواب موردنیاز را نتیجه می‌دهد. اگر یکی از این سه بخش نامشخص است، هنوز درک الگوریتم کامل نشده است.

## تحلیل زمان و حافظه

کار ایده‌آل T1/P است اما speedup با span، memory bandwidth، lock contention، false sharing و scheduling محدود می‌شود (Amdahl). scale-up روی core بیشتر تضمین خطی ندارد.

در Big-O ورودی را تعریف کن (مثلاً n تعداد عناصر)، نوع حالت را نام ببر (بهترین/میانگین/بدترین)، و فضای کمکی را از حافظهٔ خود ورودی جدا کن. مرتبهٔ رشد زمان واقعی بر حسب ثانیه نیست؛ cache، تخصیص حافظه و ثابت‌های پیاده‌سازی هم اثر دارند.

## کاربرد واقعی و انتخاب مناسب

پردازش تصویر، server request، map/reduce، محاسبات علمی و pipeline. برای I/O-bound کار asynchronous ممکن است بهتر از thread بیشتر باشد؛ برای CPU-bound parallelism واقعی لازم است.

پیش از انتخاب بپرس: چه عملیاتی پرتکرارند؟ آیا ترتیب مهم است؟ دادهٔ ورودی چه اندازه است؟ آیا محدودیت حافظه، latency بدترین‌حالت یا thread-safety داریم؟ ساختار خوب برای workload نامناسب می‌تواند انتخاب بدی باشد.

## خطاهای رایج و edge caseها

race، deadlock، starvation، false sharing، exception نیمه‌کاره و nondeterminism. عدم اشتراک‌گذاری state اغلب ساده‌ترین طراحی است. اندازهٔ chunk خیلی ریز overhead و خیلی درشت load imbalance می‌سازد.

حالت‌های مرزی را جداگانه بررسی کن: ورودی خالی، یک عضو، همهٔ اعضا برابر، هدف غایب، حداقل/حداکثر مقدار و اندازهٔ بزرگ. سرریز عدد صحیح در محاسبهٔ اندیس/ظرفیت نیز بسته به زبان مهم است.

## تمرین‌های مرحله‌ای

۱) reduction موازی را با 4 thread طراحی کن. ۲) race روی counter را نشان و atomic/lock حل کن. ۳) با بخش سریالی 20%، قانون Amdahl را برای 8 پردازنده حساب کن.

برای هر تمرین، اول پاسخ ساده و درست بنویس، بعد پیچیدگی را حساب کن، سپس edge case اضافه کن. تمرین را با دست‌کم یک ورودی کوچک ردگیری کن و خروجی را با انتظار مستقل مقایسه کن.

## آزمون جامع با پاسخ تشریحی

ابتدا پاسخ‌ها را نخوان؛ جواب را با استدلال بنویس، سپس توضیح را مقایسه کن.

1. **پرسش:** Work چیست؟
   **پاسخ تشریحی:** مجموع عملیات الگوریتم ترتیبی.
2. **پرسش:** Span چیست؟
   **پاسخ تشریحی:** طولانی‌ترین زنجیرهٔ وابستگی که موازی نمی‌شود.
3. **پرسش:** race چیست؟
   **پاسخ تشریحی:** دسترسی هم‌زمان ناسازگار به state مشترک با حداقل یک write.
4. **پرسش:** چرا speedup خطی نیست؟
   **پاسخ تشریحی:** span، bandwidth و overhead/ contention محدود می‌کنند.
5. **پرسش:** یک راه کاهش race؟
   **پاسخ تشریحی:** chunkهای مستقل و ترکیب نتایج محلی.

## راهنمای بازگویی از حافظه

بدون نگاه به متن، ایده، پیش‌شرط، invariant، یک ردگیری واقعی، پیچیدگی، edge case و یک کاربرد را در چند دقیقه روی کاغذ توضیح بده. اگر فقط pseudocode را حفظی می‌نویسی اما دلیل درستی یا محدودیت‌ها را نمی‌دانی، یک بار دیگر بخش‌های invariant و خطاها را مرور کن.
