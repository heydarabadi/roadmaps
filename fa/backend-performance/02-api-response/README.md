# فصل ۰۲: پاسخ API — دادهٔ لازم، با کار و انتقال متناسب

**زبان:** فارسی · [English version](../../../en/backend-performance/02-api-response/README.md)


وقتی کاربر فهرست سفارش‌ها را باز می‌کند، سریع بودن Query به‌تنهایی کافی نیست. ساختن هزاران شیء، محاسبهٔ فیلدهای بلااستفاده، تبدیل آن‌ها به JSON، انتقال چند مگابایت و Parse کردن در گوشی هم هزینه دارند. این فصل چهار تصمیم را به هم وصل می‌کند: چه داده‌ای، چه تعداد، با چه Encoding و پس از چه مقدار پردازش برگردد.

این فصل بخشی از [بستهٔ Backend Performance](../README.md) و متناظر با بخش API Response در [نقشهٔ راه مبنا](https://roadmap.sh/backend-performance-best-practices) است. تاریخ بررسی منابع: **۲۰۲۶-۱۱-۱۰**. مثال‌های عددی این فصل آموزشی‌اند؛ هدف عملکرد عمومی برای همهٔ سرویس‌ها نیستند.

## پیش‌نیاز و نتیجهٔ یادگیری

با Request/Response در HTTP، JSON، Header، Status Code و یک Endpoint فهرستی آشنا باشید. دانستن مفهوم Query و Index کافی است؛ زبان یا Cloud خاصی لازم نیست. هر درس اصطلاحات ویژهٔ خود را در همان صفحه باز می‌کند و بدون خواندن لینک‌های دیگر قابل پیگیری است؛ منابع بیرونی فقط برای مطالعهٔ اختیاری و راستی‌آزمایی‌اند. پس از مطالعه می‌توانید برای یک Endpoint بودجهٔ اندازه تعیین کنید، مذاکرهٔ Compression را بررسی کنید، قرارداد Pagination بسازید و کار اضافی را پیش از اجرا حذف کنید.

## سناریوی مشترک فصل

**سناریوی فرضی:** فهرست سفارش‌های فروشگاه در هر بازدید همهٔ تاریخچه، اقلام، عکس‌های درون JSON و امتیاز محاسبه‌شدهٔ مشتری را می‌فرستد؛ رابط فقط شناسه، تاریخ، وضعیت و مبلغ را نشان می‌دهد.

1. یک نمایش خلاصه تعریف کنید؛ جزئیات و فایل‌ها مسیر جدا داشته باشند. اندازهٔ بازشده و منتقل‌شده را جدا ثبت کنید.
2. تعداد خروجی را محدود کنید و لینک ادامه بدهید؛ ترتیب و رفتار تغییر داده بین صفحات را بنویسید.
3. JSON کافی‌بزرگ را در لایهٔ مسئول با Encoding مورد قبول کلاینت فشرده کنید؛ نتیجه را از دید مصرف‌کننده ببینید.
4. محاسبهٔ امتیاز و واکشی اقلام را فقط در درخواست جزئیات انجام دهید. اگر نمایش خلاصه تغییری نکرده، اعتبار آن را پیش از ساخت کامل بررسی کنید.

موفقیت این سناریو فقط «JSON کوچک‌تر» نیست. تعداد Query/فراخوانی وابسته، CPU هر درخواست، حافظه، زمان تا نخستین بایت و زمان کل پاسخ، p95/p99 و خطاهای کلاینت را نیز مقایسه کنید. درصد بهبود بدون خط مبنا و شرایط یکسان معنای عملی کمی دارد.

## چک‌لیست مرور فصل

- [ ] مصرف‌کننده و فیلدهای لازم مشخص‌اند؛ پاسخ فهرست با جزئیات تفاوت دارد.
- [ ] سقف تعداد، اندازهٔ بایتی، عمق Expand و رفتار خطا مستندند.
- [ ] اندازهٔ JSON بازشده و بدنهٔ منتقل‌شده جدا اندازه‌گیری می‌شوند.
- [ ] Encoding، `Vary` و رفتار Reverse Proxy/CDN از دید کلاینت بررسی شده‌اند.
- [ ] Pagination از صفحهٔ نخست تا پایان، روی مجموعهٔ خالی و دادهٔ در حال تغییر تعریف دارد.
- [ ] فیلد انتخاب‌نشده باعث اجرای Query یا محاسبهٔ گران نمی‌شود.
- [ ] حذف کار اضافی مجوزدهی، صحت داده و تعهدات ثبت رویداد را حذف نمی‌کند.
- [ ] برای هر تغییر، خط مبنا، مشاهدهٔ مورد انتظار و راه برگشت وجود دارد.
