# پیچیدگی زمان و فضا

> مسیر: [فصل ۱ — پایه‌ها و تحلیل الگوریتم](../readme.md) · پیش‌نیاز پیشنهادی: فصل ۱ و مبانی برنامه‌نویسی · [English](readme.en.md)

## پیش‌نیازها و نقشهٔ ذهنی

Big-O و شمارش عملیات. ابتدا مفهوم را به‌عنوان یک قرارداد ببین، سپس نمایش حافظه و عملیات را دنبال کن. هدف حفظ‌کردن نام نیست؛ باید بتوانی برای یک ورودی کوچک، state را بعد از هر گام بنویسی.

## ایده از پایه

زمان تعداد عملیات را با رشد ورودی می‌سنجد؛ فضا مقدار حافظهٔ هم‌زمان موردنیاز را. ورودی/خروجی خود مسئله را از حافظهٔ کمکی جدا کن و در هر دو، worst/average/best را مطابق نیاز بیان کن.

## مدل، قرارداد و ناوردا

زمان معمولاً شمارش primitive operationها در مدل محاسباتی است. فضای کمکی peak extra memory است؛ بعضی قراردادها stack بازگشت را می‌شمارند و بعضی آن را جدا گزارش می‌کنند. خروجی n عضوی اگر لازم باشد Ω(n) فضا دارد ولی ممکن است auxiliary space را نادیده بگیرند.

ناوردا (invariant) جمله‌ای است که در تمام مراحل الگوریتم باید درست بماند. نوشتن آن پیش از کدنویسی، هم به اثبات درستی کمک می‌کند و هم خطاهای مرزی را آشکار می‌سازد.

## الگوریتم یا عملیات گام‌به‌گام

برای حلقهٔ یک‌باره روی n عضو: T=Θ(n). اگر فقط چند شمارنده داریم S_aux=Θ(1). ساخت آرایهٔ copy از n عضو، S_aux=Θ(n). recursion با عمق h، stack Θ(h)، حتی اگر هر call فقط چند متغیر داشته باشد.

در پیاده‌سازی واقعی، قرارداد ورودی/خروجی را دقیق تعریف کن: رفتار ورودی تهی، مقدار تکراری، عنصر پیدا‌نشده و ظرفیت تمام‌شده باید روشن باشد.

## اجرای حل‌شده با ردگیری

Merge sort T=Θ(n log n)، buffer Θ(n)، stack Θ(log n). Heap sort T=Θ(n log n)، auxiliary Θ(1)، اما output مرتب همان آرایهٔ ورودی است و in-place محسوب می‌شود. انتخاب تابع به محدودیت RAM و latency وابسته است.

برای تمرین، جدولی با ستون‌های «گام»، «اندیس/اشاره‌گر»، «بخش فعال»، «تغییر state» و «دلیل» بساز. این روش به‌خصوص برای الگوریتم‌های درجا و تقسیم‌و‌غلبه جلوی پرش ذهنی را می‌گیرد.

## چرا درست است؟

تحلیل باید تمام ساختارها و متغیرهای هم‌زمان زنده را بشمارد، نه مجموع allocationهای طول اجرا. حافظه‌ای که آزاد می‌شود peak فضای هم‌زمان را افزایش نمی‌دهد مگر runtime آن را نگه دارد.

اثبات معمولاً سه بخش دارد: (۱) آغاز—ناوردا پیش از نخستین گام درست است؛ (۲) نگهداری—هر گام آن را حفظ می‌کند؛ (۳) پایان—شرط توقف همراه invariant جواب موردنیاز را نتیجه می‌دهد. اگر یکی از این سه بخش نامشخص است، هنوز درک الگوریتم کامل نشده است.

## تحلیل زمان و حافظه

زمان و فضا trade-off دارند: memoization زمان را از نمایی به چندجمله‌ای کاهش می‌دهد اما cache می‌گیرد؛ in-place الگوریتم فضا را کم می‌کند اما ممکن است کد/دسترسی پیچیده‌تر شود. چندریسمانی فضای stack/buffer موازی را افزایش می‌دهد.

در Big-O ورودی را تعریف کن (مثلاً n تعداد عناصر)، نوع حالت را نام ببر (بهترین/میانگین/بدترین)، و فضای کمکی را از حافظهٔ خود ورودی جدا کن. مرتبهٔ رشد زمان واقعی بر حسب ثانیه نیست؛ cache، تخصیص حافظه و ثابت‌های پیاده‌سازی هم اثر دارند.

## کاربرد واقعی و انتخاب مناسب

انتخاب sort برای محدودیت حافظه، پردازش دادهٔ بزرگ‌تر از RAM، سرویس با latency محدود و موبایل/embedded. هزینهٔ واقعی RAM شامل object overhead، allocator، stack و cache behavior است.

پیش از انتخاب بپرس: چه عملیاتی پرتکرارند؟ آیا ترتیب مهم است؟ دادهٔ ورودی چه اندازه است؟ آیا محدودیت حافظه، latency بدترین‌حالت یا thread-safety داریم؟ ساختار خوب برای workload نامناسب می‌تواند انتخاب بدی باشد.

## خطاهای رایج و edge caseها

O(1) space یعنی حافظهٔ کمکی ثابت، نه اینکه برنامه کلّاً حافظه نمی‌گیرد. recursion را فراموش نکن. output buffer را مشخص کن. asymptotic space با مصرف peak واقعی و GC heap یکی نیست.

حالت‌های مرزی را جداگانه بررسی کن: ورودی خالی، یک عضو، همهٔ اعضا برابر، هدف غایب، حداقل/حداکثر مقدار و اندازهٔ بزرگ. سرریز عدد صحیح در محاسبهٔ اندیس/ظرفیت نیز بسته به زبان مهم است.

## تمرین‌های مرحله‌ای

۱) زمان/فضای BFS، merge sort و binary search iterative را جدا حساب کن. ۲) recursive DFS در path graph با n گره stack چقدر می‌گیرد؟ ۳) memoization Fibonacci چه trade-offی دارد؟

برای هر تمرین، اول پاسخ ساده و درست بنویس، بعد پیچیدگی را حساب کن، سپس edge case اضافه کن. تمرین را با دست‌کم یک ورودی کوچک ردگیری کن و خروجی را با انتظار مستقل مقایسه کن.

## آزمون جامع با پاسخ تشریحی

ابتدا پاسخ‌ها را نخوان؛ جواب را با استدلال بنویس، سپس توضیح را مقایسه کن.

1. **پرسش:** space complexity معمولاً چه می‌شمارد؟
   **پاسخ تشریحی:** حافظهٔ کمکی/زنده برحسب ورودی؛ قرارداد output را روشن کن.
2. **پرسش:** recursive عمق h؟
   **پاسخ تشریحی:** O(h) stack.
3. **پرسش:** merge sort auxiliary space؟
   **پاسخ تشریحی:** O(n) در نسخهٔ آرایه‌ای معمول.
4. **پرسش:** O(1) space چه نیست؟
   **پاسخ تشریحی:** به معنی مصرف صفر حافظه نیست.
5. **پرسش:** چطور time-space trade-off رخ می‌دهد؟
   **پاسخ تشریحی:** حافظهٔ cache/جدول زمان محاسبهٔ تکراری را کم می‌کند.

## راهنمای بازگویی از حافظه
