# تمرین DSA با Rust

> والد: [انتخاب زبان](../README.md) · [فصل ۱](../../README.md) · [English](../../../../../en/data-structures-and-algorithms/01-foundations/choose-language/rust/README.md)

## پیش‌نیازها و نقشهٔ ذهنی

ownership، borrowing، Vec و Option. ابتدا مفهوم را به‌عنوان یک قرارداد ببین، سپس نمایش حافظه و عملیات را دنبال کن. هدف حفظ‌کردن نام نیست؛ باید بتوانی برای یک ورودی کوچک، state را بعد از هر گام بنویسی.

## ایده از پایه

Rust ایمنی حافظه را با ownership و borrow checker در زمان کامپایل تضمین می‌کند. در DSA باید lifetime ارجاع‌ها، انتقال ownership و API collectionها را یاد بگیری؛ برخی ساختارهای پیوندی از Vec پیچیده‌ترند.

## مدل، قرارداد و ناوردا

`Vec<T>` آرایهٔ پویا؛ `VecDeque<T>` صف دوطرفه؛ `HashMap/HashSet`; `BinaryHeap<T>` max-heap پیش‌فرض؛ `BTreeMap/Set` مرتب. pointerهای optional اغلب `Option<Box<Node>>` هستند.

ناوردا (invariant) جمله‌ای است که در تمام مراحل الگوریتم باید درست بماند. نوشتن آن پیش از کدنویسی، هم به اثبات درستی کمک می‌کند و هم خطاهای مرزی را آشکار می‌سازد.

## الگوریتم یا عملیات گام‌به‌گام

BFS: `VecDeque::from([start])`، `pop_front` و `push_back`؛ `HashSet` یا vector<bool> برای visited. Dijkstra با `BinaryHeap<Reverse<(cost,node)>>` کمینه را بیرون می‌آورد. برای heap ورودی stale را با dist مقایسه کن.

در پیاده‌سازی واقعی، قرارداد ورودی/خروجی را دقیق تعریف کن: رفتار ورودی تهی، مقدار تکراری، عنصر پیدا‌نشده و ظرفیت تمام‌شده باید روشن باشد.

## اجرای حل‌شده با ردگیری

`BinaryHeap<Reverse<(u64,usize)>>` ترتیب را معکوس می‌کند تا کمترین cost در pop بیاید. Tuple در tie از node هم ترتیب می‌گیرد؛ اگر node قابل Ord نیست، struct و `Ord`/`PartialOrd` سازگار پیاده کن.

برای تمرین، جدولی با ستون‌های «گام»، «اندیس/اشاره‌گر»، «بخش فعال»، «تغییر state» و «دلیل» بساز. این روش به‌خصوص برای الگوریتم‌های درجا و تقسیم‌و‌غلبه جلوی پرش ذهنی را می‌گیرد.

## چرا درست است؟

تنها مالک Box هنگام drop حافظه را آزاد می‌کند؛ borrow نباید پس از عمر owner بماند. تغییر Vec می‌تواند borrow را نامعتبر کند و compiler جلوی آن را می‌گیرد. `HashMap` key نیازمند Eq+Hash است و mutable key معمولاً borrow model آن را محدود می‌کند.

اثبات معمولاً سه بخش دارد: (۱) آغاز—ناوردا پیش از نخستین گام درست است؛ (۲) نگهداری—هر گام آن را حفظ می‌کند؛ (۳) پایان—شرط توقف همراه invariant جواب موردنیاز را نتیجه می‌دهد. اگر یکی از این سه بخش نامشخص است، هنوز درک الگوریتم کامل نشده است.

## تحلیل زمان و حافظه

Vec index O(1)، push amortized O(1)، VecDeque دو سر amortized O(1)، HashMap average O(1)، BTreeMap O(log n)، BinaryHeap push/pop O(log n). allocation و clone را صریح پیگیری کن.

در Big-O ورودی را تعریف کن (مثلاً n تعداد عناصر)، نوع حالت را نام ببر (بهترین/میانگین/بدترین)، و فضای کمکی را از حافظهٔ خود ورودی جدا کن. مرتبهٔ رشد زمان واقعی بر حسب ثانیه نیست؛ cache، تخصیص حافظه و ثابت‌های پیاده‌سازی هم اثر دارند.

## کاربرد واقعی و انتخاب مناسب

سیستم‌های performance-sensitive و ابزارهای با correctness حافظه مهم. Vec اغلب انتخاب اول است؛ linked list فقط وقتی workload و profiling آن را توجیه کند، چون locality ضعیف و ownership پیچیده‌تر دارد.

پیش از انتخاب بپرس: چه عملیاتی پرتکرارند؟ آیا ترتیب مهم است؟ دادهٔ ورودی چه اندازه است؟ آیا محدودیت حافظه، latency بدترین‌حالت یا thread-safety داریم؟ ساختار خوب برای workload نامناسب می‌تواند انتخاب بدی باشد.

## خطاهای رایج و edge caseها

clone پنهان می‌تواند O(n) باشد؛ borrow conflict را با طراحی مالکیت حل کن، نه فوراً Rc/RefCell. `BinaryHeap` max-heap است. integer overflow و `usize` index/portability را در نظر بگیر.

حالت‌های مرزی را جداگانه بررسی کن: ورودی خالی، یک عضو، همهٔ اعضا برابر، هدف غایب، حداقل/حداکثر مقدار و اندازهٔ بزرگ. سرریز عدد صحیح در محاسبهٔ اندیس/ظرفیت نیز بسته به زبان مهم است.

## تمرین‌های مرحله‌ای

۱) BFS با VecDeque و HashSet بساز. ۲) BinaryHeap min را با Reverse پیاده کن. ۳) یک linked node با Option<Box<Node>> و درج را توضیح بده.

برای هر تمرین، اول پاسخ ساده و درست بنویس، بعد پیچیدگی را حساب کن، سپس edge case اضافه کن. تمرین را با دست‌کم یک ورودی کوچک ردگیری کن و خروجی را با انتظار مستقل مقایسه کن.

## آزمون جامع با پاسخ تشریحی

ابتدا پاسخ‌ها را نخوان؛ جواب را با استدلال بنویس، سپس توضیح را مقایسه کن.

1. **پرسش:** VecDeque چه می‌دهد؟
   **پاسخ تشریحی:** صف دوطرفه با عملیات دو سر کارآمد.
2. **پرسش:** BinaryHeap پیش‌فرض؟
   **پاسخ تشریحی:** max-heap.
3. **پرسش:** Reverse چرا؟
   **پاسخ تشریحی:** معکوس‌کردن ترتیب برای ساخت min-heap.
4. **پرسش:** HashMap key چه traitهایی می‌خواهد؟
   **پاسخ تشریحی:** Eq و Hash.
5. **پرسش:** چرا Vec معمولاً بر linked list ترجیح دارد؟
   **پاسخ تشریحی:** locality و سادگی؛ linked list فقط برای workload مناسب.

## راهنمای بازگویی از حافظه

بدون نگاه به متن، ایده، پیش‌شرط، invariant، یک ردگیری واقعی، پیچیدگی، edge case و یک کاربرد را در چند دقیقه روی کاغذ توضیح بده. اگر فقط pseudocode را حفظی می‌نویسی اما دلیل درستی یا محدودیت‌ها را نمی‌دانی، یک بار دیگر بخش‌های invariant و خطاها را مرور کن.
