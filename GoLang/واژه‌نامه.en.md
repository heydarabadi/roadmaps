# Go Glossary

This glossary complements the explanations in the lessons; it does not replace them. Keep standard English terms, package names, commands, and type names intact when discussing Go.

## Language and data

| Term | Meaning |
|---|---|
| Go / Golang | The language's name is Go; Golang is commonly used as a search term. |
| Source code | Program text written and maintained by developers. |
| Compiler | A tool that analyzes source and produces executable code or an intermediate representation. |
| Type | A set of permitted values and the operations defined for those values. |
| Zero value | The default initial value of a Go variable when no initializer is provided. |
| Variable | A named, typed storage location for a value. |
| Constant | A compile-time, immutable value declared with const. |
| Scope | The region of a program in which a name can be referred to. |
| Shadowing | Declaring a same-named identifier in an inner scope, temporarily hiding the outer one. |
| Type conversion | An explicit conversion from one type to another; Go generally does not perform implicit numeric conversions. |
| Signed integer | An integer type whose range includes negative, zero, and positive values. |
| Unsigned integer | An integer type whose range contains zero and positive values but no negative values. |
| Floating-point | An approximate real-number representation; direct equality can be unsuitable for some calculations. |
| Complex number | A number with real and imaginary components. |
| Rune | Go's name for a Unicode code point value represented as int32. |
| Byte | An alias for uint8; it represents a byte of data, not necessarily a whole character. |
| UTF-8 | A variable-width Unicode encoding using one to four bytes per code point. |
| Grapheme cluster | A sequence a user perceives as one character; it can contain multiple runes. |
| Array | A fixed-length value whose length is part of its type and which owns its elements. |
| Slice | A dynamically sized view over a backing array, described by a length and capacity. |
| Backing array | The array that stores a slice's elements; multiple slices can share it. |
| Length | The number of currently accessible elements in a slice or bytes in a string. |
| Capacity | For a slice, the number of elements from its first element to the end of its backing array. |
| Map | A key-to-value mapping; iteration order is unspecified. |
| Comma-ok idiom | Receiving a value and a bool together to check map-key presence, assertion success, or channel status. |
| Struct | A composition of named fields with declared types. |
| Struct tag | String metadata beside a field that packages such as JSON may interpret. |
| Embedding | Placing a type inside another struct or interface to compose behavior and promote some members. |
| Promotion | Shorter access to a field or method through an embedded type. |
| Composite literal | Syntax for constructing an array, slice, map, or struct value directly. |

## Functions, memory, and abstraction

| Term | Meaning |
|---|---|
| Function | An independent callable unit with defined inputs and outputs. |
| Method | A function associated with a type through a receiver. |
| Receiver | The value or pointer supplied to a method as its receiver. |
| Value receiver | A receiver that gets a copy of the value. |
| Pointer receiver | A pointer receiver that can mutate the original value and avoid copying a large value. |
| Variadic function | A function that accepts a variable number of arguments of one element type. |
| Closure | A function value that captures variables from an enclosing scope. |
| Callback | A function passed to other code to be invoked when needed or when an event occurs. |
| Pointer | A value that stores the address of another value. |
| Nil | The zero value for pointer, map, slice, channel, function, and interface types; its behavior depends on its type. |
| Typed nil | A nil concrete pointer stored inside an interface value that is itself non-nil. |
| Aliasing | Multiple names or references accessing shared data. |
| Escape analysis | Compiler analysis of value lifetime and placement; stack versus heap is an implementation decision. |
| Garbage collector | The runtime component that reclaims unreachable heap objects. |
| Heap | Storage for values whose lifetimes outlast a stack frame or that the implementation places there for other reasons. |
| Stack | Storage for function-call frames; it is an implementation model, so code should not rely on fixed addresses. |
| Interface | A behavior contract defined by a method set; Go implements interfaces implicitly. |
| Method set | The set of methods a type or pointer type provides for interface satisfaction. |
| Type assertion | A runtime operation that extracts a concrete type from an interface value. |
| Type switch | A switch that branches on the concrete type stored in an interface value. |
| Generic | A function, type, or method parameterized by types and constrained by requirements. |
| Type parameter | A type variable that is replaced by a type argument when generic code is instantiated. |
| Type argument | A concrete type selected for a type parameter. |
| Constraint | The requirements on types or operations that generic code may use for a type parameter. |
| Type set | The set of types permitted by an interface constraint. |
| Type inference | Automatic deduction of type arguments from values or use context. |
| Reflection | Runtime inspection and manipulation of type/value information using the reflect package. |
| Unsafe | Low-level facilities in the unsafe package that bypass normal type-safety guarantees. |
| ABI | A low-level calling or binary interface; details can be implementation-specific and version-sensitive. |

## Packages, errors, and standard library

| Term | Meaning |
|---|---|
| Package | A unit that groups Go source files and defines an import name. |
| Module | A collection of packages identified by a module path and dependency metadata in go.mod. |
| Module path | The public import identifier for a module, often based on its repository path and major version. |
| Dependency | Another module or package used by a program. |
| Semantic versioning | A versioning convention using major, minor, and patch numbers to communicate compatibility changes. |
| Vendor directory | A vendor folder containing copied dependencies for controlled builds. |
| Exported | A name beginning with an uppercase letter and accessible from another package. |
| Internal package | A package under an internal directory whose imports are restricted to an allowed tree. |
| Error value | A value implementing the error interface to report a failure explicitly. |
| Error wrapping | Adding context while preserving an error cause chain, commonly with %w. |
| Sentinel error | A known package-level error value that can be matched using errors.Is. |
| Panic | An abnormal control-flow event that runs deferred calls in the current goroutine until recovered or the process exits. |
| Recover | Catching a panic only in a deferred call in the same goroutine, at an intentional boundary. |
| Defer | Scheduling a call to run when the surrounding function returns; often used for cleanup. |
| Standard library | Packages distributed with Go, such as net/http and encoding/json. |
| I/O | Input and output: reading or writing files, networks, memory, and streams. |
| Serialization | Converting structured data into a storable or transferable format such as JSON. |
| Marshal / Unmarshal | Common Go terms for encoding and decoding in packages such as encoding/json. |
| Context | A value carrying cancellation, deadlines, and request-scoped data across API boundaries. |
| Deadline | The latest time by which an operation should finish. |
| Timeout | A maximum waiting duration, important for releasing resources held by network and I/O operations. |

## Concurrency, testing, and operations

| Term | Meaning |
|---|---|
| Concurrency | Progress by multiple tasks during overlapping time; they do not have to execute simultaneously on a CPU. |
| Parallelism | Multiple tasks executing at the same instant on separate cores or processors. |
| Goroutine | A lightweight execution unit scheduled by the Go runtime. |
| Channel | A typed communication path for values between goroutines. |
| Buffered channel | A channel with queue capacity; sends can complete without an immediate receiver until the buffer fills. |
| Select | A statement that waits on multiple channel operations or cancellation signals. |
| Mutex | An exclusive lock used to protect shared data. |
| WaitGroup | A synchronization tool for waiting until a known set of tasks finishes. |
| Race condition | A result that depends on execution order, even if the accesses do not form a data race. |
| Data race | Unsynchronized concurrent access to one memory location where at least one access is a write. |
| Worker pool | A bounded set of workers processing a larger number of jobs. |
| Fan-in | Combining multiple streams or results into one stream. |
| Fan-out | Distributing work or data among multiple consumers or workers. |
| Backpressure | Feedback that aligns production speed with consumer capacity. |
| Goroutine leak | A goroutine that remains blocked or waiting after its intended work has ended. |
| Unit test | A small behavioral test for one unit with controlled dependencies. |
| Integration test | A test of interactions among multiple components or a more realistic boundary. |
| Table-driven test | Running test logic over a data-driven collection of cases. |
| Stub | A test dependency that returns controlled responses. |
| Fake | A simple working implementation for tests, such as an in-memory repository. |
| Mock | A test double that records and checks expected interactions. |
| Benchmark | A repeated measurement of code cost under a defined workload. |
| Coverage | The proportion of code exercised by tests; by itself it does not prove quality or correctness. |
| Fuzzing | Automatically generating varied inputs to discover panics and input-related bugs. |
| Profiling | Collecting CPU, heap, allocation, blocking, or goroutine evidence to locate bottlenecks. |
| Trace | A timeline of runtime events used to analyze scheduling and blocking. |
| Linter | A static-analysis tool for style, bug patterns, and quality rules. |
| Vulnerability | An exploitable weakness in code, a dependency, configuration, or operations. |
| Cross-compilation | Building a binary for an OS or architecture different from the build machine. |
| Build constraint | A condition that selects Go files based on OS, architecture, or build tags. |
| cgo | Connecting Go to C and native ABIs/libraries, with added build and portability complexity. |
| Graceful shutdown | Stopping acceptance of new work and draining or cleaning up active resources in a controlled way. |
| SLO | A service-level objective for user experience, such as latency or availability. |
| SSRF | Server-side request forgery: inducing a server to request an attacker-chosen destination, potentially internal or prohibited. |
