# مجموعهٔ مجزا (Union-Find / DSU)

> نسخهٔ انگلیسی: [English version](../../../../en/data-structures-and-algorithms/06-advanced-data-structures/union-find/README.md)

> مسیر: [فصل ۶ — ساختمان‌های دادهٔ پیشرفته](../README.md) · پیش‌نیاز پیشنهادی: فصل ۱ و مبانی برنامه‌نویسی

## پیش‌نیازها و نقشهٔ ذهنی

آرایه، درخت و مفهوم component. ابتدا مفهوم را به‌عنوان یک قرارداد ببین، سپس نمایش حافظه و عملیات را دنبال کن. هدف حفظ‌کردن نام نیست؛ باید بتوانی برای یک ورودی کوچک، state را بعد از هر گام بنویسی.

## ایده از پایه

DSU مجموعه‌هایی را مدیریت می‌کند که جدا هستند و با union به هم می‌پیوندند. find نمایندهٔ مجموعه را می‌دهد و برای connectivity سریع است؛ ساختار از ادغام پشتیبانی می‌کند، اما حذف دلخواه عضو/یال را ساده پشتیبانی نمی‌کند.

## مدل، قرارداد و ناوردا

parent[x]=x برای ریشه. find(x) تا root می‌رود. path compression والدها را هنگام برگشت مستقیم به root وصل می‌کند؛ union by size/rank ریشهٔ کوچک‌تر را زیر بزرگ‌تر می‌گذارد تا درخت کم‌ارتفاع بماند.

ناوردا (invariant) جمله‌ای است که در تمام مراحل الگوریتم باید درست بماند. نوشتن آن پیش از کدنویسی، هم به اثبات درستی کمک می‌کند و هم خطاهای مرزی را آشکار می‌سازد.

## الگوریتم یا عملیات گام‌به‌گام

find(x): اگر parent[x]!=x، parent[x]=find(parent[x])؛ return parent[x]. union(a,b): ra=find(a)، rb=find(b)؛ اگر برابر، false؛ وگرنه ریشهٔ با size/rank کمتر را زیر بزرگ‌تر وصل، اندازه/رتبه را به‌روز و true برگردان.

در پیاده‌سازی واقعی، قرارداد ورودی/خروجی را دقیق تعریف کن: رفتار ورودی تهی، مقدار تکراری، عنصر پیدا‌نشده و ظرفیت تمام‌شده باید روشن باشد.

## اجرای حل‌شده با ردگیری

با 0..4، union(0,1)، union(2,3)، union(1,2) چهار رأس نخست یک component می‌شوند؛ find(0)==find(3)، ولی find(4) جداست. در Kruskal همین آزمون می‌گوید یال چرخه می‌سازد یا دو component را وصل می‌کند.

برای تمرین، جدولی با ستون‌های «گام»، «اندیس/اشاره‌گر»، «بخش فعال»، «تغییر state» و «دلیل» بساز. این روش به‌خصوص برای الگوریتم‌های درجا و تقسیم‌و‌غلبه جلوی پرش ذهنی را می‌گیرد.

## چرا درست است؟

هر ریشه شناسهٔ یک مجموعهٔ disjoint است و تمام اعضای همان مجموعه در نهایت به آن می‌رسند. union دو مجموعهٔ جدا را دقیقاً یک مجموعه می‌کند؛ یکپارچگی نماینده‌های دیگر حفظ می‌شود.

اثبات معمولاً سه بخش دارد: (۱) آغاز—ناوردا پیش از نخستین گام درست است؛ (۲) نگهداری—هر گام آن را حفظ می‌کند؛ (۳) پایان—شرط توقف همراه invariant جواب موردنیاز را نتیجه می‌دهد. اگر یکی از این سه بخش نامشخص است، هنوز درک الگوریتم کامل نشده است.

## تحلیل زمان و حافظه

با union by size/rank و path compression، عملیات‌ها O(α(n)) سرشکن‌اند؛ α تابع معکوس Ackermann است و برای اندازه‌های عملی بسیار آهسته رشد می‌کند. init O(n)، حافظه O(n).

در Big-O ورودی را تعریف کن (مثلاً n تعداد عناصر)، نوع حالت را نام ببر (بهترین/میانگین/بدترین)، و فضای کمکی را از حافظهٔ خود ورودی جدا کن. مرتبهٔ رشد زمان واقعی بر حسب ثانیه نیست؛ cache، تخصیص حافظه و ثابت‌های پیاده‌سازی هم اثر دارند.

## کاربرد واقعی و انتخاب مناسب

Kruskal MST، componentهای شبکهٔ پویا با فقط ادغام، percolation و گروه‌بندی حساب‌ها. برای حذف یال در dynamic connectivity معمولاً ساختار بسیار پیچیده‌تر لازم است.

پیش از انتخاب بپرس: چه عملیاتی پرتکرارند؟ آیا ترتیب مهم است؟ دادهٔ ورودی چه اندازه است؟ آیا محدودیت حافظه، latency بدترین‌حالت یا thread-safety داریم؟ ساختار خوب برای workload نامناسب می‌تواند انتخاب بدی باشد.

## خطاهای رایج و edge caseها

parent لزوماً ریشهٔ مستقیم نیست؛ فقط find نماینده را می‌دهد. rank پس از path compression ارتفاع واقعی نیست، بلکه کران تاریخی است. union روی عناصر تکراری نباید size را دوباره افزایش دهد.

حالت‌های مرزی را جداگانه بررسی کن: ورودی خالی، یک عضو، همهٔ اعضا برابر، هدف غایب، حداقل/حداکثر مقدار و اندازهٔ بزرگ. سرریز عدد صحیح در محاسبهٔ اندیس/ظرفیت نیز بسته به زبان مهم است.

## تمرین‌های مرحله‌ای

۱) parent array را پس از unionهای داده‌شده رسم کن. ۲) یک مسیر بلند را قبل و بعد از compression مقایسه کن. ۳) چرا DSU به‌تنهایی حذف ارتباط را پشتیبانی نمی‌کند؟

برای هر تمرین، اول پاسخ ساده و درست بنویس، بعد پیچیدگی را حساب کن، سپس edge case اضافه کن. تمرین را با دست‌کم یک ورودی کوچک ردگیری کن و خروجی را با انتظار مستقل مقایسه کن.

## آزمون جامع با پاسخ تشریحی

ابتدا پاسخ‌ها را نخوان؛ جواب را با استدلال بنویس، سپس توضیح را مقایسه کن.

1. **پرسش:** find چه می‌دهد؟
   **پاسخ تشریحی:** نمایندهٔ component.
2. **پرسش:** path compression چه می‌کند؟
   **پاسخ تشریحی:** مسیر فرزندها را مستقیم‌تر به ریشه وصل می‌کند.
3. **پرسش:** union by size چه هدفی دارد؟
   **پاسخ تشریحی:** جلوگیری از بلندشدن درخت.
4. **پرسش:** زمان سرشکن؟
   **پاسخ تشریحی:** O(α(n)).
5. **پرسش:** چه عملیاتی به‌سختی پشتیبانی می‌شود؟
   **پاسخ تشریحی:** حذف دلخواه یال یا جداکردن component.
