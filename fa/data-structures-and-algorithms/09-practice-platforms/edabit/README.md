# تمرین در Edabit

> مسیر: [فصل ۹ — تمرین و خودارزیابی](../README.md) · پیش‌نیاز پیشنهادی: فصل ۱ و مبانی برنامه‌نویسی

## پیش‌نیازها و نقشهٔ ذهنی

سینتکس، تابع، شرط و حلقهٔ زبان منتخب. ابتدا مفهوم را به‌عنوان یک قرارداد ببین، سپس نمایش حافظه و عملیات را دنبال کن. هدف حفظ‌کردن نام نیست؛ باید بتوانی برای یک ورودی کوچک، state را بعد از هر گام بنویسی.

## ایده از پایه

تمرین‌های کوتاه Edabit برای روان‌شدن در syntax، تبدیل ورودی، شرط و مسئله‌های کوچک مفیدند. آن را مرحلهٔ تسلط بر زبان و بازخورد سریع ببین؛ جای تحلیل ساختار داده یا تمرین الگوریتم‌های بزرگ را نمی‌گیرد.

## مدل، قرارداد و ناوردا

برای هر تمرین: قرارداد ورودی/خروجی را دقیق بخوان؛ یک مثال و edge case بساز؛ تابع خالص و کوتاه طراحی کن؛ بعد از قبولی کد را ساده و قابل‌خواندن کن. سطح دشواری را تدریجی بالا ببر و اشتباه‌ها را در دفترچهٔ الگو ثبت کن.

ناوردا (invariant) جمله‌ای است که در تمام مراحل الگوریتم باید درست بماند. نوشتن آن پیش از کدنویسی، هم به اثبات درستی کمک می‌کند و هم خطاهای مرزی را آشکار می‌سازد.

## الگوریتم یا عملیات گام‌به‌گام

نمونه: تشخیص زوج‌بودن n: ورودی integer، خروجی boolean؛ شرط `n % 2 == 0` برای صفر و منفی نیز درست است. تست‌ها را خودت اضافه کن: 0، 1، −2. سپس قرارداد زبان دربارهٔ integer، division و null را بررسی کن.

در پیاده‌سازی واقعی، قرارداد ورودی/خروجی را دقیق تعریف کن: رفتار ورودی تهی، مقدار تکراری، عنصر پیدا‌نشده و ظرفیت تمام‌شده باید روشن باشد.

## اجرای حل‌شده با ردگیری

تابع sumArray: آیا آرایهٔ خالی باید 0 بدهد؟ اگر صورت مسئله این قرارداد را دارد، accumulator را 0 بگذار و loop کن. اگر نوع‌ها یا null مجازند، رفتار جدا تعریف کن. مسئلهٔ کوتاه هم specification دارد و حدس‌زدن قرارداد اشتباه است.

برای تمرین، جدولی با ستون‌های «گام»، «اندیس/اشاره‌گر»، «بخش فعال»، «تغییر state» و «دلیل» بساز. این روش به‌خصوص برای الگوریتم‌های درجا و تقسیم‌و‌غلبه جلوی پرش ذهنی را می‌گیرد.

## چرا درست است؟

برای loopی که accumulator دارد، پیش از دور i، accumulator باید برابر نتیجهٔ ترکیب عناصر قبلی باشد؛ پس از پایان، همهٔ عناصر پردازش شده‌اند. حتی مسئلهٔ بسیار ساده را می‌توان با چنین invariantی توضیح داد.

اثبات معمولاً سه بخش دارد: (۱) آغاز—ناوردا پیش از نخستین گام درست است؛ (۲) نگهداری—هر گام آن را حفظ می‌کند؛ (۳) پایان—شرط توقف همراه invariant جواب موردنیاز را نتیجه می‌دهد. اگر یکی از این سه بخش نامشخص است، هنوز درک الگوریتم کامل نشده است.

## تحلیل زمان و حافظه

اکثر چالش‌های آغازین complexity کوچکی دارند؛ برای آرایه n عضوی یک pass O(n) و O(1) فضاست. روی رشته، هزینهٔ ساخت رشتهٔ immutable می‌تواند با الحاق مکرر O(n²) شود؛ از builder مناسب زبان استفاده کن.

در Big-O ورودی را تعریف کن (مثلاً n تعداد عناصر)، نوع حالت را نام ببر (بهترین/میانگین/بدترین)، و فضای کمکی را از حافظهٔ خود ورودی جدا کن. مرتبهٔ رشد زمان واقعی بر حسب ثانیه نیست؛ cache، تخصیص حافظه و ثابت‌های پیاده‌سازی هم اثر دارند.

## کاربرد واقعی و انتخاب مناسب

micro-practice سرعت و تسلط سینتکس می‌سازد؛ در کار روزمره، خوانایی، naming، error behavior و آزمون واحد هم‌وزن کوتاهی کد هستند. خروجی یک خطی لزوماً بهترین کد نیست.

پیش از انتخاب بپرس: چه عملیاتی پرتکرارند؟ آیا ترتیب مهم است؟ دادهٔ ورودی چه اندازه است؟ آیا محدودیت حافظه، latency بدترین‌حالت یا thread-safety داریم؟ ساختار خوب برای workload نامناسب می‌تواند انتخاب بدی باشد.

## خطاهای رایج و edge caseها

فقط happy path را حل نکن. تفاوت truthy/falsy، division منفی، Unicode، mutable/immutable و overflow به زبان وابسته است. از clever one-linerی که edge case را پنهان می‌کند پرهیز کن.

حالت‌های مرزی را جداگانه بررسی کن: ورودی خالی، یک عضو، همهٔ اعضا برابر، هدف غایب، حداقل/حداکثر مقدار و اندازهٔ بزرگ. سرریز عدد صحیح در محاسبهٔ اندیس/ظرفیت نیز بسته به زبان مهم است.

## تمرین‌های مرحله‌ای

۱) برای هر تمرین چهار تست مرزی خودت اضافه کن. ۲) نسخهٔ خوانا و سپس نسخهٔ مختصر بنویس و تفاوت فهم‌پذیری را مقایسه کن. ۳) یک تمرین را با زبان دوم حل و تفاوت semantics را یادداشت کن.

برای هر تمرین، اول پاسخ ساده و درست بنویس، بعد پیچیدگی را حساب کن، سپس edge case اضافه کن. تمرین را با دست‌کم یک ورودی کوچک ردگیری کن و خروجی را با انتظار مستقل مقایسه کن.

## آزمون جامع با پاسخ تشریحی

ابتدا پاسخ‌ها را نخوان؛ جواب را با استدلال بنویس، سپس توضیح را مقایسه کن.

1. **پرسش:** Edabit برای چه مناسب است؟
   **پاسخ تشریحی:** تمرین‌های کوتاه syntax و مهارت پایه.
2. **پرسش:** چرا قرارداد خروجی مهم است؟
   **پاسخ تشریحی:** مثلاً جمع آرایهٔ خالی ممکن است تعریف خاص داشته باشد.
3. **پرسش:** حلقهٔ accumulator چه invariantی دارد؟
   **پاسخ تشریحی:** تا هر گام نتیجه برابر ترکیب prefix پردازش‌شده است.
4. **پرسش:** الحاق رشتهٔ immutable در حلقه چه خطری دارد؟
   **پاسخ تشریحی:** ممکن است کپی‌های پیاپی و هزینهٔ O(n²) ایجاد کند.
5. **پرسش:** قبولی تمرین کافی است؟
   **پاسخ تشریحی:** نه؛ edge case، readability و complexity را نیز مرور کن.

## راهنمای بازگویی از حافظه

بدون نگاه به متن، ایده، پیش‌شرط، invariant، یک ردگیری واقعی، پیچیدگی، edge case و یک کاربرد را در چند دقیقه روی کاغذ توضیح بده. اگر فقط pseudocode را حفظی می‌نویسی اما دلیل درستی یا محدودیت‌ها را نمی‌دانی، یک بار دیگر بخش‌های invariant و خطاها را مرور کن.
