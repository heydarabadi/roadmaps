# کارگاه مدل‌سازی

> **نسخهٔ انگلیسی:** [English edition](../../../../en/mongodb/labs/03-modeling/README.md).

## نیازها

یک فروشگاه باید صفحهٔ محصول، سبد خرید، checkout، فهرست سفارش‌های مشتری و invoice تاریخی داشته باشد.

## طراحی پیشنهادی و دلیل

- products: ویژگی‌های کوچک و متغیر محصول embed؛ برای SKU index یکتا.
- customers: اطلاعات پایهٔ مشتری؛ سفارش‌ها داخل آرایهٔ او نگهداری نشوند.
- carts: سند محدود به سبد جاری؛ اقلام با سقف یا کنترل رشد.
- orders: customerId reference؛ آدرس و قیمت زمان خرید snapshot؛ اقلام محدود با تعداد مشخص.
- events: رخدادهای پرتعداد یا تاریخچهٔ نامحدود در collection جدا با entityId و زمان.

## پرسش‌های بررسی

1. کدام فیلدها در query محصول با هم خوانده می‌شوند؟
2. آیا ویژگی هر دسته محصول یکسان است؟ اگر نه، چه validation لازم است؟
3. اگر محصول حذف شود، invoice قدیمی چگونه حفظ می‌شود؟
4. برای تغییر سفارش و موجودی، آیا transaction لازم است یا الگوی رزرو مناسب‌تر است؟
5. کدام queryها نیاز به compound index دارند؟

## پاسخ‌نامهٔ راهنما

- مدل از روی query و lifecycle ساخته شود.
- قیمت و عنوان زمان خرید در order snapshot شوند.
- تاریخچهٔ نامحدود به آرایهٔ والد اضافه نشود.
- consistency و concurrency در موجودی جداگانه تحلیل شود.
- index فقط بعد از query shape و sort تعریف و سپس اندازه‌گیری شود.
