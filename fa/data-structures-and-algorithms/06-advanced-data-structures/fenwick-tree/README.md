# درخت فنویک (BIT)

> نسخهٔ انگلیسی: [English version](../../../../en/data-structures-and-algorithms/06-advanced-data-structures/fenwick-tree/README.md)

> مسیر: [فصل ۶ — ساختمان‌های دادهٔ پیشرفته](../README.md) · پیش‌نیاز پیشنهادی: فصل ۱ و مبانی برنامه‌نویسی

## پیش‌نیازها و نقشهٔ ذهنی

آرایه، prefix sum و عملیات bitwise. ابتدا مفهوم را به‌عنوان یک قرارداد ببین، سپس نمایش حافظه و عملیات را دنبال کن. هدف حفظ‌کردن نام نیست؛ باید بتوانی برای یک ورودی کوچک، state را بعد از هر گام بنویسی.

## ایده از پایه

Fenwick tree جمع prefix را با نگهداری بلوک‌هایی با اندازه‌های توانی از دو در O(log n) می‌دهد. هر خانه بخشی از آرایه را پوشش می‌دهد و بیت کم‌ارزش index اندازهٔ بلوک آن را مشخص می‌کند.

## مدل، قرارداد و ناوردا

نسخهٔ رایج 1-based: `lowbit(i)=i & -i`. خانهٔ bit[i] جمع بازهٔ [i−lowbit(i)+1,i] را نگه می‌دارد. prefix sum از i شروع و با `i -= lowbit(i)` از بلوک‌ها عبور می‌کند؛ update نقطه‌ای با `i += lowbit(i)` همهٔ بلوک‌های شامل موقعیت را اصلاح می‌کند.

ناوردا (invariant) جمله‌ای است که در تمام مراحل الگوریتم باید درست بماند. نوشتن آن پیش از کدنویسی، هم به اثبات درستی کمک می‌کند و هم خطاهای مرزی را آشکار می‌سازد.

## الگوریتم یا عملیات گام‌به‌گام

query(i): sum=0؛ تا i>0: sum+=bit[i]؛ i-=lowbit(i). add(i,delta): تا i≤n: bit[i]+=delta؛ i+=lowbit(i). rangeSum(l,r)=query(r)-query(l-1).

در پیاده‌سازی واقعی، قرارداد ورودی/خروجی را دقیق تعریف کن: رفتار ورودی تهی، مقدار تکراری، عنصر پیدا‌نشده و ظرفیت تمام‌شده باید روشن باشد.

## اجرای حل‌شده با ردگیری

آرایهٔ [3,2,−1,6] با index یک‌مبنا. add(3,+4) مقدار سوم را از −1 به 3 می‌رساند. query(3) باید 3+2+3=8 دهد؛ بلوک‌های bit که با جداکردن lowbit پیموده می‌شوند مجموع را بدون دیدن هر عنصر می‌سازند.

برای تمرین، جدولی با ستون‌های «گام»، «اندیس/اشاره‌گر»، «بخش فعال»، «تغییر state» و «دلیل» بساز. این روش به‌خصوص برای الگوریتم‌های درجا و تقسیم‌و‌غلبه جلوی پرش ذهنی را می‌گیرد.

## چرا درست است؟

هر bit[i] دقیقاً مجموع بازهٔ پوشش‌داده‌شدهٔ خودش است. update مقدار نقطه را به تمام بلوک‌هایی اضافه می‌کند که آن index را شامل‌اند؛ query بازه‌های مجزا و بی‌هم‌پوشانی را جمع می‌کند تا prefix کامل شود.

اثبات معمولاً سه بخش دارد: (۱) آغاز—ناوردا پیش از نخستین گام درست است؛ (۲) نگهداری—هر گام آن را حفظ می‌کند؛ (۳) پایان—شرط توقف همراه invariant جواب موردنیاز را نتیجه می‌دهد. اگر یکی از این سه بخش نامشخص است، هنوز درک الگوریتم کامل نشده است.

## تحلیل زمان و حافظه

نقطه‌ای update و prefix/range sum O(log n)، حافظه O(n). برای range update/point query یا range update/range sum از دو BIT استفاده می‌شود. الگوریتم به عملگر جمع‌پذیر/گروه مناسب وابسته است؛ max عمومی با کاهش مقدار به‌سادگی قابل پشتیبانی نیست.

در Big-O ورودی را تعریف کن (مثلاً n تعداد عناصر)، نوع حالت را نام ببر (بهترین/میانگین/بدترین)، و فضای کمکی را از حافظهٔ خود ورودی جدا کن. مرتبهٔ رشد زمان واقعی بر حسب ثانیه نیست؛ cache، تخصیص حافظه و ثابت‌های پیاده‌سازی هم اثر دارند.

## کاربرد واقعی و انتخاب مناسب

شمارش prefix، inversion count با coordinate compression، frequency table پویا و cumulative distribution. برای پرس‌وجوی مجموع نقطه‌ای، از segment tree سبک‌تر و ساده‌تر است.

پیش از انتخاب بپرس: چه عملیاتی پرتکرارند؟ آیا ترتیب مهم است؟ دادهٔ ورودی چه اندازه است؟ آیا محدودیت حافظه، latency بدترین‌حالت یا thread-safety داریم؟ ساختار خوب برای workload نامناسب می‌تواند انتخاب بدی باشد.

## خطاهای رایج و edge caseها

index صفر در نسخهٔ 1-based وارد حلقهٔ بی‌پایان می‌شود چون lowbit(0)=0؛ ورودی را به 1..n تبدیل کن. lowbit به مکمل دو و نمایش صحیح وابسته است. update برابر set نیست؛ باید delta بدهی.

حالت‌های مرزی را جداگانه بررسی کن: ورودی خالی، یک عضو، همهٔ اعضا برابر، هدف غایب، حداقل/حداکثر مقدار و اندازهٔ بزرگ. سرریز عدد صحیح در محاسبهٔ اندیس/ظرفیت نیز بسته به زبان مهم است.

## تمرین‌های مرحله‌ای

۱) lowbit(12)، lowbit(10) را محاسبه کن. ۲) یک update و سه prefix query را جدول‌کشی کن. ۳) برای شمارش تعداد اعداد کوچک‌تر از x، coordinate compression را با Fenwick ترکیب کن.

برای هر تمرین، اول پاسخ ساده و درست بنویس، بعد پیچیدگی را حساب کن، سپس edge case اضافه کن. تمرین را با دست‌کم یک ورودی کوچک ردگیری کن و خروجی را با انتظار مستقل مقایسه کن.

## آزمون جامع با پاسخ تشریحی

ابتدا پاسخ‌ها را نخوان؛ جواب را با استدلال بنویس، سپس توضیح را مقایسه کن.

1. **پرسش:** lowbit(i) چیست؟
   **پاسخ تشریحی:** i & -i؛ پایین‌ترین بیت یکِ i.
2. **پرسش:** query چگونه حرکت می‌کند؟
   **پاسخ تشریحی:** i را هر بار به اندازهٔ lowbit کم می‌کند.
3. **پرسش:** update چگونه حرکت می‌کند؟
   **پاسخ تشریحی:** i را هر بار به اندازهٔ lowbit زیاد می‌کند.
4. **پرسش:** هزینه؟
   **پاسخ تشریحی:** O(log n) برای update و prefix sum.
5. **پرسش:** update چه ورودی‌ای می‌خواهد؟
   **پاسخ تشریحی:** delta نسبت به مقدار فعلی، نه مقدار جایگزین.
