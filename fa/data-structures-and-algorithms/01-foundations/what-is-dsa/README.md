# ساختمان داده و الگوریتم چیست؟

> مسیر: [فصل ۱ — پایه‌ها و تحلیل الگوریتم](../README.md) · پیش‌نیاز پیشنهادی: فصل ۱ و مبانی برنامه‌نویسی · [English](../../../../en/data-structures-and-algorithms/01-foundations/what-is-dsa/README.md)

## پیش‌نیازها و نقشهٔ ذهنی

ورودی، خروجی و تابع. ابتدا مفهوم را به‌عنوان یک قرارداد ببین، سپس نمایش حافظه و عملیات را دنبال کن. هدف حفظ‌کردن نام نیست؛ باید بتوانی برای یک ورودی کوچک، state را بعد از هر گام بنویسی.

## ایده از پایه

ساختمان داده سازمان‌دهی داده و مجموعهٔ عملیات آن است؛ الگوریتم دستور محدود و دقیق برای تبدیل ورودی معتبر به خروجی موردنیاز. هر کدام انتخاب دیگری را تحت تأثیر می‌گذارد: آرایه دسترسی سریع index می‌دهد ولی درج وسط را گران می‌کند؛ hash map lookup را سریع می‌کند ولی ترتیب را الزاماً حفظ نمی‌کند.

## مدل، قرارداد و ناوردا

ADT (نوع دادهٔ انتزاعی) قرارداد عملیات مانند push/pop است؛ پیاده‌سازی با آرایه، لیست یا representation دیگر انجام می‌شود. الگوریتم correctness، termination و cost دارد. مسئله را با domain، constraints و output دقیق مدل کن.

ناوردا (invariant) جمله‌ای است که در تمام مراحل الگوریتم باید درست بماند. نوشتن آن پیش از کدنویسی، هم به اثبات درستی کمک می‌کند و هم خطاهای مرزی را آشکار می‌سازد.

## الگوریتم یا عملیات گام‌به‌گام

برای دفترچهٔ مخاطب: key=شمارهٔ تلفن، value=نام/رکورد. اگر lookup بر شماره زیاد و ترتیب مهم نیست، hash map؛ اگر range/order query لازم است, ordered tree/index. الگوریتم lookup روی ساختار متناسب اجرا می‌شود.

در پیاده‌سازی واقعی، قرارداد ورودی/خروجی را دقیق تعریف کن: رفتار ورودی تهی، مقدار تکراری، عنصر پیدا‌نشده و ظرفیت تمام‌شده باید روشن باشد.

## اجرای حل‌شده با ردگیری

یک فهرست نام 8تایی را یک بار جست‌وجو می‌کنی: linear scan ساده و کافی. صد میلیون query روی فهرست ثابت و مرتب: sort/index هزینهٔ اولیه دارد اما هر query را سریع می‌کند. نرخ read/write بخشی از تصمیم است.

برای تمرین، جدولی با ستون‌های «گام»، «اندیس/اشاره‌گر»، «بخش فعال»، «تغییر state» و «دلیل» بساز. این روش به‌خصوص برای الگوریتم‌های درجا و تقسیم‌و‌غلبه جلوی پرش ذهنی را می‌گیرد.

## چرا درست است؟

یک راه‌حل کامل ورودی/خروجی و شرایط معتبر را تعریف می‌کند؛ ادعای correctness با invariant/proof پشتیبانی می‌شود؛ ادعای کارایی با تحلیل زمان/فضا. موفقیت روی یک نمونه اثبات نیست.

اثبات معمولاً سه بخش دارد: (۱) آغاز—ناوردا پیش از نخستین گام درست است؛ (۲) نگهداری—هر گام آن را حفظ می‌کند؛ (۳) پایان—شرط توقف همراه invariant جواب موردنیاز را نتیجه می‌دهد. اگر یکی از این سه بخش نامشخص است، هنوز درک الگوریتم کامل نشده است.

## تحلیل زمان و حافظه

تحلیل رشد با n، m، V، E جداگانه؛ زمان و فضای کمکی. trade-off ساختار بر عملیات پرتکرار بناست. پیاده‌سازی واقعی cache، disk I/O، allocation، concurrency و constants را هم وارد تصمیم می‌کند.

در Big-O ورودی را تعریف کن (مثلاً n تعداد عناصر)، نوع حالت را نام ببر (بهترین/میانگین/بدترین)، و فضای کمکی را از حافظهٔ خود ورودی جدا کن. مرتبهٔ رشد زمان واقعی بر حسب ثانیه نیست؛ cache، تخصیص حافظه و ثابت‌های پیاده‌سازی هم اثر دارند.

## کاربرد واقعی و انتخاب مناسب

پایگاه‌داده index، صف پیام، cache، نقشه/route و کامپایلر tree مثال‌های کاربردی‌اند؛ اما مسئلهٔ واقعی علاوه بر الگوریتم، reliability و failure behavior نیز دارد.

پیش از انتخاب بپرس: چه عملیاتی پرتکرارند؟ آیا ترتیب مهم است؟ دادهٔ ورودی چه اندازه است؟ آیا محدودیت حافظه، latency بدترین‌حالت یا thread-safety داریم؟ ساختار خوب برای workload نامناسب می‌تواند انتخاب بدی باشد.

## خطاهای رایج و edge caseها

ساختمان داده را با ADT و algorithm قاطی نکن. binary search بدون sorted input معتبر نیست. O(1) را بدون average/worst qualifier ننویس. انتخاب بر اساس شهرت به‌جای workload نکن.

حالت‌های مرزی را جداگانه بررسی کن: ورودی خالی، یک عضو، همهٔ اعضا برابر، هدف غایب، حداقل/حداکثر مقدار و اندازهٔ بزرگ. سرریز عدد صحیح در محاسبهٔ اندیس/ظرفیت نیز بسته به زبان مهم است.

## تمرین‌های مرحله‌ای

۱) عملیات پرتکرار دفترچه، صف پیام و history را تعیین کن. ۲) برای هرکدام structure و trade-off انتخاب کن. ۳) ورودی/خروجی و invariant یک مسئلهٔ سادهٔ membership را بنویس.

برای هر تمرین، اول پاسخ ساده و درست بنویس، بعد پیچیدگی را حساب کن، سپس edge case اضافه کن. تمرین را با دست‌کم یک ورودی کوچک ردگیری کن و خروجی را با انتظار مستقل مقایسه کن.

## آزمون جامع با پاسخ تشریحی

ابتدا پاسخ‌ها را نخوان؛ جواب را با استدلال بنویس، سپس توضیح را مقایسه کن.

1. **پرسش:** Data Structure چیست؟
   **پاسخ تشریحی:** سازمان‌دهی و عملیات داده.
2. **پرسش:** Algorithm چیست؟
   **پاسخ تشریحی:** مراحل محدود و دقیق برای حل مسئله.
3. **پرسش:** ADT چیست؟
   **پاسخ تشریحی:** قرارداد عملیات مستقل از پیاده‌سازی.
4. **پرسش:** چرا workload مهم است؟
   **پاسخ تشریحی:** هزینه و مزیت هر ساختار بر عملیات مختلف فرق دارد.
5. **پرسش:** یک مثال پیش‌شرط؟
   **پاسخ تشریحی:** Binary search دادهٔ مرتب می‌خواهد.

## راهنمای بازگویی از حافظه

بدون نگاه به متن، ایده، پیش‌شرط، invariant، یک ردگیری واقعی، پیچیدگی، edge case و یک کاربرد را در چند دقیقه روی کاغذ توضیح بده. اگر فقط pseudocode را حفظی می‌نویسی اما دلیل درستی یا محدودیت‌ها را نمی‌دانی، یک بار دیگر بخش‌های invariant و خطاها را مرور کن.
