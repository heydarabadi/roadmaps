# 12-Week Go Study Route

This plan assumes about 60–90 minutes a day, five days a week. It is a pacing estimate, not a deadline. Each week includes review and a practical output. Try quizzes before opening their keys; explain answers from memory rather than memorizing answer numbers. Local Markdown lessons and code examples are enough for offline study; external links are optional deep reading and version checks.

## Week 1 — Introduction and environment

**Lessons:** [Introduction and history](01-شروع-و-ابزار/01-معرفی-go/README.en.md), [installation and Hello World](01-شروع-و-ابزار/02-نصب-و-hello-world/README.en.md), [commands and docs](01-شروع-و-ابزار/03-فرمان-و-docs/README.en.md).

- Day 1: Go's design goals and suitable workloads; take the introduction quiz.
- Day 2: Install Go, inspect PATH, workspace, and toolchain version.
- Day 3: Run and build a small program; explain source versus executable.
- Day 4: Review package/module concepts and everyday commands.
- Day 5: Recreate Hello World from memory and explain run/build/fmt.

**Deliverable:** A personal setup note with OS, install path, run/build/test/doc commands, and two reasons Go does or does not fit a sample project.

## Week 2 — Variables, types, and composite data

**Lessons:** [Variables and constants](02-مبانی-زبان/01-variables-constants/README.en.md), [types and conversions](02-مبانی-زبان/02-types-conversion/README.en.md), [arrays and slices](03-ساختار-داده/01-arrays-slices/README.en.md), [strings](03-ساختار-داده/02-strings/README.en.md), [maps](03-ساختار-داده/03-maps-comma-ok/README.en.md), [structs](03-ساختار-داده/04-struct-tags-embedding/README.en.md).

- Day 1: Zero values, scope, shadowing, and constants.
- Day 2: Integers, overflow, floats, and explicit conversions.
- Day 3: Draw array/slice backing storage, length/capacity, and aliasing.
- Day 4: Explain UTF-8/rune/grapheme, maps, and comma-ok.
- Day 5: Structs, JSON tags, embedding, and the quizzes.

**Deliverable:** A small library model with Book records, an ID map, search, and JSON output. Deliberately check what happens when aliased slices are edited.

## Week 3 — Control flow and functions

**Lessons:** [Conditionals and loops](04-کنترل-و-توابع/01-loops-conditionals/README.en.md), [functions and closures](04-کنترل-و-توابع/02-functions-closures/README.en.md).

- Day 1: if/switch/for and guard clauses.
- Day 2: range over strings/maps and unspecified map order.
- Day 3: Multiple results and explicit error returns.
- Day 4: Variadics, function values, closures, and call-by-value.
- Day 5: Solve lesson exercises and write a small input parser with manual cases.

**Deliverable:** A cost summarizer with independent functions and boundary inputs.

## Week 4 — Pointers, methods, and interfaces

**Lessons:** [Pointers and GC](05-pointer-memory/01-pointers-memory-gc/README.en.md), [methods and interfaces](06-متد-interface-generics/01-methods-interfaces/README.en.md).

- Day 1: Address, dereference, nil, and struct copies.
- Day 2: Aliasing, escape analysis, and garbage collector responsibilities.
- Day 3: Value/pointer receivers and method sets.
- Day 4: Implicit interfaces, assertions, typed nil, and embedding.
- Day 5: Design a small package API and choose a practical fake/mock.

**Deliverable:** A wallet model with clear methods; test whether mutation is expected from each receiver.

## Week 5 — Generics and modules

**Lessons:** [Generics](06-متد-interface-generics/02-generics/README.en.md), [packages and modules](07-packages-modules/01-packages-modules/README.en.md).

- Day 1: Type parameters and the duplication problem they can solve.
- Day 2: Constraints, type sets, unions, and inference.
- Day 3: Generic types/methods and minimum Go version requirements.
- Day 4: go.mod, tidy, imports, and dependencies.
- Day 5: Create a small module, review its package API, and take the quizzes.

**Deliverable:** Add a generic helper only when multiple types need the same abstraction; otherwise keep concrete code and explain the tradeoff.

## Week 6 — Errors and panic

**Lessons:** [Error handling](08-error-resilience/01-errors/README.en.md), [panic/defer/recover](08-error-resilience/02-panic-defer-recover/README.en.md).

- Day 1: Error values, context, and wrapping.
- Day 2: Is/As, sentinel/type errors, and error translation boundaries.
- Day 3: defer and cleanup.
- Day 4: Panic versus ordinary failure and where recovery belongs.
- Day 5: Analyze retries with deadlines, backoff, and budgets.

**Deliverable:** A config reader that preserves path and cause while treating ordinary errors without panicking.

## Week 7 — Basic concurrency and lifecycle

**Lessons:** [Goroutines and channels](09-concurrency/01-goroutines-channels/README.en.md), [sync and context](09-concurrency/02-sync-context/README.en.md).

- Day 1: Goroutines, channels, and ownership.
- Day 2: Buffered/unbuffered channels and select.
- Day 3: Mutex and WaitGroup; identify which state each protects or waits for.
- Day 4: Cancellation, deadlines, and propagation.
- Day 5: Draw a request and worker lifecycle.

**Deliverable:** A small parallel calculation with cancellation and complete goroutine cleanup.

## Week 8 — Concurrency patterns and races

**Lessons:** [Worker pools and pipelines](09-concurrency/03-worker-pool-pipeline/README.en.md), [race detector](09-concurrency/04-race-detector/README.en.md).

- Day 1: A bounded worker pool and concurrency limit.
- Day 2: Fan-in/fan-out and backpressure.
- Day 3: Pipeline cancellation and channel-close ownership.
- Day 4: Data races, test coverage, and race detection.
- Day 5: Reproduce, diagnose, and explain one failure mode.

**Deliverable:** A stoppable pipeline with correct channel closing and clear ownership for each goroutine.

## Week 9 — Tests and benchmarks

**Lessons:** [Tests and httptest](10-testing/01-testing-httptest/README.en.md), [benchmarks and coverage](10-testing/02-benchmarks-coverage/README.en.md).

- Day 1: Test functions, helpers, and table-driven cases.
- Day 2: Fake/stub/mock and the least costly appropriate test double.
- Day 3: Test a handler with a recorder and a client with a test server.
- Day 4: Benchmarks, allocations, coverage, and fuzzing.
- Day 5: Write a test plan for a project and identify likely mutations.

**Deliverable:** Tests for success, invalid input, dependency failure, and cancellation.

## Week 10 — Standard library

**Lesson:** [Standard library, I/O, JSON, and time](11-standard-library/01-stdlib-io-json-time/README.en.md).

- Day 1: io.Reader/Writer, files, input limits, and close.
- Day 2: os, flag, and environment.
- Day 3: JSON encoding/decoding and validation.
- Day 4: bufio, regexp, slog, embed, and time.
- Day 5: Compare Go 1.27 JSON v2 conceptually with v1 and take the lesson quiz.

**Deliverable:** A small file tool with an input limit, contextual errors, and structured logs.

## Week 11 — Ecosystem and external APIs

**Lesson:** [Libraries, HTTP/RPC/DB/CLI](12-اکوسیستم/01-کتابخانه-های-اکوسیستم/README.en.md).

- Day 1: net/http and optional frameworks.
- Day 2: CLI libraries and dependency selection.
- Day 3: gRPC/Protobuf and schema versioning.
- Day 4: database/sql, pgx, and ORMs.
- Day 5: Logging, WebSockets, and operational tradeoffs.

**Deliverable:** Define the API contract and error mapping for the API project; sketch a standard-library version before choosing a framework.

## Week 12 — Quality, runtime, and review

**Lessons:** [Toolchain, security, and deployment](13-toolchain-امنیت/01-tooling-security-deploy/README.en.md), [advanced topics](14-مباحث-پیشرفته/01-advanced-runtime/README.en.md).

- Day 1: fmt, vet, test, build, and versioned linters.
- Day 2: govulncheck, build tags, and code generation.
- Day 3: Cross-compilation, artifacts, and graceful shutdown.
- Day 4: pprof/trace, reflection, unsafe, cgo, and compiler/linker flags.
- Day 5: Review all three projects and finish one to a demonstrable rubric.

**Deliverable:** A project with run instructions, explained test approach, limitations, an architecture decision, and profile/benchmark evidence when relevant.

## Spaced review and completion checklist

Every Friday, review terms in the [glossary](واژه‌نامه.en.md) and answer from memory: What is the concept? When is it suitable? What can fail? What is a real or test example? Revisit missed quiz questions after one day and one week. Explain the reasoning; remembering the answer number is not evidence of learning.

- [ ] I can explain packages, modules, and core Go commands.
- [ ] I understand arrays, slices, maps, structs, and aliasing effects.
- [ ] I can distinguish functions, methods, pointers, and interfaces with examples.
- [ ] I can wrap errors and translate them at an appropriate boundary.
- [ ] I can reason about goroutine lifecycle, channel closing, cancellation, and backpressure.
- [ ] I can select tests, benchmarks, and diagnostic tools for a question.
- [ ] I can explain HTTP/database/CLI boundaries and input security.
- [ ] I know when unsafe, cgo, or optimization can be justified.
- [ ] I have run, tested, and documented the limits of one final project.
