# فصل ۱۰ — شبکه و مسیر تحویل پاسخ

**زبان:** فارسی · [نسخهٔ انگلیسی](README.en.md)  

کارایی شبکه فقط سرعت لینک نیست: تعداد رفت‌وبرگشت، محل وابستگی‌ها، ساخت اتصال، حجم انتقال و پاسخ صحیح از کش روی زمان کاربر اثر دارند. این فصل چهار موضوع Network در [نقشه راه Backend Performance](https://roadmap.sh/backend-performance-best-practices) را پوشش می‌دهد. تاریخ بررسی منابع: **۲۰۲۶-۱۱-۱۱؛ تکمیل آموزشی: ۲۰۲۶-۱۱-۱۱**. اصطلاح‌ها و روش محاسبه در خود درس‌ها آمده‌اند؛ لینک بیرونی برای فهم تمرین لازم نیست و فقط مطالعهٔ اختیاری/مرجع فنی است. همه عددهای تمرین فرضی‌اند؛ هیچ آزمایش شبکه یا تغییر زیرساخت در این مجموعه اجرا نشده است.

## پیش‌نیاز و مسیر مطالعه

آشنایی مقدماتی با درخواست و پاسخ وب کافی است. **RTT** زمان رفت‌وبرگشت، **Bandwidth** ظرفیت انتقال و **Throughput** نرخ مشاهده‌شده‌اند؛ **TLS** کانال ارتباطی را امن می‌کند و **DNS** نام میزبان را به مقصد قابل اتصال نگاشت می‌کند. هر اصطلاح و محدودیت نسخهٔ پروتکل در درس مربوط باز می‌شود. TTFB علاوه بر شبکه ممکن است صف و پردازش سرور را در بر بگیرد؛ Ping به‌تنهایی کیفیت API را ثابت نمی‌کند.

ابتدا خط مبنا را از دید کاربر و به تفکیک منطقه/ISP، Route و اندازه پاسخ بگیرید. DNS، اتصال/TLS، TTFB و انتقال بدنه را جدا کنید؛ سپس Trace برنامه و وابستگی‌ها را کنار آن بگذارید. هر بار یک تغییر را با ترافیک نماینده، خطا، هزینه و tail latency مقایسه کنید. تصمیم منطقه، پروتکل یا CDN را فقط از روی یک میانگین نگیرید.

## سناریوی پیونددهنده

در فروشگاه **فرضی**، عکس‌ها و فونت عمومی‌اند ولی سفارش‌ها شخصی‌اند. انتقال API به نزدیک کاربر ممکن است با DB دور، سه رفت‌وبرگشت جدید بسازد. اول محل داده و مسیر checkout را تحلیل کنید؛ سپس Client طول‌عمر مناسب و Pool محدود بسازید. عکس نسخه‌دار را روی CDN قرار دهید و پاسخ سفارش را از کش مشترک خارج کنید. فقط فونت حیاتی همین صفحه را Preload و یک منبع عمومی محتمل برای صفحه بعد را با بودجه محدود Prefetch کنید. موفقیت یعنی پاسخ درست، تأخیر کمتر و هزینه قابل‌قبول؛ hit بیشتر یا اتصال کمتر به‌تنهایی کافی نیست.

## چک‌لیست پایان فصل

- [ ] RTT، TTFB، زمان بدنه و صف/پردازش با مرز مشخص سنجیده شده‌اند.
- [ ] جای کاربر، API و وابستگی‌ها و هزینه انتقال بین مناطق مشخص است.
- [ ] نسخه HTTP در هر hop و محدودیت Pool/Stream معلوم است.
- [ ] پاسخ شخصی، کلید کش، TTL و ابطال CDN قرارداد دارند.
- [ ] Prefetch احتمال مصرف، سقف بایت و رفتار هنگام اشباع دارد.
- [ ] اثر تغییر بر p99، خطا، ترافیک و صحت بررسی می‌شود.
