# نمایه‌سازی درختی

> نسخهٔ انگلیسی: [English version](../../../../en/data-structures-and-algorithms/07-complex-structures-and-indexing/tree-indexing/README.md)

> مسیر: [فصل ۷ — ساختارهای پیچیده و نمایه‌سازی](../README.md) · پیش‌نیاز پیشنهادی: فصل ۱ و مبانی برنامه‌نویسی

## پیش‌نیازها و نقشهٔ ذهنی

BST، B-tree/B+ tree و page I/O. ابتدا مفهوم را به‌عنوان یک قرارداد ببین، سپس نمایش حافظه و عملیات را دنبال کن. هدف حفظ‌کردن نام نیست؛ باید بتوانی برای یک ورودی کوچک، state را بعد از هر گام بنویسی.

## ایده از پایه

ایندکس درختی کلیدها را در nodeهای مرتب نگه می‌دارد تا جست‌وجو با هر سطح یک بازه را کنار بگذارد. در حافظهٔ اصلی BST متعادل ممکن است مناسب باشد؛ در storage block-based، درخت چندراهه fanout و locality را بالا می‌برد.

## مدل، قرارداد و ناوردا

هر internal node separator keys و child pointers دارد. جست‌وجو از root تا leaf می‌رود؛ range query lower bound تا upper bound را از leaf و siblingها می‌خواند. B-tree می‌تواند record/pointer در nodeهای داخلی داشته باشد؛ B+ tree معمولاً همهٔ رکوردها را در برگ دارد.

ناوردا (invariant) جمله‌ای است که در تمام مراحل الگوریتم باید درست بماند. نوشتن آن پیش از کدنویسی، هم به اثبات درستی کمک می‌کند و هم خطاهای مرزی را آشکار می‌سازد.

## الگوریتم یا عملیات گام‌به‌گام

Lookup: در هر node با binary search separator، child مناسب را پیدا کن و ادامه بده. Insert/delete: طبق occupancy، split یا redistribution/merge کن و separator را update کن. برای range scan، اولین leaf را پیدا و leaf chain را دنبال کن.

در پیاده‌سازی واقعی، قرارداد ورودی/خروجی را دقیق تعریف کن: رفتار ورودی تهی، مقدار تکراری، عنصر پیدا‌نشده و ظرفیت تمام‌شده باید روشن باشد.

## اجرای حل‌شده با ردگیری

برای کلید 37، ریشه separatorهای [20,50] دارد: چون 20≤37<50 به child میانی می‌رویم؛ در leaf [31,37,42] نتیجه پیدا می‌شود. query بازه [37,70] از همان leaf تا برگ‌های بعدی ادامه دارد.

برای تمرین، جدولی با ستون‌های «گام»، «اندیس/اشاره‌گر»، «بخش فعال»، «تغییر state» و «دلیل» بساز. این روش به‌خصوص برای الگوریتم‌های درجا و تقسیم‌و‌غلبه جلوی پرش ذهنی را می‌گیرد.

## چرا درست است؟

separator بازه‌های child را بدون ابهام تقسیم می‌کند؛ ترتیب کلیدها، حداقل/حداکثر occupancy و برگ‌های هم‌عمق حفظ می‌شوند. تغییر child ممکن است separator والد را نیز تغییر دهد.

اثبات معمولاً سه بخش دارد: (۱) آغاز—ناوردا پیش از نخستین گام درست است؛ (۲) نگهداری—هر گام آن را حفظ می‌کند؛ (۳) پایان—شرط توقف همراه invariant جواب موردنیاز را نتیجه می‌دهد. اگر یکی از این سه بخش نامشخص است، هنوز درک الگوریتم کامل نشده است.

## تحلیل زمان و حافظه

درخت متوازن binary O(log₂ n) گره می‌خواند؛ B-tree fanout f، O(log_f n) page access. range scan O(log_f n + output/pages). عدد I/O مهم‌تر از تعداد مقایسه CPU برای index دیسکی است.

در Big-O ورودی را تعریف کن (مثلاً n تعداد عناصر)، نوع حالت را نام ببر (بهترین/میانگین/بدترین)، و فضای کمکی را از حافظهٔ خود ورودی جدا کن. مرتبهٔ رشد زمان واقعی بر حسب ثانیه نیست؛ cache، تخصیص حافظه و ثابت‌های پیاده‌سازی هم اثر دارند.

## کاربرد واقعی و انتخاب مناسب

ایندکس پایگاه داده، storage engine و فایل‌سیستم. Query planner با cardinality/selectivity و هزینهٔ صفحه تصمیم می‌گیرد index scan بهتر است یا sequential scan.

پیش از انتخاب بپرس: چه عملیاتی پرتکرارند؟ آیا ترتیب مهم است؟ دادهٔ ورودی چه اندازه است؟ آیا محدودیت حافظه، latency بدترین‌حالت یا thread-safety داریم؟ ساختار خوب برای workload نامناسب می‌تواند انتخاب بدی باشد.

## خطاهای رایج و edge caseها

index همیشه سریع‌تر نیست؛ برای query کم‌انتخاب ممکن است sequential scan ارزان‌تر باشد. stale statistics و ترتیب نامناسب composite index performance را پایین می‌آورد. node size را با cache/page اندازه‌گیری کن.

حالت‌های مرزی را جداگانه بررسی کن: ورودی خالی، یک عضو، همهٔ اعضا برابر، هدف غایب، حداقل/حداکثر مقدار و اندازهٔ بزرگ. سرریز عدد صحیح در محاسبهٔ اندیس/ظرفیت نیز بسته به زبان مهم است.

## تمرین‌های مرحله‌ای

۱) مسیر lookup را برای مثال بنویس. ۲) leaf scan بازه‌ای را رسم کن. ۳) یک query بساز که full table scan از index بهتر باشد و دلیلش را بنویس.

برای هر تمرین، اول پاسخ ساده و درست بنویس، بعد پیچیدگی را حساب کن، سپس edge case اضافه کن. تمرین را با دست‌کم یک ورودی کوچک ردگیری کن و خروجی را با انتظار مستقل مقایسه کن.

## آزمون جامع با پاسخ تشریحی

ابتدا پاسخ‌ها را نخوان؛ جواب را با استدلال بنویس، سپس توضیح را مقایسه کن.

1. **پرسش:** هر node internal چه می‌دهد؟
   **پاسخ تشریحی:** separator و pointerهای child.
2. **پرسش:** چرا B-tree برای دیسک مناسب است؟
   **پاسخ تشریحی:** fanout بالا تعداد page level را کم می‌کند.
3. **پرسش:** range query چگونه ادامه می‌یابد؟
   **پاسخ تشریحی:** از lower-bound leaf تا upper bound با leaf links.
4. **پرسش:** آیا index scan همیشه بهتر است؟
   **پاسخ تشریحی:** خیر؛ selectivity پایین ممکن است sequential scan را بهتر کند.
5. **پرسش:** هزینهٔ اصلی در storage؟
   **پاسخ تشریحی:** page I/O و نگهداری index.

## راهنمای بازگویی از حافظه
