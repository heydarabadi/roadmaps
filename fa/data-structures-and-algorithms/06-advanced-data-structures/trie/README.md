# Trie یا درخت پیشوندی

> نسخهٔ انگلیسی: [English version](../../../../en/data-structures-and-algorithms/06-advanced-data-structures/trie/README.md)

> مسیر: [فصل ۶ — ساختمان‌های دادهٔ پیشرفته](../README.md) · پیش‌نیاز پیشنهادی: فصل ۱ و مبانی برنامه‌نویسی

## پیش‌نیازها و نقشهٔ ذهنی

درخت، آرایه/نقشه و رشته. ابتدا مفهوم را به‌عنوان یک قرارداد ببین، سپس نمایش حافظه و عملیات را دنبال کن. هدف حفظ‌کردن نام نیست؛ باید بتوانی برای یک ورودی کوچک، state را بعد از هر گام بنویسی.

## ایده از پایه

Trie پیشوند مشترک رشته‌ها را در مسیر ریشه تا گره اشتراک می‌گذارد. هر یال یک نماد است و marker پایان‌واژه مشخص می‌کند یک مسیر واقعاً واژهٔ درج‌شده است.

## مدل، قرارداد و ناوردا

برای alphabet ثابت، هر گره می‌تواند آرایهٔ فرزندها داشته باشد؛ برای alphabet بزرگ/تنک از map استفاده می‌شود. `isWord` جداست: مسیر `car` ممکن است پیشوند `cart` باشد ولی بدون marker، خود `car` را عضو مجموعه نمی‌دانیم.

ناوردا (invariant) جمله‌ای است که در تمام مراحل الگوریتم باید درست بماند. نوشتن آن پیش از کدنویسی، هم به اثبات درستی کمک می‌کند و هم خطاهای مرزی را آشکار می‌سازد.

## الگوریتم یا عملیات گام‌به‌گام

درج: از ریشه برای هر character فرزند بساز/بگیر؛ در پایان isWord=true. جست‌وجو: مسیر هر character را دنبال کن؛ اگر فرزند نبود false؛ در انتها isWord را برگردان. prefix query فقط رسیدن به گرهٔ پیشوند را می‌خواهد. حذف marker را خاموش و گره‌های بی‌استفاده را از پایین prune کن.

در پیاده‌سازی واقعی، قرارداد ورودی/خروجی را دقیق تعریف کن: رفتار ورودی تهی، مقدار تکراری، عنصر پیدا‌نشده و ظرفیت تمام‌شده باید روشن باشد.

## اجرای حل‌شده با ردگیری

درج `to`, `tea`, `ten`: مسیر t مشترک است؛ از آن o و e؛ زیر e دو شاخهٔ a و n. جست‌وجوی `te` به گره می‌رسد ولی isWord=false، درحالی‌که prefix معتبر است.

برای تمرین، جدولی با ستون‌های «گام»، «اندیس/اشاره‌گر»، «بخش فعال»، «تغییر state» و «دلیل» بساز. این روش به‌خصوص برای الگوریتم‌های درجا و تقسیم‌و‌غلبه جلوی پرش ذهنی را می‌گیرد.

## چرا درست است؟

هر مسیر از ریشه label یک prefix از دست‌کم یک کلید ذخیره‌شده است؛ برگ‌بودن به‌تنهایی پایان واژه را مشخص نمی‌کند. همهٔ کلیدهای زیر یک node با prefix همان مسیر شروع می‌شوند.

اثبات معمولاً سه بخش دارد: (۱) آغاز—ناوردا پیش از نخستین گام درست است؛ (۲) نگهداری—هر گام آن را حفظ می‌کند؛ (۳) پایان—شرط توقف همراه invariant جواب موردنیاز را نتیجه می‌دهد. اگر یکی از این سه بخش نامشخص است، هنوز درک الگوریتم کامل نشده است.

## تحلیل زمان و حافظه

درج/جست‌وجو O(L) زمان برای طول رشته L، مستقل از تعداد کلیدها در مدل ایده‌آل؛ حافظه متناسب با مجموع prefixهای یکتا و ضریب fan-out است. آرایهٔ فرزندان سریع ولی پرمصرف، map کم‌مصرف‌تر اما با overhead/هزینه جست‌وجو است.

در Big-O ورودی را تعریف کن (مثلاً n تعداد عناصر)، نوع حالت را نام ببر (بهترین/میانگین/بدترین)، و فضای کمکی را از حافظهٔ خود ورودی جدا کن. مرتبهٔ رشد زمان واقعی بر حسب ثانیه نیست؛ cache، تخصیص حافظه و ثابت‌های پیاده‌سازی هم اثر دارند.

## کاربرد واقعی و انتخاب مناسب

autocomplete، prefix search، dictionary، routing prefix و lexicographic enumeration. برای واژه‌نامهٔ بزرگ، radix/compressed trie مسیرهای تک‌فرزند را ادغام می‌کند.

پیش از انتخاب بپرس: چه عملیاتی پرتکرارند؟ آیا ترتیب مهم است؟ دادهٔ ورودی چه اندازه است؟ آیا محدودیت حافظه، latency بدترین‌حالت یا thread-safety داریم؟ ساختار خوب برای workload نامناسب می‌تواند انتخاب بدی باشد.

## خطاهای رایج و edge caseها

پایان واژه را از وجود child جدا نگه دار. normalization حروف/Unicode/case مهم است؛ «حرف» ممکن است چند code unit باشد. حذف باید شاخهٔ مشترک را که واژهٔ دیگری استفاده می‌کند نگه دارد.

حالت‌های مرزی را جداگانه بررسی کن: ورودی خالی، یک عضو، همهٔ اعضا برابر، هدف غایب، حداقل/حداکثر مقدار و اندازهٔ بزرگ. سرریز عدد صحیح در محاسبهٔ اندیس/ظرفیت نیز بسته به زبان مهم است.

## تمرین‌های مرحله‌ای

۱) trie واژه‌های `a, an, ant, all` را رسم کن. ۲) prefix `an` و واژهٔ دقیق `an` را جدا جست‌وجو کن. ۳) فضای trie آرایه‌ای را برای alphabet 26 و رشته‌های تک‌حرفی sparse برآورد کن.

برای هر تمرین، اول پاسخ ساده و درست بنویس، بعد پیچیدگی را حساب کن، سپس edge case اضافه کن. تمرین را با دست‌کم یک ورودی کوچک ردگیری کن و خروجی را با انتظار مستقل مقایسه کن.

## آزمون جامع با پاسخ تشریحی

ابتدا پاسخ‌ها را نخوان؛ جواب را با استدلال بنویس، سپس توضیح را مقایسه کن.

1. **پرسش:** هر یال چه نگه می‌دارد؟
   **پاسخ تشریحی:** نماد/کاراکتر بعدی رشته.
2. **پرسش:** چرا isWord لازم است؟
   **پاسخ تشریحی:** تا prefix را با واژهٔ کامل اشتباه نگیریم.
3. **پرسش:** زمان search؟
   **پاسخ تشریحی:** O(L) با L طول رشته.
4. **پرسش:** کاربرد؟
   **پاسخ تشریحی:** autocomplete و prefix lookup.
5. **پرسش:** محدودیت آرایهٔ فرزند؟
   **پاسخ تشریحی:** برای alphabet بزرگ و sparse حافظهٔ خالی زیادی می‌گیرد.

## راهنمای بازگویی از حافظه

بدون نگاه به متن، ایده، پیش‌شرط، invariant، یک ردگیری واقعی، پیچیدگی، edge case و یک کاربرد را در چند دقیقه روی کاغذ توضیح بده. اگر فقط pseudocode را حفظی می‌نویسی اما دلیل درستی یا محدودیت‌ها را نمی‌دانی، یک بار دیگر بخش‌های invariant و خطاها را مرور کن.
