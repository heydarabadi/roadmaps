# فصل ۵ — گراف‌ها و الگوریتم‌های آن

> نسخهٔ انگلیسی: [English version](readme.en.md)

شبکه‌ها را مدل کن، پیمایش کن و الگوریتم مسیر/اتصال را با وزن و جهت مناسب انتخاب کن.

## ترتیب پیشنهادی

1. پیش‌نیازها و تعریف‌ها را بخوان.
2. مثال هر تاپیک را دستی اجرا کن.
3. تمرین‌ها را انجام بده و بعد پاسخ آزمون را ببین.
4. هنگام پیاده‌سازی، complexity را با operation واقعی کتابخانهٔ زبانت تطبیق بده.

## راهنمای انتخاب الگوریتم گراف

| پرسش | انتخاب معمول |
|---|---|
| فقط reachability/component | DFS یا BFS |
| shortest path و همهٔ وزن‌ها برابر | BFS |
| وزن نامنفی، یک مبدأ | Dijkstra |
| وزن منفی و تشخیص چرخهٔ منفی reachable | Bellman–Ford |
| هدف مشخص و lower-bound heuristic | A* |
| اتصال همه با کمترین مجموع یال | Prim یا Kruskal برای MST |

## اجرای تصمیم‌گیری

مثلاً شبکهٔ مسیر شهری: رأس را تقاطع و یال را خیابان بگیر؛ جهت یک‌طرفه را ثبت؛ زمان سفر را وزن کن. اگر وزن زمان نامنفی است Dijkstra؛ اگر مبدأ و مقصد مشخص و heuristic فاصلهٔ مستقیم زمان واقعی را بیش‌برآورد نمی‌کند، A* می‌تواند هدف‌محور شود. اگر فقط تعداد حرکت مهم است و وزن همهٔ یال‌ها برابر است، BFS کافی است. اگر می‌خواهیم همهٔ شهرک‌ها را با کمترین هزینهٔ کابل وصل کنیم، مسئله MST است و Dijkstra جواب نمی‌دهد.

## آموزش گره‌های والد در نقشهٔ رسمی

این بخش عنوان‌های گروهی نقشه را نیز پوشش می‌دهد؛ برای درس مستقل هر برگ، README تاپیک را باز کن.

## تاپیک والد نقشه: Graph Data Structures

### آموزش

گراف مجموعهٔ رأس‌ها و یال‌هاست؛ جهت، وزن، تراکم و نمایش adjacency list/matrix انتخاب الگوریتم و حافظه را عوض می‌کند.

**روش انتخاب/اجرا:** مدل را با رأس/یال دقیق تعریف کن؛ جهت و وزن را تعیین کن؛ با توجه به V و E نمایش انتخاب کن؛ برای هر رأس/یال visited و metadata نگه دار.

**پیچیدگی و مبادله:** List برای گراف تنک O(V+E) فضا دارد؛ matrix O(V²) است و آزمون وجود یال را O(1) می‌کند.

**تجربهٔ عملی:** شبکه‌های ارتباطی، وابستگی سرویس‌ها، نقشه‌ها و گراف راه‌ها.

**دام رایج:** اگر graph cycle دارد، traversal باید visited داشته باشد؛ یال جهت‌دار و بی‌جهت را قاطی نکن.

### آزمون کوتاه با پاسخ

1. **پرسش:** چه زمانی adjacency list ترجیح دارد؟
   **پاسخ:** وقتی گراف تنک است و پیمایش همسایه‌ها مهم است.
2. **پرسش:** در adjacency matrix بررسی یال چه مرتبه‌ای دارد؟
   **پاسخ:** O(1)، با هزینهٔ O(V²) فضا.
3. **پرسش:** چه اطلاعاتی باید در تعریف گراف ثبت شود؟
   **پاسخ:** رأس‌ها، یال‌ها، جهت، وزن و قواعد همسایگی.

## تاپیک والد نقشه: Graph Search Algorithms

### آموزش

BFS و DFS دو پیمایش پایه‌اند. BFS با صف لایه‌به‌لایه پیش می‌رود؛ DFS با stack/recursion یک مسیر را عمیق دنبال می‌کند.

**روش انتخاب/اجرا:** visited را پیش از افزودن/فراخوانی ثبت کن؛ BFS را برای فاصلهٔ کمترین تعداد یال در گراف بی‌وزن و DFS را برای ساختار شاخه‌ای/چرخه/مؤلفه‌ها انتخاب کن.

**پیچیدگی و مبادله:** هر دو با adjacency list O(V+E) زمان می‌گیرند؛ حافظه تا O(V) است.

**تجربهٔ عملی:** کشف مؤلفه‌های شبکه، جست‌وجوی فایل، crawl و فاصلهٔ ارتباطی در گراف بدون وزن.

**دام رایج:** BFS برای یال وزن‌دار shortest path نیست؛ DFS recursion می‌تواند روی مسیر عمیق سرریز شود.

### آزمون کوتاه با پاسخ

1. **پرسش:** کدام پیمایش لایه‌به‌لایه است؟
   **پاسخ:** BFS.
2. **پرسش:** کدام ساختار کنترلی طبیعی BFS است؟
   **پاسخ:** صف FIFO.
3. **پرسش:** چرا visited لازم است؟
   **پاسخ:** جلوگیری از بازدید تکراری و حلقه در گراف چرخه‌دار.

## تاپیک والد نقشه: Shortest Path Algorithms

### آموزش

کوتاه‌ترین مسیر کمینه‌کردن مجموع وزن یال‌هاست. Dijkstra وزن نامنفی، Bellman-Ford وزن منفی و A* heuristic تا هدف را پوشش می‌دهند.

**روش انتخاب/اجرا:** وزن‌ها و نیاز به همهٔ مقصدها یا مقصد واحد را بررسی کن؛ algorithm را بر اساس منفی‌بودن وزن و heuristic انتخاب کن؛ relax و reconstruct path را ثبت کن.

**پیچیدگی و مبادله:** Dijkstra با heap O((V+E)log V)، Bellman-Ford O(VE)، A* تابع heuristic و فضای حالت است.

**تجربهٔ عملی:** RFC پروتکل OSPF از محاسبهٔ shortest-path-first بر پایهٔ Dijkstra برای ساخت مسیرهای link-state استفاده می‌کند؛ نقشهٔ grid می‌تواند A* را نمایش دهد.

**دام رایج:** Dijkstra وزن منفی را قبول نمی‌کند؛ heuristic بیش‌ازحد می‌تواند A* را غیربهینه کند؛ چرخهٔ منفی جواب محدود ندارد.

### آزمون کوتاه با پاسخ

1. **پرسش:** کدام الگوریتم وزن منفی را تشخیص می‌دهد؟
   **پاسخ:** Bellman-Ford.
2. **پرسش:** شرط اصلی Dijkstra چیست؟
   **پاسخ:** وزن همهٔ یال‌ها نامنفی باشد.
3. **پرسش:** چه چیزی A* را به مقصد هدایت می‌کند؟
   **پاسخ:** heuristic تخمینی h(n) در f(n)=g(n)+h(n).

## تاپیک والد نقشه: Minimum Spanning Tree

### آموزش

MST کم‌وزن‌ترین زیرگرافی است که همهٔ رأس‌های گراف بی‌جهت متصل را بدون چرخه وصل می‌کند. Prim و Kruskal دو روش ساخت آن‌اند.

**روش انتخاب/اجرا:** Prim از یک مؤلفه با کمترین یال مرزی رشد می‌کند؛ Kruskal همهٔ یال‌ها را مرتب و با DSU چرخه‌ها را رد می‌کند.

**پیچیدگی و مبادله:** هر دو معمولاً O(E log V) یا O(E log E) با heap/sort و DSU.

**تجربهٔ عملی:** انتخاب اتصالات کابل/فیبر با کمترین هزینهٔ مجموع، اگر مدل وزن یال نشان‌دهندهٔ هزینه باشد.

**دام رایج:** MST کوتاه‌ترین مسیر از یک مبدأ نیست؛ برای گراف ناپیوسته spanning forest بساز.

### آزمون کوتاه با پاسخ

1. **پرسش:** هدف MST چیست؟
   **پاسخ:** اتصال همهٔ رأس‌ها با کمترین وزن کل بدون چرخه.
2. **پرسش:** کدام الگوریتم به Union-Find طبیعی متکی است؟
   **پاسخ:** Kruskal.
3. **پرسش:** چند یال در MST گراف متصل با V رأس هست؟
   **پاسخ:** V−1.


## آزمون جمع‌بندی فصل

۱. adjacency list برای چه گرافی مناسب است؟ sparse و پیمایش‌محور. ۲. چرا visited هنگام enqueue ثبت می‌شود؟ جلوگیری از چندبار صف‌شدن. ۳. چه پیش‌شرطی Dijkstra دارد؟ وزن غیرمنفی. ۴. Bellman–Ford چه چیزی را اضافه می‌کند؟ وزن منفی و تشخیص چرخهٔ منفی reachable. ۵. heuristic بیش‌برآوردی چه خطر دارد؟ A* دیگر بهینگی کلاسیک را تضمین نمی‌کند. ۶. shortest path tree و MST چه objective متفاوت دارند؟ مسیر از مبدأ در برابر مجموع اتصال کل رأس‌ها.

## معیار عبور

برای یک مسئله، جهت، وزن، density، query و goal را دقیق تعریف کن؛ الگوریتم را با دلیل انتخاب کن؛ graph کوچک را با frontier/dist/parent یا DSU ردگیری کن؛ در انتها edge case disconnected, cycle, parallel edge, negative weight را بسنج.
