> فصل 01: مبانی و شناخت · درس 01

## هدف این درس
Elasticsearch را به‌عنوان نمایهٔ جست‌وجو کنار منبع حقیقت بشناس؛ مسیر سند از mapping تا shard، refresh، query و پاسخ را دنبال کن.
## تدریس کامل: Elasticsearch چه کاری می‌کند؟

فرض کن فروشگاهی چند میلیون کالا دارد. پایگاه داده‌ی اصلی کالاها را نگه می‌دارد؛ اما وقتی کاربر «کیبورد مکانیکی سبک» را جست‌وجو می‌کند، برنامه باید واژه‌های متن، غلط‌های تایپی، قیمت، موجودی و ارتباط عنوان را در نظر بگیرد. Elasticsearch داده را برای جست‌وجوی سریع آماده می‌کند، سندهای نامزد را پیدا می‌کند و بر اساس relevance مرتب می‌کند.

### مدل ذهنی

هر ورودی معمولاً یک document JSON در یک index است. index مجموعه‌ی منطقی اسناد با mapping و settings مشترک است. index به primary shardها تقسیم می‌شود؛ هر shard بخشی از داده است که روی node قرار می‌گیرد. چند node یک cluster می‌سازند. Search به shardهای لازم فرستاده می‌شود و نتیجه‌ها در coordinating node ادغام می‌شوند.

Elasticsearch بر Apache Lucene بنا شده است. هنگام index شدن، analyzer متن را به token تبدیل می‌کند و Lucene آن‌ها را در inverted index نگه می‌دارد. این ساختار واژه‌ها را به سندهای دارای آن واژه وصل می‌کند و جست‌وجوی متن را سریع می‌سازد. Mapping، analyzer و shard در فصل‌های بعد با جزئیات آموزش داده می‌شوند.

### مسیر یک سند

1. سرویس منبع کالا را با JSON می‌فرستد.
2. mapping می‌گوید title متن قابل جست‌وجو و price عدد است.
3. سند روی primary shard نوشته می‌شود و replicaها همگام می‌شوند.
4. refresh باعث می‌شود سند تازه در search دیده شود.
5. query کاربر تحلیل می‌شود، سندهای نامزد پیدا و score می‌گیرند.
6. پاسخ hitها، score و فیلدهای لازم را برمی‌گرداند.

### مرزهای کاربرد

Elasticsearch را معمولاً نمایه‌ی جست‌وجویی در کنار منبع حقیقت نگه می‌دارند. اگر کالا یا سفارش در پایگاه اصلی تغییر کند، تغییر باید به index هم برسد. Event, CDC, outbox یا job بازسازی می‌تواند این کار را انجام دهد. نوشتن هم‌زمان با دو درخواست مستقل خطرناک است: پایگاه اصلی ممکن است موفق شود و Elasticsearch شکست بخورد.

نتیجه‌ی search near real-time است؛ write تازه ممکن است تا refresh بعدی دیده نشود. برای هر سند refresh اجباری نکن، چون فشار نوشتن و هزینه‌ی ساخت segment را افزایش می‌دهد. برای موجودی یا مجوز حساس، تصمیم نهایی را از منبع حقیقت بخوان.

### تمرین قدم‌به‌قدم

1. یک index آزمایشی products-v1 بساز.
2. سه سند با ID پایدار وارد کن.
3. یکی را با Get مستقیم بخوان.
4. عنوان را با match query جست‌وجو کن.
5. پاسخ را با سند منبع مقایسه و هر تفاوت را به داده، mapping، analyzer یا query نسبت بده.

### آزمون تشریحی با پاسخ

1. **چرا متن را از پیش index می‌کنیم؟** Inverted index واژه‌ها را به سندها وصل می‌کند؛ query مجبور نیست همه‌ی سندها را از ابتدا بخواند.
2. **فرق index و node چیست؟** Index مجموعه‌ی منطقی سندهاست؛ node نمونه‌ی اجرایی cluster است که shard و درخواست را میزبانی می‌کند.
3. **چرا سند تازه فوراً پیدا نمی‌شود؟** جست‌وجو پس از refresh آن را می‌بیند؛ Elasticsearch near real-time است.


## خودآزمایی
1. Elasticsearch برای چه بارکاری مناسب است؟ پاسخ: retrieval متنی/ساخت‌یافته و تحلیل سریع؛ منبع اصلی تراکنش‌ها معمولاً جدا می‌ماند.
2. چرا جست‌وجو فوراً پس از write نتیجه نمی‌دهد؟ پاسخ: visibility پس از refresh و نزدیک‌به‌زمان‌واقعی است.
