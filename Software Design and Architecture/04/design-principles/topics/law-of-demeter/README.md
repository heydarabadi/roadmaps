## هدف یادگیری

پس از این درس بتوانی مفهوم را با زبان خودت تعریف کنی، در مثال دامنه‌ای تشخیصش بدهی و هزینهٔ انتخاب یا کنارگذاشتنش را توضیح بدهی.

## آموزش

یک واحد باید با همکاران نزدیک خود حرف بزند و از زنجیرهٔ ساختار داخلی اشیا بی‌خبر بماند؛ این کار تغییر ساختار را محلی می‌کند.

## مثال کاربردی

به‌جای `order.customer.address.city`، عملیات `shippingCity()` یا یک نمای کاربردی بده.

این مثال آموزشی است و ادعای پیاده‌سازی دقیق یک شرکت مشخص را ندارد. نمونهٔ صنعتی مستند و زمینهٔ آن در فصل «اصول طراحی» پیوند داده شده است.

## تصمیم معماری و محدودیت‌ها

- **چه زمانی به‌کار ببر:** وقتی مسئلهٔ اصلی‌ای که مفهوم حل می‌کند در سامانه واقعاً دیده می‌شود و قراردادش می‌تواند در کد یا آزمون بررسی شود.
- **چه زمانی ساده‌تر بماند:** پنهان‌کردن هر زنجیره ممکن است متدهای واسط زیاد ایجاد کند.
- **بازبینی:** هر dot access را تخلف حساب نکن؛ مسئله نشت ساختار و coupling است.

## کوییز با پاسخ تشریحی

پاسخ را بپوشان و ابتدا با کلمات خودت توضیح بده؛ پاسخ پیشنهادی معیار سنجش است، نه تنها عبارت درست.

1. **این مفهوم دقیقاً چه مسئله‌ای را حل می‌کند؟**
   - پاسخ پیشنهادی: یک واحد باید با همکاران نزدیک خود حرف بزند و از زنجیرهٔ ساختار داخلی اشیا بی‌خبر بماند؛ این کار تغییر ساختار را محلی می‌کند.
2. **در مثال زیر چه تصمیمی می‌گیری و چرا؟**
   - پاسخ پیشنهادی: به‌جای `order.customer.address.city`، عملیات `shippingCity()` یا یک نمای کاربردی بده.
3. **چه زمانی انتخاب آن نامناسب یا پرهزینه است؟**
   - پاسخ پیشنهادی: پنهان‌کردن هر زنجیره ممکن است متدهای واسط زیاد ایجاد کند.
4. **کدام خطای رایج را قبل از ادغام کد بررسی می‌کنی؟**
   - پاسخ پیشنهادی: هر dot access را تخلف حساب نکن؛ مسئله نشت ساختار و coupling است.

## آموزش تکمیلی مستقل

### ۴. Law of Demeter — قانون دیمتر

یک واحد باید با همکارهای نزدیک خود ارتباط بگیرد، نه زنجیرهٔ عمیق ساختار داخلی را بداند. عبارت customer.address.city اگر در چند جای دامنه تکرار شود، ساختار objectها به caller نشت کرده است. API دامنه‌ای مانند shipping_destination() می‌تواند معنا را نگه دارد.

قانون دیمتر «هر نقطهٔ دسترسی ممنوع» نیست. متدهای واسط زیاد هم می‌توانند boilerplate بسازند. مسئله این است که caller به جزییاتی وابسته شده که حق مالکیتش را ندارد.

## نمونهٔ کد مرحله‌ای

قانون دمتِر دسترسی‌های زنجیره‌ای به ساختار داخلی همکاران را کم می‌کند. به object نزدیک پیام بده تا خودش دانسته‌های لازم را به‌کار ببرد. با این حال، واسطه‌سازی برای هر مقدار ساده می‌تواند API را شلوغ کند.
**تمرین با پاسخ:** order.Customer.Address.Zip را به order.ShippingDestination() تبدیل کن؛ خود order مالک فهم محل ارسال باشد.

در این طرح C#، نوع‌های پشتیبان کوتاه شده‌اند تا انتخاب طراحی روشن بماند.

~~~csharp
public sealed class Order
{
    public Address ShippingAddress { get; private set; }
    public PostalCode ShippingDestination() => ShippingAddress.PostalCode;
}

var postalCode = order.ShippingDestination();
~~~
